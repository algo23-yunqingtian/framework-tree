# 交接文档 · framework-tree「主题筛选 → 导出 PPT」设计架构

> 生成：2026-09-01 · 用途：固化"选型导出 PPT"的设计思路，与后续执行细节隔离
> 范围：仅包含**设计层面的思路、取舍理由、架构方案**；不包含执行进度、commit/push 状态、坑位记录、脚本细节

---

## 一、需求一句话

用户在 GitHub 上已有 framework-tree 静态网站（多品种 × 6 大板块 × 30 节点的有色金属指标看板）。希望**上线后**能像选菜单一样：
1. 挑一个品种（如"铅"）
2. 挑某个板块（如"供给侧"）
3. 批量勾选要导出的内容
4. 一键生成一份"关于铅供给侧的综合汇报"，形态为 **PPT 或等价的离线文档**

---

## 二、两种管理方式的对比（核心取舍）

### 方式 A：按节点（页面）勾选

```
铅 → 供给 → 3.1.1 海外矿端 → 勾选 → 导出该页面的所有图
```

| 优点 | 缺点 |
|------|------|
| 符合人的思维（"我要看供给侧" → 勾供给板块） | 颗粒度粗：勾了就全部导出，没法挑单个图 |
| 页面是完整信息单元（主图+辅轴+解读） | 串用问题被掩盖（价格页放了进出口指标，勾选时看不出来） |

### 方式 B：按指标列表平铺勾选

```
铅 → 所有指标平铺 → 逐条勾选要导出的
```

| 优点 | 缺点 |
|------|------|
| 颗粒度细：每个指标独立可选 | 指标太多（全库 786 个），人无法直接浏览 |
| 串用问题一目了然 | 丢失页面上下文（单张图没有主辅轴配合） |

---

## 三、最终设计结论：**A + B 两层结合**

```
第一层（主）：按节点勾选 ← 符合人脑"按板块思考"
  ↓ 展开某节点
第二层（辅）：看到该节点下所有指标，可逐条勾选/取消
```

**具体交互设计**：

```
☑ 铅 · 3.1.1 海外矿端（节点层，主图+辅图打包导出）
  ☑ 澳洲铅精矿产量（月）       ← 主图
  ☑ 秘鲁铅精矿产量（月）       ← 辅图
  ☐ 全球矿端汇总（季）         ← 不想要，取消

☑ 铅 · 3.1.2 海外矿分国别明细
  ☑ 美国矿端产量（年）
  ☑ 澳洲矿端产量（月）
  ...
```

### 附加价值：串用问题可视化

第二层可显示每个指标的**实际板块 vs 应属板块**：

```
☑ 3.1.1 海外矿端
  ☑ 澳洲铅精矿产量（月）    ✅ 匹配
  ☑ MHP 进口价格（日）      ⚠️ 串用：实际=价格，应归=进出口
```

用户一眼看到放错位置的指标，**导出时可选择性排除**。这是"方式 B 单独做不可靠、但作为方式 A 的第二层刚好"的关键点。

## 四、技术路线：**纯前端 HTML 幻灯片，零服务器成本**

### 4.1 为什么不用真 PPT（python-pptx）

| 维度 | HTML 幻灯片 | 真 PPT（python-pptx） |
|------|------------|---------------------|
| 服务器成本 | **零**（纯前端，GitHub Pages 即可） | 需本地/服务端 Python 环境 + python-pptx 库 |
| 浏览器查看 | ✅ 翻页式（←→ 键盘 + 全屏 + 进度条） | ❌ 需 PowerPoint/WPS |
| 打印效果 | ✅ `@media print` 自动横版 A4，每页一图 | ✅ 原生 |
| 离线可用 | ✅ 单文件（截图 base64 内嵌） | ✅ 单文件 |
| 可编辑 | ❌ | ✅ 文本可编辑 |
| 跨平台 | ✅ 任意浏览器 | ⚠️ 需 PPT 软件 |

**结论**：对"汇报/分享/打印"场景，HTML 幻灯片在零成本下达到 90% 效果；仅当"需要二次编辑"时才需要真 PPT。当前阶段 HTML 幻灯片够用。

### 4.2 核心技术链（3 步）

```
预生成截图 → base64 内嵌 → CSS 打印模式
```

**① 预生成截图**
用 chromium headless 对每个页面截图（2560×1440，等高 PPT 视觉）。页面 JS 注入 `__chartsReady` 信号，截图工具等待该信号（比 sleep 可靠 10 倍）。

**② base64 内嵌**
把截图转为 base64 字符串直接写入 HTML，**单文件 100% 离线可用**，脱离 GitHub Pages 也能看。

**③ CSS 打印模式**
浏览器看：翻页式幻灯片（只显示当前页）
Ctrl+P 打印：`@media print` 自动切换为横版 A4、导航栏隐藏、每页一图。

### 4.3 文件架构（逻辑层，不含执行细节）

| 文件/目录 | 用途 |
|-----------|------|
| `export_selector.html` | 选单 UI：品种下拉 → 板块分组 → 节点勾选 → 生成报告 |
| `data/export_node_map.json` | 节点 ↔ 页面映射表（从 tree_config 自动生成） |
| `screenshots/*.png` | 预生成截图（每页一张） |
| `scripts/gen_screenshots.py` | 批量截图脚本（增量跳过已有） |
| `scripts/gen_export_node_map.py` | 从 tree_config.json 自动生成节点映射 |
| `scripts/chart_kits.py`（`__chartsReady` 信号） | 页面 ECharts 渲染完成信号，供截图工具等待 |

## 五、选单 UI 交互设计

1. **品种下拉**：从 `tree_config.json` 的 7 个品种（铅/铜/铝/锌/镍/锡/锂/硅）生成
2. **板块分组**：6 大板块（价格 2 / 供给 3 / 库存 4 / 需求 5 / 进出口 6 / 成本利润 7），按所选品种过滤
3. **节点勾选**：每个节点一个 checkbox + 预览按钮（iframe 弹窗看页面全貌）
4. **第二层指标展开**：点击节点后展开该节点所有指标，可逐条勾选/取消，标注串用状态
5. **操作栏**：全选 / 清空 / 按板块选择 / 生成 HTML 报告

## 六、已知约束与取舍理由

| 取舍 | 理由 |
|------|------|
| HTML 幻灯片而非真 PPT | 零服务器成本是硬约束（GitHub Pages 静态部署），可编辑性当前不重要 |
| 预生成截图而非实时渲染 | 258 页 × 实时加载 ECharts 太慢，预生成保证秒开 |
| 两层勾选而非单层 | 单层要么太粗（方式 A）要么太散（方式 B），结合是平衡点 |
| base64 内嵌而非外链截图 | 保证离线可用、分享方便；代价是单文件偏大（可用 `--image-quality=80` 压缩） |
| 串用标注放在第二层 | 主层保持清爽（按板块思考），细节下钻才暴露问题 |

## 七、数据口径与树配置

- 品种：7 大品种（铅/铜/铝/锌/镍/锡/锂/硅）+ 可选碳酸锂
- 板块：6 大板块，每品种 30 节点
- 指标：全库 786 个（v3.43），来源 SMM/Mysteel/LME/海关/NBS
- 映射：`tree_config.json` 为目录树唯一真源，`export_node_map.json` 由其自动生成
