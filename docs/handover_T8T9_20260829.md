### T8 季节图按原始数据粒度对齐（已推 `6d402bc`）

**用户诉求原话**：「2.3 里面的铅现货结算价，明明是有日度的数据，那为什么转成季节性就变成月度的了？可不可以把它季节性也和原本的持续的更新周期也对齐呀，比如说是日度的，那么季节性也改成日度的。」

**根因**：`__seasonalizeByYear` 按「年+月」分组（`by[yr][mm]=v`），日度数据每个交易日被压成月度，日频细节全丢。

**改动**（`scripts/chart_kits.py`）：
| 改动 | 说明 |
|---|---|
| 新增 `_detect_gran(data)` | 近 120 点平均日期间隔 <3 天 → `'D'` 日度，否则 `'M'` |
| `chart_line_t` 季节模式分支 | 日度 → 365 天类目（MM-DD）+ `__seasonalizeByDay`；月度 → 12 月类目 + `__seasonalizeByYear` |
| 新增 `__seasonalizeByDay` | 按年-日对齐，有效日 <30 条跳过该年 |
| `check_html.py` | 季节函数检查兼容 ByYear/ByDay 两分支 |
| `verify_render.js` | 长度检查兼容 12/365，非空阈值按月/日区分（3/30） |

**顺手修 2 个隐性 bug**：
1. **opts 构造时序**：`opts` 在构造时就调用季节函数，但 `__mdays` 定义在 JS_COMMON 里**后注入** → undefined 报错。改为 x 轴标签 IIFE 内联 + 函数内 `md[]` 自包含，不依赖注入顺序。
2. **非空判断**：`===null` 漏判 `undefined` → `Math.round(undefined)=NaN` 混入 365 个点。改 `==null`，现在 NaN=0。

**验证结果**：
- 日度页（2.2/2.3/2.6）：365 类目，每年有效 241-253 点，2026 年 167 点（至 8 月底），NaN=0
- 月度页（2.1/6.1/6.2/6.3）：保持 12 类目，不受影响
- 门禁：check_html 10/10 + verify_render 10/10 ALL PASS
- 线上 2.3 页实测：x 轴 `1-1`~`12-31`，5 条历年线（有效 251/249/253/253/167），canvas 1797×320，无 JS 错误

## 五、关键坑速查（15 条，详见 Playbook 第六章）

1. chart_kits JS 模板用 `%` 格式化，**不用 f-string**（f-string 内反斜杠 SyntaxError）
2. JS 里的 `%` 要写 `%%`
3. 标题/备注含 ASCII 双引号会炸 Python 字符串 → 统一中文引号「」
4. 观 kline 升序（bars[0]=旧）不要反转；zhiji series 返回 points **倒序**（最新在前）
5. check_html 版本检查已改正则 `indicators_v1\.json v\d+\.\d+`，别写死版本号
6. **STATUS.md 追加必须 python 拆行**：`raw.split("\n")` 处理后再 join。patch 的 `\n` 会变字面 `\n` 不换行
7. Pages `cache-control: max-age=600`，push 后 `sleep 75` 再 curl
8. 季节图粒度：日度 365 天类目(`__seasonalizeByDay`) / 月度 12 月(`__seasonalizeByYear`)，`_detect_gran` 自动判断
9. **opts 构造时序**：相关定义必须内联到图表 JS 内部，不能依赖 JS_COMMON 注入顺序
10. 非空判断 `==null` 不用 `===null`（`undefined` 漏判 → NaN）
11. SQLite DB 不推 GitHub（.gitignore 已配 `*.db`）
12. 反拷贝：chart_kits 的 ANTI 已内置禁用右键/Ctrl+C/S/P/F12/选中/拖拽
13. 知几中文分词：关键词间**必须空格分隔**，否则整词误命中
14. **Pages 验收别只看 200**：要查 `</html>` 结尾 + 字节数与本地一致（限流会返回截断响应，本次实测 848KB→147KB 截断）
15. 浏览器缓存：改静态文件加 `?v=20260829` 或强刷 Ctrl+Shift+R
