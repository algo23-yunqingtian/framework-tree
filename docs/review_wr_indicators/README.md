## 二、背景：这批数据是什么

另一台服务器产出的「周报指标框架树」归档，518 条指标（6 品种：铝/氧化铝/碳酸锂/锡/硅/镍与不锈钢）。

**它的原始匹配机制有 6 个缺陷**（导致大量错配）：

1. 金属名前缀丢失：`碳酸锂 产量:广西` → 匹配成 `统计局：原煤：产量：广西`
2. 多候选拼接：名称列拼了 2-5 个候选指标，ID 只存一个，**ID 与名称脱钩**
3. 子字符串模糊匹配：`铅蓄电池` 被当成 `电池` 命中
4. 地区/交易所不约束：`中国硫酸镍产量` → `印尼硫酸镍产量`
5. 图表 JSON 零数据支撑（83% 频率未知，1% 有参考值），**纯文本相似度**
6. 评分标签虚假：263 条"全匹配"里 3.5% 是硬错配

我用"多候选搜索 + 四维度约束打分"重跑了匹配（品种/子类别/地区/指标类型），把 518 条清洗到 **276 条**入库（`wr1`..`wr276`，v3.78）。

**但我的清洗引擎有两个能力缺口**，需要你补：

- **A. 无法拉真实数据验量级**：series 返回 HTTP 500。所以 `碳酸锂产量` vs `原煤产量` 这种量级差 1000 倍的错配，我只能靠名称语义判断
- **B. 品种别名表不全**：已经漏过 2 条（`A00升贴水-上海` 被修成锌锭、`锂精矿进口` 被修成锌精矿），我已手工修掉，但可能还有

**判断标准**（举例）：

| 碳酸锂 产量:广西 | 统计局：原煤：产量：广西（月） | 若数值在千万吨级 → ✗ **必须换** |

| 碳酸锂 仓单量 | GFEX: 仓单数量: 上海象屿速传库（日） | 若图表说"总量"但匹配到单一仓库 → ⚠️ 口径不符 |

### P1 — 品种/地区/口径方向复核（17 条带标记的）

```json
{
  "key": "wr96",
  "verdict": "ok",          // ok | fix | reject | merge
  "new_zhiji_id": null,     // verdict=fix 时填正确 ID
  "new_zhiji_name": null,   // verdict=fix 时填正确真名
  "series_check": "ok|bad|unavailable",  // 拉数验证结果
  "series_sample": "2026-08: 2.1万吨",   // 拉到的样本值（便于我核对）
  "reason": "数值量级符合碳酸锂产量，单位万吨级",
  "reviewed_by": "agent-2"
}
```

**verdict 取值**：

| verdict | 含义 | 我的动作 |
|---|---|---|
| `ok` | 匹配正确，可保留 | 不改 |
| `fix` | 匹配错误，需换 ID | 按你给的 new_zhiji_id 改 `ids` |
| `reject` | 无合适指标，应剔除 | 从 indicators_v1.json 删除该键 |
| `merge` | 与已有指标重复，应合并 | 告诉我合并到哪个键 |

提交并推送：

