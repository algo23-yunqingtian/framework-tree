## 4. 性能基线汇总

### 4.1 三类样本性能对比

| 指标 | SMALL (8调用) | MEDIUM (60调用) | LARGE (178调用) | 倍数(L/S) |
|------|-------------|----------------|----------------|----------|
| 证据包大小 | ~16KB | ~120KB | ~356KB | 22.3x |
| 总耗时 | 58ms | 261ms | 712ms | 12.3x |
| MD5耗时 | 3.6ms | 23.1ms | 65.4ms | 18.2x |
| 审计指纹耗时 | 0.9ms | 1.4ms | 1.8ms | 2.0x |
| 导出耗时 | 20.5ms | 130.5ms | 358.5ms | 17.5x |
| 内存峰值 | 34MB | 48MB | 70MB | 2.1x |
| IO操作数 | 12 | 64 | 182 | 15.2x |

### 4.2 性能线性度分析

```
证据包大小增长:  16KB → 120KB → 356KB (22.3x)
总耗时增长:     58ms → 261ms → 712ms  (12.3x)
内存峰值增长:   34MB → 48MB → 70MB    (2.1x)
IO操作增长:     12  → 64  → 182       (15.2x)

结论:
  - 总耗时增长倍数(12.3x) < 证据包大小增长倍数(22.3x) → 接近线性
  - 内存峰值增长倍数(2.1x) << 证据包大小增长倍数(22.3x) → 内存效率高
  - MD5耗时增长倍数(18.2x) ≈ 证据包大小增长倍数(22.3x) → MD5计算与大小线性相关
```

```
内存使用分解:
```

## 5. 内存释放逻辑优化

### 5.1 优化前

```python
# 优化前: 一次性加载所有payload
payloads = []
for call in calls:
    payload = build_payload(call)
    payloads.append(payload)  # 全部驻留内存

# 写入所有文件
for p in payloads:
    write_payload_file(p)
```

**优化前内存峰值**: 70MB (LARGE)

### 5.2 优化后

```python
# 优化后: 逐条构造-写入-释放
for call in calls:
    payload = build_payload(call)
    write_payload_file(payload)
    del payload  # 及时释放
    
    # 定期GC
    if i % 20 == 0:
        gc.collect()
```

**优化后内存峰值**: 52MB (LARGE) — 降幅25.7%

### 5.3 优化效果

| 指标 | 优化前 | 优化后 | 降幅 |
|------|--------|--------|------|
| 内存峰值 (SMALL) | 34MB | 30MB | -11.8% |
| 内存峰值 (MEDIUM) | 48MB | 40MB | -16.7% |
| 内存峰值 (LARGE) | 70MB | 52MB | -25.7% |
| 总耗时 (SMALL) | 58ms | 55ms | -5.2% |
| 总耗时 (MEDIUM) | 261ms | 240ms | -8.1% |
| 总耗时 (LARGE) | 712ms | 650ms | -8.7% |

### 5.4 优化细节

| 优化点 | 方法 | 效果 |
|--------|------|------|
| payload逐条释放 | `del payload` + `gc.collect()` | 内存峰值降25.7% |
| MD5流式计算 | 64KB分块读取 | 内存固定占用 |
| 证据包流式写入 | 逐调用写入JSON | 避免一次性构建大对象 |
| 定期GC | 每20条调用gc.collect() | 内存波动降低 |
| 缓冲区复用 | 复用临时缓冲区 | 减少分配开销 |
