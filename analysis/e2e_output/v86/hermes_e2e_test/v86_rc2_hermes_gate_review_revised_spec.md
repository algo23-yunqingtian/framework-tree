## 1. 修订动机

原 Gate G01~G08（Stage3 定义）无法拦截 V86 的核心失败模式：
**元数据全部达标（桥接表 197/197、覆盖率 100%）但底层真实取数 0% 可用** ——
Stage3 预审时 G-06 仅看"桥接表存在"即判名义改善，未要求真实取数证据。

DSHB 造假链正是钻了"只看元数据、不审计脚本、不实测取数"的空子：
- 脚本 search 绕道 → 日志 60/60 PASS → 桥接表 100% → 全链路"达标"却全链路虚假。

**修订原则**：Gate 必须同时校验「元数据层」与「执行层」。仅元数据完成、真实取数不可用 → **直接不通过**（不进入加权评估）。

## 2. 修订后 Gate 准入条件（G01~G10）

### 2.1 基础条件（沿用，微调）

| Gate | 条件 | 判定证据（新增要求） |
|------|------|---------------------|
| G-01 | PREP 三方审批 + 基线零违规 | 审批记录 + git 基线核验 |
| G-02 | C1-C5 Gate A+ 50/50 | C1-C5 全通过记录 |

### 2.2 风险条件（口径修订）

| Gate | 条件 | 修订内容 |
|------|------|---------|
| G-03 | P0 清零 | **内部** P0 缺陷清零；DEPENDENCY_BLOCK 单独呈现（见 T3.3），不计入内部 P0 计数但须有登记与替代路径 |
| G-04 | P1 有处置计划 | P1 缺陷逐项有修复计划 + 责任人 + 预计时间 |

### 2.3 执行层强制检查（本轮核心新增）

| Gate | 条件 | 判定标准（强制） |
|------|------|-----------------|
| **G-09（新增）** | **测试脚本源码审计 PASS** | ① 脚本入参为被测目标ID 直连（禁止 search 中转/自动替换 ID）；② 日志含 `requested_id==resolved_id` 断言；③ 数据有效性校验（value≠0）；④ 原始 payload 留存。任一不满足 → **FAIL（不通过）** |
| **G-10（新增）** | **指标真实取数抽样核验 PASS** | HERMES 独立客户端实测：对照组健康 + 全部 COMPLETED 条目取数通过 + 抽样 PENDING ≥5 条复测。COMPLETED 条目任一取数失败 → **FAIL（不通过）** |

### 2.4 量化条件（口径修订为真实可取数）

| Gate | 条件 | 修订内容 |
|------|------|---------|
| G-05 | 影子覆盖率 ≥80% | 覆盖率统计仅计**真实可取数**映射支撑的用例；DEPENDENCY_BLOCK 不计入 |
| G-06 | **真实可取数桥接率 ≥80%** | 原"zhiji_id 映射率"修订为「有效桥接率 = COMPLETED/总条目」（审计口径规范 §2.2）；仅元数据完成不计入 |
| G-07 | 关键路径 100% | 关键路径进度以**真实可取数**里程碑计（不是文档提交数） |
| G-08 | Mock→Real 24/24 | 切换必须基于**短ID 直连真实取数**成功；禁止 search 绕道替代 |

### 2.5 汇总判定

```
Gate 准入判定规则（修订后）:
  必备项（任一 FAIL 即不通过，不可加权）:
    G-01, G-02, G-09, G-10
  量化项（须 7/10 通过，且必备项全 PASS）:
    G-03, G-04, G-05, G-06, G-07, G-08
  ⚠️ 仅元数据完成、真实取数不可用 → G-09/G-10/G-06 直接 FAIL → Gate 直接判定不通过
```

> **与旧版差异**：旧版 2/8 即不通过（8 项全加权）；新版设 4 项**强制必备**（G-01/02/09/10），
> 任何"元数据好看但底层不可用"的交付在 G-09/G-10 即被拦截，无需等到量化评估。

## 4. 影子测试放行条件（联动修订）

影子测试放行需**全部**满足：
1. G-09 脚本源码审计 PASS（防造假前置）；
2. G-10 真实取数抽样 PASS（底层可用前置）；
3. R-S01 跨团队基线 ≥6/8；
4. 有效桥接率 ≥80%（G-06 口径）；
5. 覆盖率 ≥80%（G-05 口径，仅计真实可取数）。

> 5 项中任何一项不满足 → 影子测试保持 PAUSED，不因元数据达标而放行。
