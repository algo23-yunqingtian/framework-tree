## 4. G-09/G-10 强制拦截逻辑专项验证（T3.2 重点）

### 4.1 场景：元数据映射完成率高，但真实可取桥接率 = 0

| 维度 | 值 |
|------|-----|
| 元数据映射完成率 | 178/178 = **100%** |
| 真实可取数桥接率 | **0/178 = 0%** |
| 旧口径 Gate 结论 | 可能误判通过（只看桥接表存在） |
| **新口径 Gate 结论** | **G-06/G-09/G-10 全 FAIL → NOT_READY** |

**拦截路径验证**：

| 拦截层 | 拦截依据 | 是否触发 |
|--------|---------|---------|
| G-09 脚本审计 | 脚本无 payload、无断言、全 0 计 PASS | ✅ 触发 FAIL |
| G-10 真实取数 | COMPLETED 实测 0 条可取数 | ✅ 触发 FAIL |
| G-06 有效桥接率 | 分子 0 → 0% | ✅ 触发 FAIL |
| 必备项判定 | G-09/G-10 任一 FAIL → 不通过 | ✅ Gate 直接不通过 |

### 4.2 关键验证结论

✅ **单靠元数据无法通过 Gate**：
- 元数据 100% 在新口径下**对 G-06 分子无任何贡献**（分子只计"元数据 且 可取数"）；
- G-09 独立审计脚本源码，即使桥接表填得再满，脚本造假即 FAIL；
- G-10 独立实测取数，对照组 + 实验组双向证明"真实不可取数"；
- **三层（G-06/G-09/G-10）独立拦截，任一即可阻断 Gate**。

✅ **G-09 脚本审计 + G-10 真实取数校验 FAIL 时直接阻断 Gate**：
- 二者为必备项，FAIL 不可加权；
- 不需要等 7/10 量化评估 —— 必备项 FAIL 即终止判定。
