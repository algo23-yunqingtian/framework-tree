## 1. 设计动机（V86 空转 5 阶段的教训）

V86-RC2 经历了 Stage1→Stage2→Stage2复核→Stage3→二次审计共 **5 个阶段空转**，根因：
- 交付方自测在**最后一环**（Gate 终审）才被 HERMES 独立复现推翻 → 前期所有"通过"无效；
- DSHB 60/60 PASS 与 HERMES 实测 0/7 的矛盾直到二次审计才暴露，浪费 5 轮工期；
- 缺少**前置、逐级阻断**机制，错误结论一路流转到 Gate。

**设计原则：错误越早拦截，成本越低。上一级不通过，禁止流转下一级。**

## 2. 流水线总览

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌────────────┐
│ L1 DSHB自测   │ →  │ L2 DSHE联合抽样│ → │ L3 HERMES抽样 │ → │ Gate终审    │
│ (交付方)      │    │ (消费方)     │    │ (预审,轻量)   │    │ (正式准入)  │
└──────────────┘    └──────────────┘    └──────────────┘    └────────────┘
  产出: 自测报告     产出: 联合校验记录   产出: 预审意见       产出: 准入判定
  +原始payload       +抽样复核记录       +通过/退回
  阻断规则:          阻断规则:           阻断规则:
  自测FAIL→不流转    L1未过→不接单       L2未过→不审计      L3不过→不准入
```

### 2.1 各级定位

| 级别 | 责任方 | 角色 | 成本 | 触发时机 |
|------|--------|------|------|---------|
| L1 | DSHB（交付方） | 自测证明"我确实修好了" | 交付方内部 | 每次交付提交前 |
| L2 | DSHE（消费方） | 联合抽样证明"数据能被消费方用上" | 中 | L1 通过后 |
| L3 | HERMES（审计方） | 抽样预审证明"结论独立可复现" | 轻量（Gate 前） | L2 通过后 |

> **关键**：L3 是**Gate 前**的轻量预审，不是 Gate 终审的替代。L3 拦截的是"元数据达标但底层不可用"（V86 的核心失败模式）。

---

## 3. L1 — DSHB 自测（交付方）

### 3.1 交付物要求（缺一不可）

1. **测试脚本源码**（提交远端，供 L3 源码审计）；
2. **原始 API payload 日志**：每次调用的 请求URL + 响应体（可截断），禁止只交统计数字；
3. **自测报告**：按 `v86_rc2_hermes_audit_canonical_spec.md` §2.1 五级状态标记每条结果；
4. **入参-出参一致性声明**：`requested_id == resolved_id` 断言结果。

### 3.2 阻断规则（L1 FAIL → 不流转 L2）

| 情形 | 判定 |
|------|------|
| 脚本含 search 中转 / 自动替换 ID | ❌ 阻断（造假模式，整批作废） |
| 无原始 payload | ❌ 阻断（不可复核） |
| requested_id ≠ resolved_id 未处理 | ❌ 阻断 |
| 数据有效性未校验（全 0 计 PASS） | ❌ 阻断 |
| 短ID 直连取数 < 抽样要求通过率 | ❌ 阻断 |

> L1 阻断时，DSHB 必须**重写脚本 + 重新测试**，禁止修复后沿用旧日志（旧日志已污染，不可采信）。

---

## 4. L2 — DSHE 联合抽样（消费方）

### 4.1 职责

DSHE 作为**数据消费方**，验证"交付的映射在展示层/告警层/日志层真实可用"：
1. 从 DSHB 交付中**独立抽样**（≥10%，含全部 COMPLETED 条目）；
2. 对每个抽样条目，**用自己的调用链**（不调 DSHB 脚本）验证取数与展示；
3. 出具联合校验记录：抽样清单、通过率、异常明细。

### 4.2 阻断规则（L2 FAIL → 不流转 L3）

| 情形 | 判定 |
|------|------|
| L1 未通过（无自测报告） | ❌ 拒绝接单 |
| 抽样通过率 < 100%（COMPLETED 条目） | ❌ 阻断，退回 L1 |
| 转述 DSHB 自报数字、无独立调用 | ❌ 阻断（背书式引用 = 零价值，V86 教训 R-AUDIT-05） |
| 未按 COMPLETED/PENDING 分级理解映射 | ❌ 阻断（170 条 PENDING 被当已映射 = 运行时错误） |

> **硬性**：DSHE 的"PASS"必须来自**自己的 API 调用结果**，任何"DSHB 说 60/60 所以我也 PASS"的记录视为无效。

---

## 5. L3 — HERMES 抽样预审（审计方，Gate 前轻量审计）

### 5.1 职责

1. **脚本源码审计**（强制，见审计口径规范 §3.2）：逐行检查入参真实性；
2. **独立抽样实测**：独立客户端复现 ≥5 个关键条目 + 全部 COMPLETED 条目，对照组验证环境；
3. **交叉验证**：核对 DSHB 自测、DSHE 联合校验、HERMES 实测三方结论一致性；
4. 输出**预审意见**：通过（放行至 Gate）/ 退回（附证据）。

### 5.2 阻断规则（L3 FAIL → Gate 直接不通过）

| 情形 | 判定 |
|------|------|
| 脚本源码存在造假模式 | ❌ 退回 L1，触发 P0（R-AUDIT-01 模式） |
| 实测与自测结论矛盾（如自测 100% vs 实测 0%） | ❌ 退回，标记结果不可采信 |
| COMPLETED 条目实测取数失败 | ❌ 退回（COMPLETED 必须双证据） |
| L2 背书式引用（无独立调用） | ❌ 退回 L2 重做 |

### 5.3 预审时效与成本控制

- L3 目标耗时 ≤ Gate 终审的 1/3（轻量定位）；
- 抽样规模：全部 COMPLETED + 随机 ≥5 条 PENDING；
- 预审结论实时写入 JOB_READY.flag（L3_PRE_AUDIT=PASS/FAIL）。

---

## 6. 流水线流转规则（强制）

1. **单向流转**：L1 → L2 → L3 → Gate，逐级阻断，禁止跳级；
2. **退回重跑**：任一级 FAIL，退回上一级重做，且**旧日志/旧结论作废**（不允许"补个报告"续用旧数据）；
3. **状态标记**：每一级结论写入对应文档 + JOB_READY.flag，状态机：
   `L1_PENDING → L1_PASS → L2_PENDING → L2_PASS → L3_PENDING → L3_PASS → GATE_REVIEW`
4. **时间约束**：任一级停留超过 3 个工作日自动升级告警（HERMES 介入仲裁）；
5. **DEPENDENCY_BLOCK 处理**：若某条目的取数受外部平台阻塞（数据平台短ID 解析未就绪），按 T3.3 规范登记，该条目从 L1/L2/L3 的"必须通过"清单中暂挂，但**整体 Gate 放行仍需满足 Gate 条件**（含覆盖率要求，DEPENDENCY_BLOCK 不计入覆盖率）。

## 8. 结论

- ✅ 三级流水线设计完成：L1 自测（原始 payload）→ L2 联合抽样（独立调用）→ L3 预审（源码审计+独立实测）；
- ✅ 每级准入/阻断规则明确，上一级不通过禁止流转；
- ✅ 拦截目标：避免"元数据达标但底层不可用"再次流入 Gate（V86 五阶段空转的根治方案）；
- ⏳ 落地依赖：短ID 服务器解析（B-1）就绪后，流水线即按此规范运转。
