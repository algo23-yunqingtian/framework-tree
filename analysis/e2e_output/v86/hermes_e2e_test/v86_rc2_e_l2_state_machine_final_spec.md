## 2. 状态机架构总览

### 2.1 四状态定义

| 状态 | 代号 | 含义 | 触发条件 | 恢复条件 | 颜色标识 |
|------|------|------|----------|----------|----------|
| BLOCKED | B | 故障已触发, 熔断生效 | 告警触发+阈值超限 | 自动恢复或手动恢复 | 🔴 红色 |
| ACTIVE | A | 故障活跃, 系统降级运行 | BLOCKED后自动转换 | 指标恢复正常 | 🟠 橙色 |
| RECOVERY | R | 故障恢复中, 指标收敛 | ACTIVE后指标开始恢复 | 指标连续3min正常 | 🟡 黄色 |
| COMPLETE | C | 故障已完全恢复 | RECOVERY后确认稳定 | 自动转入正常态 | 🟢 绿色 |

### 2.2 状态流转图

```
                    ┌─────────────────────────────────┐
                    │         正常态 (Normal)          │
                    │         (绿色, 无告警)           │
                    └──────────────┬──────────────────┘
                                   │ 告警触发+阈值超限
                                   ▼
                    ┌─────────────────────────────────┐
                    │       BLOCKED (红色)             │
                    │  熔断生效, 系统降级               │
                    └──────────────┬──────────────────┘
                                   │ 熔断确认+故障活跃
                                   ▼
                    ┌─────────────────────────────────┐
                    │       ACTIVE (橙色)              │
                    │  故障活跃, 系统降级运行           │
                    └──────────────┬──────────────────┘
                                   │ 指标开始恢复
                                   ▼
                    ┌─────────────────────────────────┐
                    │     RECOVERY (黄色)              │
                    │  恢复中, 指标收敛                 │
                    └──────────────┬──────────────────┘
                                   │ 指标连续3min正常
                                   ▼
                    ┌─────────────────────────────────┐
                    │     COMPLETE (绿色)              │
                    │  完全恢复, 正常态                 │
                    └──────────────┬──────────────────┘
                                   │ 稳定确认
                                   ▼
                    ┌─────────────────────────────────┐
                    │         正常态 (Normal)          │
                    │         (绿色, 无告警)           │
                    └─────────────────────────────────┘

    异常路径:
    BLOCKED → RECOVERY (直接跳过ACTIVE, 适用于瞬时故障)
    ACTIVE → BLOCKED (回退, 适用于恢复失败)
    RECOVERY → ACTIVE (回退, 适用于恢复不稳定)
```

### 2.3 状态机状态码

| 状态 | 状态码 | 描述 | 持续时间 | 通知策略 |
|------|--------|------|----------|----------|
| BLOCKED | STATE_BLOCKED | 熔断生效 | 按故障类型定义 | 立即通知+升级 |
| ACTIVE | STATE_ACTIVE | 故障活跃 | 持续监控 | 5min聚合通知 |
| RECOVERY | STATE_RECOVERY | 恢复中 | 3min观察期 | 10min聚合通知 |
| COMPLETE | STATE_COMPLETE | 完全恢复 | 自动转入正常态 | 恢复通知 |

## 5. 多故障叠加展示逻辑

### 5.1 优先级堆叠算法

```
输入: 并发故障列表 [F1, F2, F3, F4, F5]
输出: 排序后的展示列表 (高优先级在前)

排序规则:
1. P0级别优先于P1级别
2. P0级别之间按故障触发时间排序
3. P1级别按故障触发时间排序
4. 复合故障(多故障并发)显示为复合状态

伪代码:
function sortFaults(faults):
    p0_faults = [f for f in faults if f.level == P0]
    p1_faults = [f for f in faults if f.level == P1]
    p0_faults.sort(key=lambda f: f.trigger_time)
    p1_faults.sort(key=lambda f: f.trigger_time)
    return p0_faults + p1_faults
```

### 5.2 状态非覆盖机制

| 机制 | 描述 | 实现方式 |
|------|------|----------|
| 状态互不覆盖 | 多故障状态独立存储, 互不覆盖 | 独立状态表 per fault |
| 优先级显示 | 高优先级故障显示在上层 | z-index + 优先级排序 |
| 降级显示 | 低优先级故障降级显示(灰色/半透明) | opacity 0.6 + 小字体 |
| 复合状态 | 多故障并发时显示复合状态 | 合成状态 + 子状态展开 |

### 5.3 层级展示规则

| 层级 | 内容 | 显示方式 |
|------|------|----------|
| L1 | 复合状态 (CF01/CF02/CF03) | 大字体 + 醒目颜色 |
| L2 | P0子故障 (F1/F2) | 中字体 + 正常颜色 |
| L3 | P1子故障 (F3/F4/F5) | 小字体 + 灰色 |
