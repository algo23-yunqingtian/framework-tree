### 2.2 WAL v2 SQLite 写入架构

WAL (Write-Ahead Log) v2 采用 SQLite 作为落盘底座，通过以下机制达成 ~0.7ms/event 的写入延迟：

```
AuditConsumer ──> InMemoryBuffer(1MB) ──> BatchFlusher(64 events) ──> SQLite WAL
                └──────> AsyncSigner (HMAC-SHA256)   └──────> Checkpoint @64MB
```

- **缓冲层**: 1MB 环形缓冲，避免高频小写入。
- **批处理**: 每 64 事件或 50ms 触发 flush，两者取先到。
- **并行签名**: 异步 HMAC-SHA256 签名，不阻塞主写入路径。
- **CheckPoint**: 64MB 阈值触发 checkpoint，防止 WAL 文件膨胀。
- **持久化顺序**: WAL 落盘 → 主表写入 → 返回确认，符合 ACID。

### 2.3 SHA256 链架构

采用**创世哈希 + 逐条链接**的可篡改敏感链结构：

```
GENESIS_HASH = SHA256("DSHE_L2_CHAIN_GENESIS_V86_RC2_E")
             = e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855

For i in 1..N:
    canonical_i = canonical_json(event_i)   # 排序、去 BOM、UTF-8
    curr_hash_i = SHA256(prev_hash || canonical_i)
    prev_hash_{i+1} = curr_hash_i
```

**哈希算法**: SHA-256 (FIPS 180-4)
**规范化**: RFC 8785 JCS (JSON Canonicalization Scheme)
**创世哈希**: 每个 `chain_id` 独立，避免跨链碰撞。

## 5. 事件丢失率优化

| 批大小 | 16 | 64 | 4x 吞吐 |
