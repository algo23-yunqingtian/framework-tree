## 2. 外部依赖阻塞说明

### 2.1 什么是外部依赖阻塞？

**外部依赖阻塞**是指底层数据源（zhiji数据平台API）当前不可用，导致指标虽然元数据已注册、UI渲染正常，但无法从底层获取实际数据的情况。

```
┌─────────────────────────────────────────────────────┐
│              外部依赖阻塞 vs 系统Bug                    │
├─────────────────────────────────────────────────────┤
│                                                        │
│  🟡 外部依赖阻塞 (当前场景)                              │
│  ├── 面板显示: ✅ 正常渲染 (标题/标签/布局正常)          │
│  ├── 状态标记: 🟡 DEPENDENCY_BLOCKED                    │
│  ├── 数据状态: ❌ 无法获取底层数据                       │
│  ├── 原因: zhiji API外部平台不可用                      │
│  ├── 影响: 所有178项指标均受影响                        │
│  └── 修复: 需zhiji数据平台恢复API服务                   │
│                                                        │
│  🔴 系统Bug (非当前场景)                                │
│  ├── 面板显示: ❌ 异常 (白屏/报错/截断/空白)             │
│  ├── 状态标记: 无标记或错误标记                         │
│  ├── 数据状态: 未知 (无法判断)                          │
│  ├── 原因: DSHE展示层代码缺陷                           │
│  ├── 影响: 特定面板/指标受影响                          │
│  └── 修复: DSHE展示层修复                              │
│                                                        │
└─────────────────────────────────────────────────────┘
```

### 2.2 当前阻塞状态

| 属性 | 值 |
|------|-----|
| 阻塞原因 | zhiji数据平台API服务不可用 |
| 影响范围 | 全部178项指标 (100%) |
| 阻塞状态 | data_fetchable=FALSE |
| 面板状态 | 🟡 DEPENDENCY_BLOCKED |
| 降级级别 | L3 (面板隔离) |
| 持续时间 | >1小时 (持续中) |
| 修复责任方 | zhiji数据平台 |
| DSHE可修复性 | ❌ 无法修复 (外部依赖) |

### 2.3 区分方法: 系统Bug vs 外部阻塞

| 检查项 | 系统Bug | 外部阻塞 | 当前状态 |
|--------|--------|---------|---------|
| 面板是否正常渲染 | ❌ 异常 | ✅ 正常 | ✅ 正常 |
| 状态标记 | 无或错误 | 🟡 DEPENDENCY_BLOCKED | ✅ 🟡 |
| data_fetchable字段 | 正常(可TRUE) | FALSE | ✅ FALSE |
| 告警是否标记受限 | 无标记 | ✅ 标记受限 | ✅ 受限 |
| 影响范围 | 部分面板/指标 | 全部指标 | ✅ 全部 |
| 是否DSHE可修复 | ✅ 可修复 | ❌ 不可修复 | ❌ |
| 跨视图状态 | 不一致 | 一致 | ✅ 一致 |

**快速判断**: 如果面板正常显示🟡标记 + data_fetchable=FALSE + 全部指标受影响 → **外部依赖阻塞**（非系统Bug）

### 2.4 面板标记含义速查

| 标记 | 含义 | 用户操作 |
|------|------|---------|
| 🟢 FULLY_AVAILABLE | 全链路可用，数据可正常获取 | 正常使用 |
| 🟡 DEPENDENCY_BLOCKED | 上游数据源阻塞，面板可显示但底层无数据 | 等待上游恢复 |
| ⚠️ WARNING | 数据质量告警，数据可用但有质量问题 | 查看告警详情 |
| 🔴 ERROR | 系统错误，需运维介入 | 联系运维 |
| ⏳ PENDING | 数据待更新，等待刷新 | 等待刷新 |

### 6.2 常见问题FAQ

#### Q1: 面板上显示🟡标记是什么？

**A**: 🟡 DEPENDENCY_BLOCKED表示该指标的上游数据源当前不可用，底层无法获取数据。面板本身UI渲染正常，但底层数据因外部依赖阻塞而不可用。这不是系统Bug，无需DSHE修复，需等待上游数据平台恢复服务。

#### Q2: 为什么所有指标都显示阻塞？

**A**: 当前zhiji数据平台API服务全面不可用，导致所有178项指标均无法从底层获取数据。这是外部平台级别的阻塞，非DSHE展示层问题。待zhiji API恢复后，所有指标将自动恢复为🟢 FULLY_AVAILABLE状态。

#### Q3: 如何确认是系统Bug还是外部阻塞？

**A**: 三步判断法：
1. **看标记**: 🟡 DEPENDENCY_BLOCKED = 外部阻塞，无标记或错误标记 = 可能是系统Bug
2. **看范围**: 全部指标阻塞 = 外部阻塞，部分指标异常 = 可能是系统Bug
3. **看渲染**: 面板正常渲染 = 外部阻塞，面板异常(白屏/报错) = 系统Bug

#### Q4: 降级后数据会丢失吗？

**A**: 不会。降级策略按以下优先级展示数据：
- L1: 展示最近缓存数据（数据在缓存有效期内）
- L2: 展示最近静态快照（数据为最后一次成功获取的数据）
- L3: 面板隔离，不展示数据（避免展示过期数据）

#### Q5: 上游恢复后需要做什么？

**A**: 上游恢复后执行以下操作：
1. 自动：DSHE检测到data_fetchable=TRUE，自动解除降级
2. 手动确认：验证面板状态恢复为🟢
3. 重新校验：执行一次联合抽样校验确认全链路可用
4. 解除Gate阻断：更新Gate评审状态

#### Q6: 降级期间告警还会触发吗？

**A**: 降级期间告警处理如下：
- L1/L2降级：阻塞指标的告警被抑制，非阻塞告警正常触发
- L3降级：全部告警静默，仅保留运维通知
- 恢复后：告警自动恢复，抑制/静默状态解除

#### Q7: 业务方如何确认指标是否可用？

**A**: 查看面板状态标记：
- 🟢 FULLY_AVAILABLE = 指标完全可用，数据实时
- 🟡 DEPENDENCY_BLOCKED = 指标UI正常但底层数据不可用
- 点击面板标题查看详情，包含data_fetchable状态和阻塞原因
