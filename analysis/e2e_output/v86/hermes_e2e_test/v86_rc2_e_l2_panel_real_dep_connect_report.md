### 2.4 数据路由层详细设计

数据路由层是连接数据源层和面板层的关键中间件，负责根据当前配置和数据源健康状态决定数据流向：

| 路由策略 | 触发条件 | 数据流向 | 优先级 |
|---------|---------|---------|--------|
| **策略1: Real优先** | `source_mode=real` 且 DEP-001 可用 | Real DEP-001 → 面板层 | 1（最高） |
| **策略2: Mock优先** | `source_mode=mock` 或 DEP-001 不可用 | Mock 沙箱 → 面板层 | 2 |
| **策略3: 自动降级** | Real 失败超过宽限期 | Real → Mock（自动切换） | 3 |
| **策略4: 桥接表兜底** | Real 和 Mock 均不可用 | zhiji API 短ID → DSHB桥接表 | 4 |

```python
# 数据路由伪代码
def route_data_source(request: PanelRequest) -> DataSource:
    if config.source_mode == "real" and dep001_health.check():
        try:
            data = dep001.fetch(request.metric_ids)
            validate_data_integrity(data)
            return data
        except TimeoutError as e:
            if grace_period.exceeded():
                return fallback_to_mock(request)
            else:
                return retry_with_backoff(dep001, request)
    elif config.source_mode == "mock":
        return mock_datasource.fetch(request.metric_ids)
    else:
        return mock_datasource.fetch(request.metric_ids)  # 兜底
```

## 10. 异常处理与降级策略

### 10.1 三级降级策略

当 DEP-001 数据源出现慢响应或不可用时，系统执行三级降级策略：

| 降级级别 | 触发条件 | 降级动作 | 面板显示 | 恢复条件 |
|---------|---------|---------|---------|---------|
| L1 (轻微) | 延迟>500ms 持续30s | 延长超时 + 重试 | 正常显示+延迟标记 | 延迟恢复<300ms |
| L2 (中度) | 延迟>2s 或 失败率>5% | 自动切换到 Mock 兜底 | Mock 数据+🟡标记 | Real 恢复后自动切回 |
| L3 (严重) | Real 完全不可用>5min | 切换到 Mock + 告警 | Mock 数据+🔴标记 | Real 恢复+人工确认 |

### 10.2 宽限期机制

| 参数 | 值 | 说明 |
|------|-----|------|
| 首次响应超时 | 3s | DEP-001 单次调用超时 |
| 重试次数 | 5 | 指数退避重试（100ms→200ms→400ms→800ms→1600ms） |
| 宽限期 | 30s | 超时后等待恢复的宽限期 |
| 降级触发 | >30s 未恢复 | 触发自动降级到 Mock |
| 最大暂停时长 | 30天 | Mock 兜底最大保留时间 |
| 升级机制 | 30天未恢复 | 升级至 HERMES 团队 |

### 10.3 异常场景矩阵

| 场景ID | 场景描述 | 发生概率 | 影响 | 处理策略 | 状态 |
|--------|---------|---------|------|---------|------|
