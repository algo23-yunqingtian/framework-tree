## 1. 对账架构

```
┌─────────┐     ┌─────────┐     ┌─────────┐
│ HERMES  │ ←→ │  DSHB   │ ←→ │  DSHE   │
│ (写入)  │     │ (流量)  │     │ (大盘)  │
└─────────┘     └─────────┘     └─────────┘
      ↑               ↑               ↑
      └─────── SHA256 哈希抽样 ───────┘
```

## 2. 对账配置

| 参数 | 值 |
|------|---|
| 对账方 | HERMES ↔ DSHB ↔ DSHE |
| 窗口时长 | 3 小时 |
| 窗口数/天 | 8 |
| 对账频率 | 每 24h（覆盖 8 窗口） |
| 校验方式 | SHA256 哈希 + 事件计数 + 丢包偏差 |
| 事件偏差阈值 | ≤0.5% |
| 丢包偏差阈值 | ≤0.5pp |

## 3. 正常对账流程

### 3.1 每 24h 执行

```
1. DSHE 拉取过去 24h 8 个窗口数据
2. 逐窗口校验:
   a. 事件计数偏差 = max(|DSHB-HERMES|, |DSHE-HERMES|) / HERMES × 100%
   b. 丢包偏差 = |HERMES_loss - DSHB_loss| × 100  (pp)
   c. SHA256 哈希比对
3. 输出对账报告:
   - 全部 PASS → 记录归档
   - 任一 FAIL → 触发异常处置流程
4. 趋势监控: 连续 3 窗口偏差上升 → 预警
```

### 3.2 对账报告模板

```yaml
日期: 2026-XX-XX
```

## 4. 异常告警定义

| 告警级别 | 触发条件 | 通知方式 | 响应时间 |
|---------|---------|---------|---------|
| WARN | 单窗口事件偏差 > 0.3% | DSHE 大盘黄灯 | 1h 内排查 |
| WARN | 连续 3 窗口偏差上升 | DSHE 大盘黄灯 | 2h 内排查 |
| ERROR | 单窗口事件偏差 > 0.5% | DSHE 大盘红灯 + 通知值班 | 30min 内处置 |
| ERROR | SHA256 不一致 | DSHE 大盘红灯 + 紧急通知 | 立即处置 |
| CRITICAL | 多窗口偏差同时 > 0.5% | 全平台通知 + 回滚评估 | 立即处置 |

## 5. 异常处置流程

### 5.1 事件计数偏差 > 0.5%

```
1. 冻结当前窗口数据（不覆盖）
2. 逐条比对三端事件序列:
   a. 提取 HERMES 写入事件 ID 列表
   b. 提取 DSHB 流量事件 ID 列表
   c. 提取 DSHE 大盘事件 ID 列表
3. 定位偏差来源:
   - HERMES < DSHB → 写入丢失（排查 WAL/写入失败）
   - HERMES > DSHB → 重复写入（排查去重逻辑）
   - DSHE ≠ HERMES → 大盘聚合延迟（排查 DSHE pipeline）
4. 修正偏差源头
5. 重跑对账验证
6. 记录偏差根因 + 修正措施
```

### 5.2 SHA256 不一致

```
1. 立即冻结窗口（最高优先级）
2. 提取三端原始 payload
3. 逐字节比对:
   a. 编码差异（UTF-8）
   b. 字段顺序差异
   c. 数据截断（payload_truncated）
4. 修复数据一致性
5. 重算 SHA256 并验证
6. 全量重跑对账
7. 输出根因分析报告
```

### 5.3 丢包偏差 > 0.5pp

```
1. 提取三端丢包率统计
2. 校验 write_failures 计数一致性
3. 排查:
   a. DSHB 是否记录了被拒绝事件
   b. DSHE 是否包含重试事件
   c. HERMES write_failures 是否完整
4. 对齐口径
5. 重跑对账
```

## 6. 应急处置流程

### 6.1 多窗口偏差同时超阈值

```
触发: ≥2 个连续窗口事件偏差 > 0.5%
1. DSHE 自动触发红灯告警
2. 通知值班运维 + 主管
3. 评估是否需要降速至 50%
4. 排查根因（优先检查链断裂/去重/WAL）
5. 修复后重跑全 8 窗口对账
6. Gate 复审确认一致性恢复
```

### 6.2 全端不一致（三方均偏离）

```
触发: HERMES/DSHB/DSHE 三方互相偏差 > 0.5%
1. 立即停止流量写入
2. 冻结全部数据
3. 逐端排查（从数据源开始）
4. 定位系统级故障
5. 修复后全量重跑
6. Gate 重审
```
