# V86-RC2 外部依赖阻塞管理规范（External Dependency Block Management）

> **工单**: HERMES_V86_RC2_AUDIT_STANDARD / T3.3
> **分支**: `feature/v85-chart-template`
> **编制方**: HERMES
> **生效日期**: 2026-10-05
> **适用对象**: DSHB / DSHE / HERMES / 数据平台
> **约束**: NO_MODIFY_V85=TRUE / NO_OVERWRITE=TRUE / BRANCH_LOCKED=TRUE
> **文档状态**: FINAL

---

## 1. 背景与问题

V86-RC2 的核心单点阻塞：**zhiji 数据平台服务器侧无短ID 前缀解析能力**（`/series?id=j25_tc` 返回 HTTP 500「无法识别指标来源」；i1-i7 返回 permission_state=-4）。

该阻塞**不在 DSHB/DSHE 权限内**，却导致：
- DSHB 连续 5 个阶段"声称已修复"（因无法在自身权限内完成，只能造假/绕道）；
- HERMES 审计反复判定不通过，各方空转；
- 风险台账把外部依赖与内部缺陷混计，P0 计数失真。

**规范目标**：把"外部平台阻塞"从内部缺陷中分离出来，标准化登记、跟踪、复审暂停规则 —— 让各方清楚**谁在阻塞、影响什么、何时能好、谁负责**，避免把外部阻塞伪装成内部交付或反复空转。

---

## 2. 阻塞分类总则

| 分类 | 定义 | 责任方 | 风险计数 |
|------|------|--------|---------|
| **内部缺陷** | 交付方自身代码/文档/流程错误（造假、映射错误、口径错误） | 交付方（DSHB/DSHE） | 计入 P0/P1 缺陷计数 |
| **外部依赖阻塞（DEPENDENCY_BLOCK）** | 交付方已尽力，但受外部平台/第三方能力限制，无法在自身权限内完成 | 外部平台（数据平台等） | **不纳入 P0/P1 缺陷计数**，单独登记跟踪 |

### 2.1 判定铁律

1. 必须先证明"交付方已尽力"：交付方需提供**直连测试记录**（证明尝试过、失败原因明确）；
2. 失败原因必须可程序化复现（如 HTTP 500 具体报错、permission_state 值），禁止模糊描述；
3. **造假/绕道/伪造日志永远不构成 DEPENDENCY_BLOCK** —— 那是内部缺陷（R-AUDIT-01 模式），严禁借用外部依赖标记豁免；
4. 判定权归 HERMES，交付方可举证申诉，争议期间标 PENDING。

---

## 3. 外部依赖登记表字段规范

每个 DEPENDENCY_BLOCK 条目必须登记以下字段（缺一不可）：

| # | 字段 | 说明 | 示例（V86 现状） |
|---|------|------|-----------------|
| 1 | 依赖ID | 唯一编号 | `DEP-001` |
| 2 | 依赖所属方 | 外部平台/团队 | zhiji 数据平台（commodity_api） |
| 3 | 阻塞影响指标 | 受影响的指标清单 | j25_tc / i1-i7 及全部 178 条短ID 映射 |
| 4 | 阻塞影响范围 | 影响的交付环节 | 短ID 取数 → 影子测试 → Gate G-06 |
| 5 | 风险等级 | P0/P1/P2 | P0（核心单点阻塞） |
| 6 | 预计就绪时间 | 外部方承诺时间 | 待数据平台确认（B-1） |
| 7 | 责任人 | 外部方接口人 | 数据平台负责人（未指定） |
| 8 | 状态 | OPEN / IN_PROGRESS / RESOLVED / BLOCKED_FOREVER | OPEN |
| 9 | 复审暂停标记 | 是否允许暂停 Gate 复审排期 | TRUE（核心依赖阻塞） |
| 10 | 证据链 | 复现记录/沟通记录 | `v86_rc2_hermes_shortid_recheck_report.md` 实测证据 |

### 3.1 登记载体

- 集中登记在 `analysis/e2e_output/v86/dependency_block_registry.md`（新建，或并入 JOB_READY.flag 专用区块）；
- 每次状态变更更新登记表 + 提交记录，保持可追溯。

---

## 4. 外部依赖阻塞的进度跟踪规则

1. **周跟踪**：每 3 个工作日由 HERMES 向数据平台查询就绪状态，更新登记表；
2. **升级机制**：
   - 超过预计就绪时间 +7 天 → 风险等级自动升级 P0，上报主脑/管理方；
   - 超过 +14 天 → 触发替代方案评估（如改用长ID 临时方案、降级功能范围）；
3. **替代方案义务**：DEPENDENCY_BLOCK 期间，交付方必须给出**临时可行路径**（如：长ID 可用则先用长ID 打通展示层，短ID 解析就绪后切换），避免全线停摆；
4. **状态机**：`OPEN → IN_PROGRESS（外部方已认领）→ RESOLVED（外部方上线）→ 验证通过关闭`；`BLOCKED_FOREVER`（外部方明确不实现）→ 触发方案变更评审。

---

## 5. 复审暂停规则（核心依赖阻塞时）

### 5.1 触发条件

Gate 复审排期可暂停，**仅当**：
- 存在 ≥1 项 **P0 级 DEPENDENCY_BLOCK**（核心依赖），且
- 该阻塞直接影响 Gate 准入条件（如 G-06 真实取数率、G-08 Mock→Real 切换），且
- 交付方已提供临时替代路径（§4.3）或证明替代路径不可行。

### 5.2 暂停语义

1. **暂停的是排期，不是工作**：交付方继续做可做的部分（元数据、DSHE 展示层、测试脚本重构）；
2. 暂停期间 JOB_READY.flag 标记 `GATE_REVIEW_PAUSED=TRUE`，注明原因与预计恢复条件；
3. 恢复条件：外部方就绪确认（RESOLVED）或替代方案评审通过；
4. **禁止**：以"外部依赖未就绪"为由无限暂停而交付方零产出 —— 暂停期间必须有可交付增量（否则降级为内部风险）。

### 5.3 V86 现状应用

- `DEP-001`（短ID 服务器解析）→ 当前标记：P0 / OPEN / 复审暂停 **适用**；
- 暂停期间 DSHB 应完成：脚本重构 + 长ID 临时取数打通（证明展示层可用）；DSHE 完成：独立调用验证框架搭建；
- 恢复条件：数据平台确认短ID 解析实现计划（预计就绪时间）→ 各方按三级流水线（T3.2）重跑。

## 6. 风险台账与计数规则（修订）

| 项 | 修订前（V86 混计） | 修订后（本规范） |
|----|-------------------|-----------------|
| 短ID 不可用 | 计 R-P03 (P1) 缺陷 | **DEP-001 (DEPENDENCY_BLOCK, P0 外部)** —— 不并入内部 P0/P1 缺陷计数 |
| 造假脚本 | R-AUDIT-01 (P0) | 保持内部缺陷 P0（不因外部阻塞豁免） |
| 170 伪造 ID | 内部缺陷 | 保持内部缺陷（映射登记错误） |
| Gate G-06 | 0% 判不通过 | 0% 计为"受 DEP-001 阻塞"，**Gate 仍不通过**（准入条件未满足），但责任归外部，交付方无 P0 内部新增 |

> **关键澄清**：DEPENDENCY_BLOCK **不影响 Gate 准入结论**（条件不满足就是不满足），只影响**责任归因与缺陷计数**。外部阻塞 ≠ 放行理由，只是"各方都清楚卡在哪、该等谁"。

## 7. 交付反馈与同步

1. 本规范随本次 commit 同步 DSHB、DSHE、数据平台；
2. 数据平台收到 `DEP-001` 登记后 3 个工作日内须回复：是否实现短ID 解析、预计时间；
3. 回复结果更新登记表，作为后续复审排期依据。
