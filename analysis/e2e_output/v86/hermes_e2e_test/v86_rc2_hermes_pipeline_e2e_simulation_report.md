## 1. 流水线状态机定义（依据规范）

```
L1 DSHB自测(原始payload) → L2 DSHE独立抽样 → L3 HERMES预审 → Gate终审
    FAIL→不流转              FAIL→退回L1       FAIL→Gate不通过
状态机: L1_PENDING→L1_PASS→L2_PENDING→L2_PASS→L3_PENDING→L3_PASS→GATE_REVIEW
```

**各级硬性阻断条款**（源自 `cross_agent_pipeline_spec.md`）：

| 级 | 阻断情形 |
|----|---------|
| L1 | 脚本含 search 中转/自动替换 ID；无原始 payload；requested_id≠resolved_id 未处理；全 0 计 PASS；短ID 直连取数 < 通过率要求 |
| L2 | L1 未过→拒绝接单；COMPLETED 条目抽样通过率 <100%；**背书式引用（转述 DSHB 自报数字、无独立调用）**；未按 COMPLETED/PENDING 分级 | [OLD_CALIBER - METADATA_ONLY, HERMES_INVALID]
| L3 | 脚本源码存在造假模式；实测与自测矛盾（如自测 100% vs 实测 0%）；COMPLETED 条目实测取数失败；L2 背书式引用 |
| Gate | 必备项 G-01/G-02/G-09/G-10 任一 FAIL → 不通过（不可加权） |

**退回语义（关键）**：任一级 FAIL → 退回上一级重做，且**旧日志/旧结论作废**，
不允许"补个报告"续用旧数据。

## 2. 场景 1：正常链路（DEP 就绪，双指标达标）完整流转

### 2.1 仿真前提

这是**条件性正向推演**：假设 DEP-001（短ID 服务器解析）已就绪，
DSHB 提交合规包。标注为"仿真"因为 DEP-001 实测仍 OPEN（§0 证据链）。

### 2.2 载荷构造（合规基线）

- DSHB 脚本：`?id=<被测短ID>` 直连，无 search 中转；
- 日志含 `requested_id == resolved_id` 断言；
- value≠0 且语义匹配校验；
- 原始 payload（请求URL + 响应体）逐条留存。

### 2.3 逐级流转

| 级 | 检查项 | 判定 |
|----|-------|------|
| L1 | 脚本源码无 search 中转 ✓；断言存在 ✓；value≠0 ✓；payload 留存 ✓ | **L1_PASS** |
| L2 | DSHE 用自己的调用链（非调 DSHB 脚本）抽样 ≥10% + 全部 COMPLETED；每条独立取数 | **L2_PASS** |
| L3 | 源码审计通过 ✓；独立复现 ≥5 条 + 对照组 ✓；三方结论一致（无 100%/0% 矛盾） | **L3_PASS** |
| Gate | G-01/02/09/10 全 PASS → 量化项 ≥7/10 | **READY（准入）** |

### 2.4 结论

✅ 正常链路流转行为符合规范：4 级全绿、无退回、旧日志无需作废。
**但当前 V86 不具备该场景的 DEP 前提**（DEP-001 OPEN），此场景为"就绪后应然路径"的验证，
用于确认状态机在正向路径上无死锁、无跳级。

## 3. 场景 2：旧口径错误提交（仅元数据完成，真实可取 0%）→ 流水线拦截

### 3.1 载荷构造（模拟旧口径错误提交）

模拟 DSHB 若沿用旧口径提交的载荷：

| 字段 | 值 |
|------|-----|
| 桥接表 | 178/178 登记完成（短ID↔长ID↔语义ID 三字段齐全） |
| 自称 | `元数据完成率 100%` / `bridge rate 100%` |
| 真实取数 | **0/178（0%）** —— 全部短ID 无有效数据点 |
| 原始 payload | 未留存（仅统计数字） |

> 注意：这与 git 历史中 DSHB 真实提交 `86c1f6e`「170/170 COMPLETED, 100% bridge rate」
> 与同批次修订文档承认真实可取数率 0% **并存**的情况完全同构 ——
> 即旧口径表述残留在系统里的真实形态。

### 3.2 逐级流转

| 级 | 检查项 | 实测/判定 | 结果 |
|----|-------|----------|------|
| L1 | 原始 payload 留存 | ❌ 未留存，不可复核 | **L1_FAIL → 阻断** |
| L1 | value≠0 数据有效性 | ❌ 全 0 计 PASS | **L1_FAIL → 阻断** |
| L2 | L1 未过 → 拒绝接单 | L1 已 FAIL | **L2 不接单** |
| L3 | 实测与自测矛盾（自测 100% vs 实测 0%） | 本轮实测确认 0%（§0） | **L3_FAIL（若强行流转则触发）** |
| Gate | G-06 有效桥接率 ≥80% | 分子 0 → 0% | **FAIL** |

### 3.3 结论

✅ **流水线成功拦截旧口径错误提交**：
- **L1 第一关即阻断**（payload 缺失 + 全 0 计 PASS 双重命中），错误载荷从未到达 L2；
- 即使 L2/L3 被强行喂入（模拟越级），L3 的"实测 vs 自测矛盾"条款仍能拦截（100% vs 0%）；
- Gate 层 G-06 分子为 0，无法通过。
- **拦截点分布：L1（主）→ L3（兜底）→ Gate（终检）三层冗余，任一环节均无法放行。**

**退回后果**：DSHB 必须重写脚本 + 重新测试，**旧桥接表的 178 条登记结论全部作废**，
禁止"补个报告"续用。

## 4. 场景 3：DEP 全阻塞场景 → DEPENDENCY_BLOCK 分类，Gate 判定 NOT_READY

### 4.1 载荷构造（DEP-001 现状）

- DSHB 已提供**直连测试记录**证明"已尽力"：短ID `?id=j25_tc` 返回 HTTP 500；
- 失败原因可程序化复现（§0 证据链，本轮实测复现一致）；
- 失败非交付方脚本缺陷，而是服务器侧无短ID 前缀解析能力 → 归类 **DEPENDENCY_BLOCK**。

### 4.2 分类判定（依据 `audit_canonical_spec.md` §5）

| 情形 | 归类 | 本轮证据 |
|------|------|---------|
| 短ID HTTP 500「无法识别指标来源(id前缀)」 | **DEPENDENCY_BLOCK** | `j25_tc`、`s_001` 实测复现 |
| 短ID permission_state=-4 | **DEPENDENCY_BLOCK**（账号权限） | `i1` 实测复现 |
| 交付方脚本绕道 search / 伪造日志 | **内部缺陷 P0** | 不适用本场景 |
| 桥接表 ID 填错/不存在于 zhiji | **内部缺陷 PENDING** | 与 DEP 混合时需拆分 |

### 4.3 逐级流转

| 级 | 处理 | 结果 |
|----|------|------|
| L1 | 受 DEP-001 影响的条目从"必须通过"清单**暂挂**；其余可测条目照常校验 | L1 部分通过 + DEP 暂挂清单 |
| L2 | 暂挂条目不要求 100% 通过（规范 §6.5） | L2 可推进（非 DEP 部分） |
| L3 | HERMES 判定 DEP 归类成立（有直连证据 + 可复现） | 归类确认 |
| Gate | **DEP 不计入 G-06 分子**，但准入条件仍不满足 → **NOT_READY** | ❌ NOT_READY |

### 4.4 结论

✅ **DEP 分类正确，Gate 不豁免**：
- DEP-001 归类 DEPENDENCY_BLOCK，**不纳入内部 P0/P1 缺陷计数**（责任归数据平台）；
- 但 **Gate 准入判定不受豁免**：条件不满足就是不满足，结论保持 **NOT_READY**；
- 与 DSHB 自己的门控包 V2 一致：`GATE_STATUS = NOT_READY`（data_fetchable_rate=0.0% < 80%）。
- **外部阻塞 ≠ 放行理由**，只是让各方清楚"卡在哪、该等谁"。

## 5. 场景 4：L2 校验失败 → 逐级退回，旧日志作废

### 5.1 载荷构造（两类 L2 失败模式）

| 子场景 | 构造 |
|--------|------|
| 4A：背书式引用 | DSHE 记录写"DSHB 报 60/60 PASS，故本方 PASS"，无独立 API 调用 |
| 4B：抽样不过 | DSHE 独立调用后，COMPLETED 条目取数失败（如取到全 0 或 permission_state=-4） |

### 5.2 逐级流转

| 级 | 4A（背书式） | 4B（抽样失败） |
|----|-------------|---------------|
| L1 | 假设 L1_PASS | 假设 L1_PASS |
| L2 | ❌ 阻断：无独立调用 = 零价值（R-AUDIT-05） | ❌ 阻断：COMPLETED 通过率 <100% |
| L3 | 若强行流入 → 退回 L2 重做 | 不流转 |
| 退回目标 | 退回 **L2** 重做 | 退回 **L1** 重做 |

### 5.3 旧日志作废机制（本轮重点验证项）

规范要求：**任一级 FAIL，退回上一级重做，且旧日志/旧结论作废。**

| 检查 | 4A 结果 | 4B 结果 |
|------|---------|---------|
| DSHE 联合校验记录是否作废 | ✅ 作废（背书式记录零价值，须用自己的调用链重出） | ✅ 作废（抽样结论不可采信） |
| DSHB 自测报告是否作废 | 保留（L1 未失败），但被 L2 退回引用 | ✅ 作废（L1 需重做，旧日志污染） |
| 能否"补个报告"续用旧数据 | ❌ 禁止 | ❌ 禁止 |
| 退回后是否允许复用历史报告 | ❌ 禁止（跨团队约束） | ❌ 禁止 |

### 5.4 结论

✅ **逐级退回 + 旧日志作废机制生效**：
- 4A（背书式引用）精准命中 L2 阻断条款，退回 L2 重做 —— 这正是 V86 教训 R-AUDIT-05 的拦截点；
- 4B（抽样失败）退回 L1，DSHB 须重写脚本 + 重测，旧自测日志作废；
- **旧数据退回后不可复用**：DSHb/DSHE 均不能以"上轮报告 + 增量补丁"方式续用，
  必须从头产出新的独立调用链证据。

## 6. 四场景仿真结果汇总

| 场景 | 输入特征 | 拦截点 | 流转结果 | 结论 |
|------|---------|-------|---------|------|
| 1 正常链路 | DEP 就绪 + 双指标达标 + 合规载荷 | 无拦截 | L1→L2→L3→Gate 全绿 | ✅ READY（条件性，DEP 未就绪为应然验证） |
| 2 旧口径错误 | 元数据 100% + 真实 0% + 无 payload | **L1（主）/L3（兜底）/Gate（终检）** | L1 阻断，不流转 | ✅ 拦截成功，旧桥接表作废 |
| 3 DEP 全阻塞 | 短ID HTTP 500 + 直连证据 | 无拦截（归类成立） | DEP 暂挂 → Gate NOT_READY | ✅ 分类正确，Gate 不豁免 |
| 4 L2 失败 | 背书式引用 / 抽样不过 | **L2** | 退回 L2（4A）/ L1（4B） | ✅ 逐级退回，旧日志作废 |

### 6.1 拦截矩阵（哪一级能拦住什么）

```
                造假脚本  无payload  全0计PASS  背书式引用  实测矛盾  DEP阻塞  伪造ID
L1 阻断规则          ✓         ✓         ✓          -         -        -        ✓
L2 阻断规则          -         -         -          ✓         -        -        -
L3 阻断规则          ✓         -         -          ✓         ✓        -        -
Gate 阻断           -         -         -          -         -        不豁免    ✓
```

**冗余性验证**：任何单一错误至少被 1 层拦截；造假/伪造ID 类错误被 2-3 层冗余拦截。
**无穿透路径**：不存在任何构造能同时绕过 L1→L2→L3→Gate 全部规则。

## 8. 本场景暴露的流程缺口（新增发现）

1. **场景 1 目前不可实测**：DEP-001 OPEN 导致"正常链路"只能做逻辑推演，无法真实跑通。
   建议在 DEP-001 就绪后优先用真实数据重跑场景 1，验证正向路径无死锁。
2. **场景 4A（背书式引用）缺少机器可判定检查**：当前靠 HERMES 人工读记录识别，
   建议 DSHE 在联合校验记录中强制留"独立调用 URL + 响应体"字段，便于自动核验。
3. **退回后旧日志作废缺少技术强制**：当前是规范约束（人守），建议流水线状态机
   在退回时自动将旧报告 MD5 登记为"作废白名单外"，防止后续误引用。
4. **DEP 暂挂清单缺少版本管理**：场景 3 的暂挂条目在 DEP 状态变化时需重新评估，
   建议与 DSHB 的 `dep_ready_trigger.py` 触发器联动（本轮 rebase 已收到该产物）。
