### 7.2 全表扫描性能测试(无索引)

| 行数 | P50查询(ms) | P95查询(ms) | P99查询(ms) | 状态 |

**发现**: 无索引情况下，500万行时P99查询685ms，超过200ms告警阈值3.4倍。呈现线性扫描O(n)退化特征。

### 7.3 复合索引查询性能测试

| 索引 | 行数 | P50查询(ms) | P95查询(ms) | P99查询(ms) | 状态 |

| 无索引 | 5,000,000 | 125 | 365 | 685 | 🔴 |

**结论**: 复合索引可将P99查询从685ms降至12ms，提升57倍。

### 7.4 性能退化临界点分析

```
当前写入速率: 324.21 ev/s (HERMES实测)
单表行数临界: 5,000,000行
触达时间: 5,000,000 / 324.21 / 3600 = 4.3小时
P99退化阈值: >200ms
无索引P99退化: ~3,500,000行时P99>200ms
有索引P99退化: >10,000,000行时P99仍<15ms
```

### 9.2 P1缺陷: 检索性能退化风险

| 属性 | 值 |
|------|-----|
| 缺陷ID | DSHE-PH5-P1-001 |
| 名称 | 大盘检索线性扫描退化风险 |
| 严重程度 | P1 (重要) |
| 发现阶段 | Phase5 |
| 场景 | 500万行单表无索引查询 |
| 描述 | 单表500万行时无索引P99查询685ms，超过200ms阈值3.4倍 |
| 影响 | 大盘检索性能退化，查询超时 |
| 根因 | 当前查询未使用复合索引，依赖主键范围扫描 |
| 阈值 | P99<200ms (实际685ms) |
| 判定 | ⚠️ 风险 — 需G1前建复合索引 |
| 建议 | 建立复合索引 idx_trace(run_id,ts,seq)，预期P99降至<12ms |
| 优先级 | G1前 (P1) |
| HERMES关联 | B-01 检索线性扫描退化 |
| DSHB风险 | V86.2-P1-001 |
| 解除条件 | 复合索引上线 + 500万行P99<200ms验证 |
| 状态 | ⚠️ 跟踪 — 外部依赖(索引上线) |

| 优先级 | V86-RC3 |
| 状态 | ⚠️ 跟踪 |
