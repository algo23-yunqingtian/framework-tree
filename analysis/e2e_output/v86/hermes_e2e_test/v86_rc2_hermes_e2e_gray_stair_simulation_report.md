### 4.3 自动 vs 人工确认的设计依据

- **F1（致命）**：链路级故障（短ID HTTP 500/对照组失败）意味着整个取数链路不可用，
  **立即自动回滚全部品种**，不需人工确认——因为继续放量只会扩大故障面。
- **F2（高）**：审计告警 CRITICAL > 0，自动回滚但需人工确认——因为可能是误报，
  需要审计方判断是真故障还是规则误触发。
- **F3/F4/F5**：需要人工确认——因为这些是**性能/稳定性问题**，可能有多种原因
  （临时抖动、监控误报、外部依赖波动），需要运维+审计方联合判断。

## 5. 回滚执行清单（F1 致命场景）

F1 触发时自动执行的 7 步：

```
1. [自动] 冻结证据包: 标记 retired=true + 归档 MD5
2. [自动] DEP 状态回退: RECOVERED -> ROLLED_BACK (DS-02 合法迁移)
3. [自动] FLAG 恢复: GATE_REVIEW_PAUSED=TRUE, JOB_READY=FALSE
4. [人工] 旧证据包作废: 禁止复用 (L2-R08)
5. [人工] 数据平台通知: 附对照组证据
6. [自动] 事件持久化: CRITICAL 级 + dep_registry_id 关联
7. [人工] 回滚完成记录: DEP_ROLLBACK_COMPLETE 事件
```

### 5.1 逐级阻断与旧数据作废

检查清单 V2 的核心约束：**流水线逐级阻断，旧数据退回后作废，禁止复用历史报告**。

- F1 回滚后，所有证据包标记 `retired=true`；
- DEP 状态回退到 `ROLLED_BACK`（状态机 DS-02 合法迁移）；
- 下一轮重试必须用**全新 run_id**（旧 run_id 会被 L2-R08 检测拦截）；
- FLAG 恢复 `JOB_READY=FALSE`，流水线禁止启动。

### 6.2 DEP 抖动双重判定

**设计要点**：DEP 抖动=3 同时触发**准入不通过**（`dep_flap_max=2`）和**F5 回滚触发**
（`dep_flap >= 3`）。这是双重保护：

- 准入阶段：抖动超限直接不准入（不放量）；
- 已放量阶段：抖动超限触发回滚（回退）。
