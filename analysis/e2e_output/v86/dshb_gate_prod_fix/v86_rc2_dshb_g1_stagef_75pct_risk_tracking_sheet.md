### 1.2 Phase21 风险跟踪目标

本文件作为 **Phase21 StageF 75% Bootstrap 的预备态风险跟踪表**，目标如下：

1. **承接 Phase20 基线**：将 5 项 P2 OPEN 风险（P2-001 ~ P2-005）延续至 75% 阶段重新评估。
2. **识别新增风险**：基于 Phase21 准备工作（容量评估、索引风险评审、混沌预验证、回滚 SOP、Gate 预检查）识别 **8 项新风险**（RISK-001 ~ RISK-008）。
3. **风险量化评分**：采用 `概率 × 影响` 矩阵对全部 13 项风险进行量化评分。
4. **缓解方案落地**：为每项风险制定可执行、可验证的缓解动作，明确责任人与截止时间。
5. **升级标准明确**：定义 P2 → P1 → P0 的升级触发条件，避免风险失控。
6. **实时监控计划**：覆盖 72h × 1.5x 流量的 8,640 个信号点，建立实时风险监控。
7. **Go/No-Go 门禁**：建立基于风险的风险门禁，作为 StageF 75% Bootstrap 决策依据。
8. **登记册版本演进**：建议风险登记册从 V3.0 升级至 V3.1，纳入 8 项新风险。

## §4 风险分类与评分

### 4.1 评分方法

采用 **概率 × 影响** 矩阵进行风险评分：

| 维度 | 等级 | 分值 | 说明 |
|------|------|------|------|
| **概率 (P)** | 极低 | 0.1 | 几乎不可能发生 |
|  | 低 | 0.2 | 可能发生但概率低 |
|  | 中 | 0.3-0.4 | 有一定概率发生 |
|  | 高 | 0.5-0.6 | 很可能发生 |
|  | 极高 | 0.7-0.9 | 几乎确定发生 |
| **影响 (I)** | 轻微 | 1 | 对系统几乎无影响 |
|  | 低 | 2 | 对系统有轻微影响 |
|  | 中 | 3 | 对系统有中等影响 |
|  | 高 | 4 | 对系统有重大影响 |
|  | 严重 | 5 | 对系统有致命影响 |
| **风险分数** | 低 | 0.1-0.9 | 🟢 LOW |
|  | 中 | 1.0-1.9 | 🟡 MEDIUM |
|  | 高 | 2.0-2.9 | ⚠️ HIGH |

## §7 风险升级标准

### 7.1 升级等级定义

| **P1** | ⚠️ HIGH→P1 | 高影响，潜在 P0 | 30min | 全部核心角色 + Gate Board |
| **P0** | 🔴 CRITICAL | 阻断性风险，立即响应 | 15min | 全部角色 + 高管 |

### 7.2 P2 → P1 升级标准

风险满足以下 **任一** 条件时，从 P2 升级为 P1：

| # | 升级条件 | 示例 |
|---|----------|------|
| E-01 | 风险分数 ≥ 2.0 且缓解措施失败 | RISK-002（2.4）缓解失败 |
| E-02 | 风险指标超过 WARN 阈值 2 次以上 | RISK-003 CB-4 延迟超 80ms 2 次 |
| E-03 | 风险指标接近 BLOCKED 阈值（< 20% 余量） | RISK-001 余量 < 0.10% |
| E-04 | 风险关联其他 P1/P0 风险 | RISK-001 + RISK-002 联动 |
| E-05 | 风险在 Bootstrap 期间触发实际影响 | 索引写入失败、CPU 耗尽 |
| E-06 | 缓解措施执行失败或未按时完成 | M-001-1 未按时完成 |

### 7.3 P1 → P0 升级标准

风险满足以下 **任一** 条件时，从 P1 升级为 P0：

| # | 升级条件 | 示例 |
|---|----------|------|
| E-07 | 风险分数 ≥ 3.0 | RISK-001（3.5） |
| E-08 | 风险指标超过 BLOCKED 阈值 | RISK-001 余量 < 0.05% |
| E-09 | 风险导致服务降级或数据完整性风险 | 索引写入失败 |
| E-10 | 风险触发回滚条件 | 触发 75%→50% 回滚 |
| E-11 | 风险导致 Bootstrap 失败 | Bootstrap 中断 |
| E-12 | 风险影响下游系统或客户 | 数据一致性风险扩散 |

### 7.4 各风险升级路径

## §17 结论

### 17.1 核心结论

1. **8 项新风险识别完成**：Phase21 准备工作共识别 8 项新风险（RISK-001 ~ RISK-008），风险识别覆盖容量、熔断、混沌、回滚、一致性等关键维度。

2. **RISK-001 为最高优先级风险** 🔴：索引扩展余量收窄至 WARN（7.95% at 75%, margin 0.05%），风险分数 3.5（CRITICAL），为 Phase21 StageF 75% Bootstrap 的 **TOP RISK**。必须在 Bootstrap 前完成缓解验证。

3. **RISK-002 为次高风险** ⚠️：CPU 余量收窄至 WARN（92% at 75%, margin 0%），风险分数 2.4（HIGH），需与 RISK-001 联合缓解。

4. **5 项延续风险重新评估**：Phase20 的 5 项 P2 OPEN 风险（P2-001 ~ P2-005）在 75% 阶段重新评估，其中 P2-003（索引扩展余量）升级为 OPEN 状态。

5. **13 项风险全部可缓解**：全部 13 项风险（8 新 + 5 延续）均有明确的缓解措施，无不可缓解的 P0 阻断性风险。

6. **风险监控覆盖充足**：10 个信号源、18,432 个 72h 信号，覆盖全部风险指标，远超 8,640 个信号的最低要求。

7. **Go/No-Go 门禁明确**：7 项 GO 条件、6 项 NO-GO 条件、5 项条件批准标准，为 Bootstrap 决策提供明确依据。

8. **风险登记册建议升级 V3.1**：新增 8 项风险，风险总数从 47 增至 55，建议登记册从 V3.0 升级至 V3.1。
