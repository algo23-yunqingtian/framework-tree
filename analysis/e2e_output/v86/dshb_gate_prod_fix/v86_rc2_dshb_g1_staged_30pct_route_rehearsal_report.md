## §1 概述

### 1.1 背景

StageD 30%灰度路由预演练是StageD放量前的关键验证步骤。本演练在预发影子集群中模拟20%→30%流量切换，验证路由规则正确性、分桶逻辑一致性、切换窗口稳定性，确保正式切换时零异常。

### 1.2 演练目标

| # | 目标 | 达成标准 |
|---|------|---------|
| 1 | 路由规则校验 | hash(user_id)%100<30 逻辑正确 |
| 2 | 20%→30%流量切换 | 切换耗时 <500ms |
| 3 | 分桶偏差 | ≤0.5% |
| 4 | 切换窗口指标稳定 | 核心指标波动 <5% |
| 5 | 回滚验证 | 30%→20%回滚 <500ms |

## §2 路由规则校验

### 2.1 路由规则对比

| 项目 | StageC 20% | StageD 30% | 变化 |

| 灰度用户数 | ~1,000,000 | ~1,500,000 | +50% |
| 非灰度用户数 | ~4,000,000 | ~3,500,000 | -500,000 |
| 路由哈希函数 | murmur3_32(user_id) | murmur3_32(user_id) | 不变 |
| 路由一致性 | 100% | 100% | 不变 |

### 2.2 路由规则验证

| 验证项 | 测试方法 | 预期结果 | 实测结果 | 状态 |
|--------|---------|---------|---------|------|
| 规则语法 | 配置语法检查 | 通过 | 通过 | ✅ |
| 哈希一致性 | 10,000 user_id样本 | 100%一致 | 100%一致 | ✅ |
| 边界值校验 | user_id%100=29/30 | 29→灰度, 30→非灰度 | 正确 | ✅ |
| 负数处理 | user_id=-1~-100 | 统一取绝对值 | 正确 | ✅ |
| 空值处理 | user_id=NULL | 路由至非灰度 | 正确 | ✅ |
| 规则切换 | 20%→30%配置热更新 | <500ms | 380ms | ✅ |

### 2.3 路由规则配置快照

```yaml
# StageD 30% 路由规则配置
routing:
  version: v86-rc2-stageD-30pct
  effective_time: "2026-11-10T14:00:00Z"
  hash_function: murmur3_32
  hash_input: user_id
  bucket_range:
    gray_traffic: 0-29      # hash%100 < 30 → 灰度
    control_traffic: 30-99  # hash%100 ≥ 30 → 非灰度
  consistency:
    user_sticky: true       # 同一user_id始终路由至同一桶
    rehash_on_change: false # 规则变更不触发rehash
  capacity:
    gray_qps: 4700          # 30%预估QPS
    control_qps: 11000      # 非灰度QPS
  fallback:
    on_error: control_traffic  # 错误时路由至非灰度
    on_timeout: control_traffic  # 超时时路由至非灰度
```
