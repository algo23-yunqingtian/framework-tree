### 7.2 突发流量行为

```
突发流量时间线 (t=0s至t=5min):

t=0s:    QPS=0 → 1000 (瞬时突发)
t=0-10s: 队列深度从0升至120 (峰值)
t=10s:   限流器触发第一次429 (速率超限)
t=10-60s: 队列深度从120降至0 (排空)
t=60s:   限流器触发第二次429 (突发窗口)
t=60-300s: 稳定在980 QPS (低于1000限制)

突发流量处理流程:
  ┌──────────┐     ┌──────────┐     ┌──────────┐
```

### 16.2 缺陷详情

#### DEF-01: 突发流量队列深度接近上限 (P1)

| 字段 | 值 |
|------|-----|
| **严重度** | P1 |
| **场景** | S3: 突发流量测试 |
| **描述** | 1000 QPS突发时，队列深度瞬时达120，接近配置的200上限 |
| **影响** | 如果突发QPS超过1000，可能导致队列溢出 |
| **缓解措施** | 队列上限已从200提升至500 |
| **状态** | 🟢 已缓解 |

#### DEF-02: 降级响应缺少cache_miss标志 (P1)

| 字段 | 值 |
|------|-----|
| **严重度** | P1 |
| **场景** | S7: DB延迟测试 |
| **描述** | 降级响应(480次)未包含cache_miss标志，无法区分是缓存未命中降级还是其他原因 |
| **影响** | 降级响应无法区分原因，影响故障定位 |
| **修复措施** | 降级响应已添加`"cache_miss": true`字段 |
| **状态** | 🟢 已修复 |

#### DEF-03: 崩溃期间负载均衡切换延迟 (P2)

| 字段 | 值 |
|------|-----|
| **严重度** | P2 |
| **场景** | S6: 进程崩溃测试 |
| **描述** | Pod崩溃后负载均衡切换至其他Pod有~200ms延迟 |
| **影响** | 崩溃期间少量请求(180个)超时 |
| **状态** | 🟡 已接受 (K8s调度延迟，可接受) |
