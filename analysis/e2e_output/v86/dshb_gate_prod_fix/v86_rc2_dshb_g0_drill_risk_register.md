## 2. 风险分级标准

### 2.1 分级定义

| 级别 | 定义 | 修复要求 | 验证要求 | 责任人 |
|------|------|----------|----------|--------|

## 3. P1 警告项

### 3.1 P1-001: 指标采集超时丢弃

| 属性 | 值 |
|------|-----|
| 风险ID | P1-001 |
| 来源 | T3.2 C2 场景 |
| 标题 | 网络抖动期间指标采集超时丢弃 13 条 |
| 描述 | C2 网络时延抖动场景下，5s 超时阈值导致指标采集超时，13 条指标被丢弃 (采集率 98.5%)。虽然未触发 P0 条件 (>95%)，但指标不完整可能影响告警判断。 |
| 影响 | 指标采集率 98.5% (低于 100%)，可能影响 P99 延迟告警的准确性 |
| 触发条件 | 网络延迟 >5s 时指标采集超时 |
| 发生概率 | 低 (仅在网络严重抖动时) |
| 严重程度 | 中 |
| 影响评分 | 65/100 |

**修复方案**：

| # | 方案 | 操作 | 预计效果 | 风险 |
|---|------|------|----------|------|
| 1 | 增加超时阈值 | 5s → 10s | 丢弃率降至 <0.5% | 增加指标延迟 |
| 2 | 增加重试次数 | 1 次 → 3 次 | 丢弃率降至 <1% | 增加网络负载 |
| 3 | 异步采集 | 同步采集 → 异步缓冲+定时flush | 丢弃率降至 0% | 实现复杂度增加 |

**推荐方案**：方案 3 (异步采集)，兼顾指标完整性和网络负载。

**验证方法**：
1. 在混沌环境中注入 500ms±200ms 网络抖动
2. 持续 10min，采集指标
3. 验证指标采集率 100%
4. 验证告警触发时间 <15s

**责任人**：DEP-001 负责人
**截止时间**：G0 投产前 (T-2 天)
**修复状态**：待修复
