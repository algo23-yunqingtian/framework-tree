### 2.3 P0 阻断指标判定规则

```
规则一: 单指标触发
  任一 M-01 ~ M-08 指标进入 P0 阻断范围 → 立即触发熔断

规则二: 双指标联动
  任意两个 M-01 ~ M-08 指标同时处于警告范围 → 触发熔断（预防性）

规则三: 趋势触发
  任一指标在连续3个采样周期内呈单调恶化趋势 → 触发熔断（趋势阻断）

规则四: 窗口重置
  指标从P0阻断范围恢复到警告范围以下，且连续保持5min → 允许进入恢复流程
```

### 3.2 自动回滚判定阈值

#### 3.2.1 时间窗口与计数

| 参数 | 值 | 说明 |
|------|-----|------|
| 滑动窗口长度 | 5 min | 所有P0事件计数均基于5分钟滑动窗口 |
| P0事件计数阈值 | ≥ 2 | 窗口内P0事件计数 ≥ 2 次触发自动回滚 |
| 连续触发次数阈值 | ≥ 3 | 同一熔断触发器连续触发 ≥ 3 次（不经过恢复流程）触发自动回滚 |
| 回滚判定延迟 | ≤ 30s | 从P0事件判定到回滚执行的最长延迟 |
| 回滚决策超时 | 60s | 回滚决策超时后自动升级至紧急止损（Level 4） |

#### 3.2.2 回滚触发判定逻辑

```python
# ============================================================================
# 自动回滚判定逻辑 — 伪代码
# ============================================================================

def auto_rollback_decision(event_stream):
    """
    5分钟滑动窗口内的自动回滚判定引擎
    """
    window = sliding_window(event_stream, duration=5 * 60)  # 5分钟
    p0_events = [e for e in window if e.severity == 'P0']
    unique_triggers = set(e.trigger_id for e in p0_events)
    consecutive_fuse_count = get_consecutive_fuse_count()
    
    # 条件1: P0事件计数 ≥ 2
    if len(p0_events) >= 2:
        log.warning("回滚触发: 5min窗口内P0事件计数={}".format(len(p0_events)))
        return ROLLBACK_LEVEL_3  # 全面降级
    
    # 条件2: 同一触发器连续触发 ≥ 3 次
    if consecutive_fuse_count >= 3:
        log.warning("回滚触发: 连续熔断次数={}".format(consecutive_fuse_count))
        return ROLLBACK_LEVEL_4  # 紧急止损
    
    # 条件3: 双指标联动（M-01~M-08任意2项同时处于P0或警告）
    warning_count = count_metrics_in_warning_range()
    p0_count = count_metrics_in_p0_range()
    if (p0_count >= 1 and warning_count >= 1) or (warning_count >= 2):
        log.warning("回滚触发: 双指标联动 P0={} Warning={}".format(p0_count, warning_count))
        return ROLLBACK_LEVEL_2  # 流量降级
    
    # 条件4: 单P0事件但未达到回滚阈值
    if p0_count >= 1 and consecutive_fuse_count < 3:
        return FUSE_BLOCK  # 仅熔断，不触发回滚
    
    return NORMAL  # 正常
```

#### 3.2.3 回滚级别映射

| 触发条件 | 回滚级别 | 对应操作 |
|----------|----------|----------|
| 单P0事件（< 2次/窗口） | 熔断BLOCK | 仅熔断，不自动回滚 |
| P0事件 ≥ 2/窗口 | Level 3 — 全面降级 | 完全回滚至V85 |
| 连续熔断 ≥ 3次 | Level 4 — 紧急止损 | 全量切回，人工介入 |
| 双指标联动 | Level 2 — 流量降级 | 降低灰度权重 |

```
│       │                        │                                    │
│       │    恢复验证通过         │    超时/失败（15min）              │
│       │                        │                                    │
│       │                        ▼                                    │
│       │                  ┌──────────┐                              │
│       │                  │ ESCALATED │ ← 人工介入/紧急止损           │
│       │                  └──────────┘                              │
│       │                                                            │
│       └────────────────────────────────────────────────────────────│
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

#### 状态定义

| 状态 | 含义 | 系统行为 | 持续时间上限 |
|------|------|----------|-------------|
| ACTIVE | 正常运行，无熔断 | 全部功能开放，灰度放量正常 | — |
| BLOCKED | P0熔断触发，流量已归零 | 阻断灰度放量，停止决策，保留诊断 | 15 min |
| RECOVERY | 恢复条件满足，正在恢复 | 逐步恢复权重，持续观测 | 30 min |
| ESCALATED | 恢复失败/超时，已升级人工介入 | 全量切回，等待人工指令 | — |

#### 状态转换规则

| 转换 | 触发条件 | 超时 | 超时动作 |
|------|----------|------|----------|
| ACTIVE → BLOCKED | 任一P0触发条件满足 | — | — |
| BLOCKED → RECOVERY | 所有触发P0的指标恢复至正常范围，且连续稳定 ≥ 5min | 15 min | BLOCKED → ESCALATED |
| RECOVERY → ACTIVE | 逐步恢复权重，所有指标正常，综合评分 ≥ 95/100 | 30 min | RECOVERY → ESCALATED |
| RECOVERY → BLOCKED | 恢复过程中新P0事件触发 | — | 重新进入BLOCKED |
| ESCALATED → ACTIVE | 人工指令，根因修复，全量验证通过 | — | — |

### 3.4 四阶段灰度熔断阈值调整

灰度放量分为 StageA / StageB / StageC / StageD 四个阶段，各阶段的熔断阈值按风险递增逐步收紧。

| 阶段 | 灰度权重 | 审计丢失率P0 | P99告警延迟P0 | P99决策延迟P0 | 错误率P0 | DB连接池P0 | 回滚触发 |
|------|----------|-------------|---------------|---------------|----------|------------|----------|
| **StageA** 初始灰度 | 1% | > 0.3% | > 800ms | > 1200ms | > 1.5% | > 90% | ≥ 1 P0事件 |
| **StageB** 小范围验证 | 5% | > 0.4% | > 900ms | > 1350ms | > 1.8% | > 92% | ≥ 1 P0事件 |
| **StageC** 中范围放量 | 10% | > 0.45% | > 950ms | > 1400ms | > 1.9% | > 93% | ≥ 2 P0事件 |
| **StageD** 大范围放量 | 20% | > 0.5% | > 1000ms | > 1500ms | > 2.0% | > 95% | ≥ 2 P0事件 |

#### 阈值调整逻辑

```
StageA: 最严格（1%流量，任何P0即回滚）
  → 小流量验证，确保核心链路无误
  → 熔断阈值取标准值的60%-80%
  
StageB: 较严格（5%流量）
  → 扩大验证范围，增加并发场景
  → 熔断阈值取标准值的80%-90%

StageC: 标准阈值（10%流量）
  → 中等放量，与Phase3基线环境一致
  → 熔断阈值取标准值的90%-95%

StageD: 标准阈值（20%流量）
  → 大范围放量，接近全量
  → 熔断阈值回归标准值（与Phase3一致）
  → 回滚触发阈值从≥1放宽至≥2（容忍偶发波动）
```

## §4 人工介入触发条件

以下场景需要人工介入，自动回滚机制不足以安全处理。

### 4.1 人工介入场景矩阵

| 编号 | 触发场景 | 触发条件 | 介入级别 | 介入角色 | 响应时间 |

| HI-03 | P0事件持续 | P0事件持续 > 5min 且未自动恢复 | P0 | 灰度值班 + SRE | ≤ 3 min |
| HI-04 | 跨团队依赖异常 | DEP/HERMES/Gate 等跨团队服务异常导致级联故障 | P0 | 灰度值班 + 对接团队 | ≤ 10 min |
| HI-05 | 业务影响扩大 | 灰度阶段中错误率/延迟恶化趋势无法通过熔断遏制 | P0 | 灰度值班 + 业务方 | ≤ 3 min |

```

  └─ 持续 > 5min？
```

## §5 降级策略

### 5.1 降级策略总览

```
Level 1: 功能降级 ─── 关闭非核心功能，保留核心链路
     │
     ▼ （若Level 1不足以遏制）
Level 2: 流量降级 ─── 降低灰度权重至更低比例
     │
     ▼ （若Level 2不足以遏制）
Level 3: 全面降级 ─── 完全回滚至V85基线
     │
     ▼ （若Level 3失败或情况危急）
Level 4: 紧急止损 ─── 全量切回，熔断强制开启
```

### 5.2 Level 1 — 功能降级

| 项目 | 说明 |
|------|------|
| **触发条件** | 单一P0指标进入警告范围但未达P0阻断；或双指标联动处于警告状态 |
| **降级目标** | 降低系统负载，保留核心审计链路和决策链路 |
| **预期恢复时间** | ≤ 10 min |
| **回退条件** | 所有P0指标恢复正常，连续稳定5min |

#### 操作清单

| 操作编号 | 操作项 | 具体操作 | 影响范围 | 预期耗时 |
|----------|--------|----------|----------|----------|
| L1-01 | 关闭非核心告警规则 | 暂停LR-006~LR-010（非核心告警） | 告警通知数量减少 | 2 min |
| L1-02 | 降低审计投递频率 | HERMES投递频率从500/s降至200/s | 审计延迟可能增加 | 1 min |
| L1-03 | 暂停非必要决策计算 | 关闭CF01-CF03场景的决策计算 | 非核心场景决策暂停 | 3 min |
| L1-04 | 暂停内存密集型扫描 | 暂停内存分析扫描任务 | 内存漂移监控暂停 | 1 min |
| L1-05 | 降低WAL归档频率 | WAL归档间隔从60s延长至120s | WAL磁盘使用率下降 | 2 min |

```
回退条件（全部满足）:
```

| **降级目标** | 降低灰度流量权重，减少压力源 |

### 6.2 一键回滚脚本详细说明

```bash
#!/bin/bash
# ============================================================================
# DSHB V86 RC2 G1 灰度一键回滚脚本
# 用途: 紧急回滚灰度流量至V85基线
# 约束: NO_MODIFY_V85=TRUE (仅回滚，不修改V85)
#       NO_OVERWRITE=TRUE   (不覆盖已有配置)
#       BRANCH_LOCKED=TRUE  (分支锁定，不操作代码分支)
# ============================================================================

# --- 参数定义 ---
TARGET_CLUSTER="g1-gray-cluster"
ROLLBACK_TARGET="v85"
GATE_NAME="g1-gray-gate"
DEP_CLUSTER="g1-gray-dep"
EVENTS_SINK="v85-sink"
REASON="${1:-emergency_rollback}"

# --- 前置检查 ---
echo "[CHECK] 确认分支锁定状态..."
dshb config status --scope g1 --field BRANCH_LOCKED | grep -q "TRUE" && \
  echo "[OK] BRANCH_LOCKED=TRUE" || echo "[FAIL] 分支未锁定"

echo "[CHECK] 确认V85不被修改..."
dshb config status --scope g1 --field NO_MODIFY_V85 | grep -q "TRUE" && \
  echo "[OK] NO_MODIFY_V85=TRUE" || echo "[FAIL] V85可能被修改"

echo "[CHECK] 确认无覆盖操作..."
dshb config status --scope g1 --field NO_OVERWRITE | grep -q "TRUE" && \
  echo "[OK] NO_OVERWRITE=TRUE" || echo "[FAIL] 可能覆盖配置"

# --- 步骤1: 熔断强制开启（5s） ---
echo "[STEP 1/5] 熔断强制开启..."
dshb fuse force-enable --cluster ${TARGET_CLUSTER} --reason "${REASON}"
echo "[OK] 熔断已开启"

# --- 步骤2: 流量权重归零（30s） ---
echo "[STEP 2/5] 流量权重归零..."
dshb traffic weight --target v86 --weight 0 --gate ${GATE_NAME}
echo "[OK] 流量已归零"

# --- 步骤3: 事件投递切换（30s） ---
echo "[STEP 3/5] 事件投递切换至V85..."
dshb events switch --to ${EVENTS_SINK} --target ${TARGET_CLUSTER} --force
echo "[OK] 事件已切换"

# --- 步骤4: Gate下线（10s） ---
echo "[STEP 4/5] Gate紧急下线..."
dshb gate offline --gate ${GATE_NAME} --force --timeout 10s
echo "[OK] Gate已下线"

# --- 步骤5: 状态确认 ---
echo "[STEP 5/5] 回滚状态确认..."
dshb status --cluster ${TARGET_CLUSTER} --expect v85 --timeout 60s
echo "[OK] 回滚完成，集群已切换至V85"

# --- 后处理 ---
echo ""
echo "============================================="
echo "  回滚完成。请执行以下后续操作:"
echo "  1. 确认V85基线运行正常"
echo "  2. 检查审计事件投递完整性"
echo "  3. 通知相关团队回滚完成"
echo "  4. 启动事故复盘流程（如适用）"
echo "============================================="
```

### 6.3 止损操作决策矩阵

