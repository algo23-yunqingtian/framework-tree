## 2. 复测背景与目标

### 2.1 复测背景

Phase5 于2026-10-18定稿了三方指标口径规范V1.0 (`v86_rc2_dshb_g1_tripartite_metric_spec_v1.0.md`)，针对Phase3/Phase4发现的4项P0级口径问题(M-CAL-001~M-CAL-004)进行了统一修正：

| 问题编号 | 问题描述 | Phase5修正方案 |
|---------|---------|--------------|
| M-CAL-001 | 吞吐统计范围不一致(raw vs filtered vs ingested) | 4层分层计数: raw=847.3 / filtered=812.4 / ingested=782.1 / WAL_persisted=761.2 ev/s |
| M-CAL-002 | 事件丢失率分母/分子定义不同 | 全链路统一基准: raw_ingressed→wal_persisted, 0.008% |
| M-CAL-003 | P99时延一个笼统定义(≤500ms)无法区分业务/审计/WAL | 3类独立P99: P99_业务端到端≤30s / P99_审计入库≤1000ms / P99_WAL写入≤50ms |
| M-CAL-004 | 72h总量窗口对齐方式不一致 | UTC+8对齐窗口: raw=52,458,720 / WAL=47,980,608 |

Phase4 Gate预检已完成106项检查(全部PASS)，但使用的仍是旧口径定义。Phase6需基于V1.0口径规范完整重跑全量预检，验证：

1. V1.0指标口径在现有基础设施上的兼容性
2. LR-001~LR-010告警规则基于新口径的正确性
3. 8场景SOP在V1.0口径下的指标上报/告警触发/状态流转兼容性
4. 告警抑制率统计模块支持≥1200样本+Wilson置信区间计算

## 7. 复测发现与缺陷闭环

复测共发现3项缺陷和歧义点, 全部已完成修订闭环。

### 7.1 FINDING-001: LR-005/LR-006阈值边界值未达精确匹配

| 属性 | 内容 |
|------|------|
| 发现类型 | 告警阈值边界 |
| 严重级别 | P2 (非阻断) |
| 发现阶段 | §5.1 LR规则V1.0口径校验 |

**问题:** LR-005(DB连接池>250/300=83%)在Phase4旧阈值为>200/300(67%), 调整后阈值从67%跳升至83%, 中间73%~83%区间为"无告警区"。LR-006(P99_审计延迟增长>10%/24h)在旧口径下基线为"P99告警延迟", 新口径下明确为"P99_审计入库延迟增长", 基线462ms需重新校准。

**影响:** P2, 非阻断性。阈值调整本身正确, 但边界值需要补充中间状态告警(如WARNING级别)。

**修订:**
- LR-005补充WARNING级别: 连接池>220(73%)持续30s触发WARNING, >250(83%)触发P1
- LR-006确认基线462ms与Phase3基线一致, 无需额外校准
- 新增LR-005W(Warning级): 连接池73%~83%区间使用WARNING级别

**修订状态:** ✅ 已修订 — LR规则V1.0.1已更新。

### 7.2 FINDING-002: 丢失率分母在Gate下线期间计算逻辑不明确

| 属性 | 内容 |
|------|------|
| 发现类型 | 指标计算逻辑 |
| 严重级别 | P1 |
| 发现阶段 | §4.6 C5 Gate下线回放 |

**问题:** V1.0口径定义丢失率=1-(wal_persisted/raw_ingressed), 但C5(Gate下线)场景下, raw_ingressed和wal_persisted同时归零, 计算结果为0/0=NaN。旧口径中该场景丢失率显示为0%, 新口径中需明确处理规则。

**影响:** P1, 影响C5/CF02场景的丢失率计算和LR-001/LR-008告警判断。

**修订:** V1.0口径补充: 当raw_ingressed=0时, 丢失率定义为0%(无事件产生时无丢失), 并记录"raw_ingressed=0"特殊状态标志。LR-001/LR-008在raw_ingressed=0时不触发(无分母则不计算)。已更新至metric_spec_v1.0.1。

**修订状态:** ✅ 已修正 — metric_spec_v1.0.1已发布, C5/CF02场景重新验证PASS。

### 7.3 FINDING-003: 4层分层吞吐在极端场景下的计数一致性

| 属性 | 内容 |
|------|------|
| 发现类型 | 指标计算一致性 |
| 严重级别 | P2 (非阻断) |
| 发现阶段 | §3.11 监控类预检 |

**问题:** 4层分层吞吐(raw→filtered→ingested→WAL)在极端场景(CF03: 50000 QPS洪泛+端口阻断)下, 各层计数存在瞬时不一致(100ms窗口内raw层比WAL层多计数约0.3%)。原因是4层计数采用独立异步计数器, 在极端负载下各层写入WAL的延迟不同步。

**影响:** P2, 非阻断性。偏差<0.5%, 在LR-001/LR-008阈值(0.5%)以内。但在持续极端负载下可能累积。

**修订:**
1. 4层计数器增加同步屏障: 每个100ms窗口结束时, 各层计数同步刷新
2. 新增"层间偏差"监控指标: |layer[i] - layer[i+1]| / layer[i] > 0.3% 时触发WARNING
3. 在gate_pre_check_auto_v5.py中新增4层一致性检查项(作为SC10检查)

**修订状态:** ✅ 已修订 — 同步屏障已部署, 一致性监控指标已上线。
