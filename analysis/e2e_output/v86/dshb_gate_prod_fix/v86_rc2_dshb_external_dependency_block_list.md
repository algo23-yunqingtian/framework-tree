## 1. 外部依赖识别

DSHB V86-RC2 在生产门禁验证过程中，发现若干数据获取能力存在外部平台依赖缺失，导致 178 项指标数据无法正常获取。以下按发现顺序逐条说明。

### 1.1 短ID服务器解析能力缺失

**问题描述**: DSHB 侧在构建 series API 请求时，使用 short_id 前缀形式（如 `j25_tc`）传递给数据平台 API，期望服务端自动解析 short_id 并定位对应的数据系列。然而 zhiji API 服务端当前**不支持** short_id 前缀解析，直接返回错误。

**错误日志**:
```
HTTP 400: 无法识别指标来源(id前缀): j25_tc
```

**影响范围**: 全部 178 项受影响指标中，涉及 short_id 解析的条目均返回该错误。short_id 格式包括：
- `j25_tc` (沪铅期货收盘价)
- `j26_tc` (沪锌期货收盘价)
- `i01` ~ `i07` (8项原有条目)
- 新增 170 项中使用的同类前缀格式

**DSHB 侧现状**: 短ID解析逻辑已重构为 long_id 查询作为回退方案，但 long_id 路径存在数据错配问题（见 1.3 节）。

### 1.2 权限状态异常 (permission_state=-4)

**问题描述**: 使用 8 项原有条目中的 i01~i07 调用 series API 时，返回数据点数为 0，且附带 `permission_state=-4` 标记。

**错误日志**:
```json
{
  "code": 0,
  "data": [],
  "permission_state": -4,
  "message": "无数据权限或数据未绑定"
}
```

**可能原因**:
| 原因 | 概率 | 验证方式 |
|------|------|----------|
| DSHB 账号权限不足 | 中 | 需数据平台确认权限模型配置 |
| 指标未绑定到数据源 | 高 | 需数据平台确认指标-数据源映射 |
| 数据源已下线但索引未更新 | 低 | 需数据平台核查数据源状态 |

**DSHB 侧现状**: DSHB 无法自行修复权限问题，需在数据平台侧调整。

### 1.3 长ID数据错配

**问题描述**: 使用 long_id（如 `ID02226332` ~ `ID02226339`）调用 series API 时，返回数据与预期指标**完全不匹配**。以下为部分样本：

| long_id | 预期指标 | 实际返回指标 | 匹配度 |
|---------|----------|--------------|--------|
| ID02226332 | 沪铅期货收盘价 | LME锌库存 | 0% |
| ID02226333 | 沪锌期货收盘价 | 沪铜库存 | 0% |
| ID02226334 | 沪铜期货收盘价 | LME镍库存 | 0% |
| ID02226335 | LME锌库存 | 沪铝库存 | 0% |
| ID02226336 | LME镍库存 | LME铝库存 | 0% |
| ID02226337 | 沪铜库存 | 沪锌库存 | 0% |
| ID02226338 | 沪铝库存 | LME铜库存 | 0% |
| ID02226339 | LME铝库存 | LME锌库存 | 0% |

**分析**: long_id 的分配规则可能为**顺序分配**而非**指标绑定分配**，导致 ID 与指标内容完全脱钩。该问题需数据平台确认 ID 分配规则后方可修正。

**DSHB 侧现状**: DSHB 无权限修改 long_id 分配规则，也无法通过 API 反查 long_id 实际对应的指标名称。

### 1.4 数据平台侧能力边界

DSHB 团队无权修复以下底层能力，均依赖数据平台（zhiji API 服务端）的支持：

| 底层能力 | DSHB 权限 | 说明 |
|----------|-----------|------|
| short_id 前缀解析 | ❌ 无权限 | 服务端解析逻辑，非客户端可修改 |
| long_id 分配规则 | ❌ 无权限 | ID 生成与绑定逻辑由平台控制 |
| API 权限模型 | ❌ 无权限 | 账号-指标-数据源绑定关系 |
| 数据源生命周期管理 | ❌ 无权限 | 数据源下线/迁移后的索引更新 |
| 搜索 API 扩展 | ❌ 无权限 | DSHB 建议的替代方案需平台评估 |

| 4 | LME锌库存 | — | `ID02226335` | long_id 返回 沪铝库存 |

### 3.3 170项新增条目

V86-RC2 新增的 170 项指标全部使用 short_id 格式构建 series API 请求，依赖数据平台的 short_id 前缀解析能力。

**short_id 命名规则**:
```
j25_tc  →  沪铅期货收盘价
j26_tc  →  沪锌期货收盘价
j27_tc  →  沪铜期货收盘价
i01     →  沪铜库存
i02     →  沪铝库存
...
j{N}_tc →  其他期货收盘价指标
j{N}_ic →  其他期货库存指标
...
```

**新增 170 项分类**:

| 类别 | 数量 | short_id 格式 | 示例 |
|------|------|--------------|------|
| 期货收盘价 | 45 | `j{N}_tc` | j25_tc, j26_tc, j27_tc... |
| 期货库存 | 38 | `j{N}_ic` | j25_ic, j26_ic, j27_ic... |
| LME 库存 | 22 | `lme_{N}_ic` | lme_zn_ic, lme_ni_ic... |
| LME 收盘价 | 18 | `lme_{N}_tc` | lme_zn_tc, lme_ni_tc... |
| 现货价格 | 15 | `spot_{N}` | spot_pb, spot_zn... |
| 加工费/升贴水 | 12 | `rc_{N}` | rc_pb_3m, rc_zn_3m... |
| 其他金属指标 | 20 | 各类 | 包括铜、铝、镍等衍生指标 |

> 由于 short_id 解析能力缺失，以上 170 项**全部**返回 HTTP 400 错误。

### 3.4 47项计算推导指标

47 项计算推导指标本身不调用 API 取数，但依赖 8+170=178 项基础指标的可取数状态。

**计算推导类型**:

| 类型 | 数量 | 依赖指标 | 计算公式示例 |
|------|------|----------|-------------|
| 库存消费比 | 12 | 库存 + 消费 | 库存 / (消费 × 250) |
| 加工费/利润 | 8 | 现货价格 + 加工费 | 现货价格 - (进口到岸价 + 加工费) |
| 期货基差 | 10 | 期货收盘价 + 现货价格 | 期货收盘价 - 现货价格 |
| 库存消费天数 | 6 | 库存 + 日均消费 | 库存 / 日均消费 |
| 升贴水 | 5 | 期现价格 | 现货升贴水 = 现货价 - 期货价 |
| 其他 | 6 | 各类组合 | 根据具体指标定义 |

> **级联阻塞说明**: 若 178 项中任一基础指标取数失败，依赖该指标的 47 项计算推导指标也将级联阻塞。目前 178 项全部阻塞 → 47 项全部级联阻塞。

### 6.2 替代方案详细设计

#### 方案 A：long_id + 搜索 API

**核心思路**: 不依赖 short_id 前缀解析，改用 long_id 直接查询，结合搜索 API 验证 long_id 对应的指标名称。

**流程**:
```
1. 使用搜索 API 搜索指标名称 → 获取 long_id
2. 使用 long_id 调用 series API → 获取数据
3. 交叉验证 long_id 返回的数据与预期指标是否匹配
4. 若匹配 → 正常返回数据
5. 若不匹配 → 标记异常，记录日志
```

**优势**:
- 不依赖 short_id 前缀解析能力
- 可通过搜索 API 动态解析指标名称到 long_id 的映射
- 长期可维护，不依赖固定的桥接表

**风险**:
- 搜索 API 可用性需数据平台确认
- long_id 分配规则需确认（当前存在错配问题）
- 需增加交叉验证逻辑，增加 API 调用量

#### 方案 B：桥接表固化 + long_id 直接查询

**核心思路**: 手动构建并定期维护 short_id → long_id 桥接表，直接使用 long_id 查询。

**流程**:
```
1. 维护桥接表 (short_id → long_id)
2. 使用 long_id 调用 series API → 获取数据
3. 定期验证桥接表准确性
```

**优势**:
- 不依赖 short_id 解析能力
- 实现简单

**风险**:
- 桥接表需人工维护，可能过期
- 无法解决 long_id 数据错配问题
- 新增指标时需手动更新桥接表
