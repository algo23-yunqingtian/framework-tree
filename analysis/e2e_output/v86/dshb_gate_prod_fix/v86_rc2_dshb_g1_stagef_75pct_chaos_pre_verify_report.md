### 1.3 Phase21 75% Chaos 预验证目标

Phase21 目标是将混沌工程流量比例从 50% 提升至 **75%**，并设计 **8 个更具攻击性的场景**（4×L2 + 4×L3），验证：

1. **索引膨胀防护触发机制** — CHAOS-F7 为核心新增场景，验证 3× 正常速率写入时 L2 保护是否正确触发
2. **DB 故障转移恢复路径** — CHAOS-F5/F6 验证 PostgreSQL 主从切换 + WAL 延迟场景
3. **75% 高负载下的多实例联合故障** — CHAOS-F8 验证 50% 实例下线后剩余实例承压能力
4. **三方对账在混沌期间的完整性** — 验证 8 轮对账无偏差
5. **回滚就绪性** — 2 次紧急回滚测试（模拟混沌期间回滚决策）

**预期整体结果**: 8/8 PASS, L2 触发 5-6 次, L3 触发 1-2 次, FUSE 0 次, CONDITIONAL PASS
