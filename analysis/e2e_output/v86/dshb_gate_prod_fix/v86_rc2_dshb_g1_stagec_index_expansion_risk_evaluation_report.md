## §1 概述

### 1.1 背景

Phase14 StageB 15% 灰度 72h 长跑观测数据显示，索引膨胀率持续在 **7.1%~7.25%** 区间运行，与告警阈值 **7.36%** 仅余 **0.11%~0.26%** 的余量。随着 StageC 流量从 15% 提升至 20%（增幅 33.3%），索引膨胀速率预计将同步上升，存在突破 WARN 阈值的风险。

本报告基于 15% 灰度全周期索引增长时序数据，完成 20% 流量下膨胀速率预判、风险评估、缓解预案制定，并给出 WARN 阈值调整建议。

| 推荐缓解方案 | 索引重平衡 + WARN 阈值调整为 8.0% + 定时压缩 |

## §8 应急处理预案

### 8.1 索引膨胀率突破 WARN 阈值应急流程

```
阶段1: WARN 触发 (8.0%)
  ├─ 自动告警 → SRE 值班通知
  ├─ 确认膨胀率趋势 (检查索引碎片化报告)
  ├─ 判断: 自然增长 vs 异常膨胀
  ├─ 若自然增长: 执行手动重平衡 (约 15min)
  ├─ 若异常膨胀: 启动故障排查流程
  └─ 恢复后确认膨胀率回落至 7.5% 以下

阶段2: 逼近 CRITICAL (8.5%)
  ├─ P1 告警 → 升级至技术负责人
  ├─ 立即执行索引重平衡 + 全量压缩
  ├─ 必要时启动 StageC 回滚预案
  └─ 评估是否需要暂停放量

阶段3: CRITICAL 触发 (8.5%)
  ├─ P0 告警 → 全员通知
  ├─ 启动自动保护: 索引写入限流 (降至 50%)
  ├─ 执行紧急重平衡
  ├─ 启动 StageC 回滚 (12min SLA)
  └─ 事故复盘
```

### 8.2 紧急重平衡操作指南

| 步骤 | 操作 | 预计耗时 | 注意事项 |
|------|------|---------|---------|
| 1 | 确认当前索引膨胀率与碎片化率 | 1min | 通过监控面板查看 |
| 2 | 在低流量时段 (凌晨 03:00~05:00 UTC) 执行 | — | 避免影响业务流量 |
| 3 | 执行 `reindex --force` 命令 | 10~15min | 不停服，在线操作 |
| 4 | 执行 `compact --deep` 碎片回收 | 5min | 与 reindex 并行 |
| 5 | 验证膨胀率回落至 <7.0% | 2min | 检查监控指标 |
| 6 | 确认查询 P99 延迟正常 | 1min | 确保性能未受影响 |
| 总耗时 | | **~25min** | |

### 8.3 回滚触发条件

| 触发条件 | 阈值 | 动作 |
|---------|------|------|
| 索引膨胀率 > 8.5% | CRITICAL | 立即回滚至 StageB 15% |
