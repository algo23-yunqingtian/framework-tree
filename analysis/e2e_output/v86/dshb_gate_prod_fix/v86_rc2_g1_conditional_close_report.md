### §3.1 长稳微小残差 — 审计丢失率 0.09%

| 丢失事件估算 | ~24,600 条 |
| 统计周期 | 72h 全周期 |

#### 3.1.2 根因分析

| 序号 | 根因 | 详细描述 |
|------|------|---------|
| R1 | 事件队列消费堆积 | 高负载期间队列积压，消费者速率低于生产者，导致部分事件超期丢弃 |
| R2 | HERMES WAL 写入延迟 | WAL 同步刷盘在高并发下产生微秒级抖动，极端情况下丢失已确认但尚未刷盘的事件 |
| R3 | 网络抖动期间事件丢失 | 跨节点事件转发链路在短暂网络分区期间发生不可恢复的发送失败 |

#### 3.1.3 修复措施

| 序号 | 措施 | 详细说明 | 预期效果 |
|------|------|---------|---------|
| F1 | 优化事件队列消费堆积策略 | 批量消费 + 优先级调度，按事件紧急度动态分配消费线程 | 消除队列堆积 |
| F2 | 补齐丢失事件重试机制 | 3 次重试 + 指数退避（1s → 2s → 4s），重试耗尽后写入补偿队列 | 消除单点丢失 |
| F3 | 审计管道扩容 | 缓冲容量从 512 扩容至 2048，增加背压感知 | 消除溢出丢失 |
| F4 | 事件补偿队列 | 本地持久化 + 定时 flush（30s 间隔），确保宕机后事件不丢失 | 消除持久化丢失 |

### §3.2 高并发 P99 波动 — 告警延迟 553ms > 500ms 阈值

#### 3.2.1 Phase2 实测数据

| 指标 | Phase2 终值 | 告警阈值 | 超标 |
|------|-----------|---------|------|
| P99 告警延迟 | 553ms | 500ms | ✅ 超标 |

#### 3.2.2 根因分析

| 序号 | 根因 | 详细描述 |
|------|------|---------|
| R1 | 连接池伸缩不足 | 连接池 max=200，高并发场景下连接数逼近上限，等待时间增加 |
| R2 | WAL 刷盘延迟 | 同步 WAL 写入在高负载时产生毛刺，拖慢告警链路 |
| R3 | 队列优先级调度不均 | P0/P1/P2 事件共用同一队列，实时告警被批量事件阻塞 |

#### 3.2.3 修复措施

| 序号 | 措施 | 详细说明 | 预期效果 |
|------|------|---------|---------|
| F1 | 连接池伸缩策略优化 | min=50 / max=300，空闲超时 30s 自动回收 | 消除连接等待毛刺 |
| F2 | WAL 刷盘策略优化 | 批量刷盘（batch size=128）+ 压缩调度（每 48h 自动压缩归档） | 消除 WAL 抖动 |
| F3 | 队列优先级调度 | P0 实时通道 / P1 准实时通道 / P2 批量通道，独立队列隔离 | 消除阻塞毛刺 |
| F4 | 缓存策略审查 | LRU 缓存命中率从 78% 提升至 95%，减少回源查询 | 降低整体延迟 |

#### 3.2.4 复测结果

#### 3.4.1 Phase2 实测数据

#### 3.4.2 根因分析

| 序号 | 根因 | 详细描述 |
|------|------|---------|
| R1 | GC 策略不足 | G1GC 在高负载下 Full GC 暂停时间达 50ms，频繁触发导致内存碎片累积 |
| R2 | 连接池自动缩容缺失 | 空闲连接未回收，高水位运行状态下连接数持续攀升 |
| R3 | 句柄泄漏 | 文件句柄和 socket 句柄未及时关闭，长运行后缓慢累积 |
| R4 | WAL 无压缩调度 | WAL 只写不压缩，72h 后磁盘占用膨胀 4 倍 |
| R5 | 索引膨胀 | 热表索引在长运行后页分裂，空间利用率下降 |

#### 3.4.3 修复措施

| 序号 | 措施 | 详细说明 | 预期效果 |
|------|------|---------|---------|
| F1 | GC 策略优化 | G1GC → ZGC，暂停时间从 50ms 降低至 8ms | 消除 GC 暂停导致的内存碎片 |
| F2 | 连接池自动缩容 | 空闲连接 5 分钟自动回收，维持 min=50/max=300 弹性伸缩 | 消除连接数超限 |
| F3 | 句柄泄漏检测 + 资源清理调度 | 每 30min 执行一次全量句柄扫描 + 回收，清理超时连接 | 消除句柄累积 |
| F4 | WAL 压缩调度 | 每 48h 自动压缩，磁盘自动扩展（max 2x），消除磁盘膨胀 | 消除 WAL 膨胀 |
| F5 | 索引膨胀监控 + 自动重建 | 每周一次索引重建（低峰时段），监控页分裂率 | 消除索引膨胀 |
