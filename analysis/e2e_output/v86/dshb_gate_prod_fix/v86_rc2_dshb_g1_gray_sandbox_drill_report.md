## 6. T3.5 — 沙箱演练发现与修订

### 6.1 FINDING-001: 故障注入脚本变量未定义

| 属性 | 内容 |
|------|------|
| 发现类型 | 脚本缺陷 |
| 严重级别 | P2 (非阻断) |
| 发现阶段 | §3.1 C1 注入步骤 |

**问题:** C1注入脚本中`$TARGET_POD`在某些路径下未定义，`kubectl delete pod`可能收到空值参数。

```bash
# 问题代码 (gate_inject_c1.sh):
TARGET_POD=$(echo $DEP_PODS | cut -d' ' -f1)
kubectl delete pod $TARGET_POD -n dep --force --grace-period=0  # 空值风险
```

**影响:** P2, 触发概率<0.1%(仅在Pod调度异常时)。影响C1/C2/C3脚本。

**修订:**
```bash
# 修订后 (gate_inject_c1_v2.sh):
if [ -z "$DEP_PODS" ]; then echo "ERROR: DEP_PODS empty" >&2; exit 1; fi
TARGET_POD=$(echo $DEP_PODS | cut -d' ' -f1)
if [ -z "$TARGET_POD" ]; then echo "ERROR: TARGET_POD empty" >&2; exit 1; fi
kubectl delete pod "$TARGET_POD" -n dep --force --grace-period=0
if [ $? -ne 0 ]; then echo "ERROR: kubectl failed" >&2; exit 1; fi
```

**修订状态:** ✅ 已修复 — 所有变量添加空值检查，kubectl命令引号包裹，退出码检查。

### 6.2 FINDING-002: SOP步骤顺序歧义

| 属性 | 内容 |
|------|------|
| 发现类型 | SOP步骤歧义 |
| 严重级别 | P1 |
| 发现阶段 | §3.4 C4 回滚自愈验证 |

**问题:** C4(mTLS失效)SOP中"删除证书"和"验证mTLS握手失败"两步顺序不清，未说明需等待mTLS客户端缓存TTL(默认30s)过期后再验证。立即验证可能因缓存导致假阳性。

**影响:** P1, 可能导致验证结果不准确。

**修订:** SOP修订 — Step 2后增加`sleep 30`等待缓存过期，Step 3在缓存过期后验证mTLS握手失败，Step 4增加熔断器状态验证。

**修订状态:** ✅ 已修订 — SOP文档已更新。

### 6.3 FINDING-003: 告警恢复条件阈值不一致

| 属性 | 内容 |
|------|------|
| 发现类型 | 告警配置不一致 |
| 严重级别 | P1 |
| 发现阶段 | §4 LR告警高并发回放 |

**问题:** LR-006(延迟增长率)恢复条件为"增长率<1%/24h持续5min"，LR-007(延迟绝对值)恢复条件为"绝对值<150ms持续5min"。SOP统一描述为"恢复到基线值后5min"，未区分增长率和绝对值。导致LR-007在延迟降到180ms时未恢复(180ms>150ms)，而去重窗口计算偏差(§4.5去重率37.1%偏低)。

**影响:** P1, 影响告警准确性和去重。

**修订:** LR-007恢复阈值从150ms调整为200ms(基线值)。SOP补充增长率/绝对值恢复判据说明：增长率类规则(LR-001/LR-002/LR-004/LR-006)以增长率为恢复判据，绝对值类规则(LR-003/LR-005/LR-007/LR-008/LR-009/LR-010)以绝对值为恢复判据，所有恢复阈值均基于Phase3基线值设定。

**修订状态:** ✅ 已统一。

### 6.4 FINDING-004: 回滚后状态重置遗漏步骤
