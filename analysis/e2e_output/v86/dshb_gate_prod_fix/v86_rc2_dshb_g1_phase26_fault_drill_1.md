## 1. 概述

### 1.1 演练目标

本次故障演练是 Phase26 韧性验证的核心环节之一，旨在验证以下关键能力：

| # | 验证目标 | 覆盖维度 |
|---|---|---|
| 1 | **L1 限流触发** — CB-4 延迟飙升时自动限流 | 检测灵敏度 |
| 2 | **L2 降级激活** — CPU 飙升时自动降级非关键链路 | 资源保护 |
| 3 | **节点故障自动转移** — 单节点宕机后剩余节点接管 | 高可用 |
| 4 | **网络抖动容错** — 50ms 延迟 + 30% 丢包下的系统稳定性 | 网络韧性 |

| 6 | **自动恢复** — 无数据丢失、业务影响可控 | SLA 保障 |

#### 2.2.2 丢包期间预期行为矩阵

| 丢包比例 | 预期系统行为 | 重试策略 | 是否触发熔断 |
|---|---|---|---|
| 0-10% | 重试隐藏延迟, 无感知 | 指数退避 1s/2s/4s | ❌ 不触发 |
| 10-20% | 重试成功, 延迟增加 | 指数退避 + 超时截断 | ❌ 不触发 |
| 20-30% (本次注入) | 部分超时, 重试失败 | 超时后切换节点 | 🟡 可能触发 L1 |
| 30-50% | 大量超时, 熔断触发 | 熔断前最后一波重试 | 🔴 触发 L1/L2 |
| 50%+ | 节点不可用, 完全转移 | 全部重试失败 | 🔴 触发 L2/L3 |

```bash
tc qdisc del dev eth0 root netem
# 验证移除
tc -s qdisc show dev eth0
# 输出: (无输出 = 已移除) ✅
```

### 3.3 FD-26-COMBINED: 复合故障注入

| 参数 | 值 |
|---|---|
| 注入顺序 | 同时 (并行注入) |
| FD-26-01 执行时间 | 03:50:00 |
| FD-26-02 执行时间 | 03:50:00 |
| 并行间隔 | < 1s (脚本并行调度) |
| 预期总恢复时间 | ≤ 5min |
| 并行注入风险 | 转移过程中网络不稳定, 可能增加重试开销 |

**并行注入脚本**:
```bash
#!/bin/bash
# FD-26-COMBINED 并行注入脚本
# 执行时间: 2026-11-05 03:50:00

echo "[$(date '+%Y-%m-%d %H:%M:%S')] FD-26-COMBINED: 并行注入开始"

# 并行注入
(
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] FD-26-01: 断电 node-3"
    ipmitool -I lanplus -H 10.0.3.103 -U admin -P Passw0rd! chassis power off
) &
IPMI_PID=$!

(
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] FD-26-02: 注入网络抖动"
    tc qdisc add dev eth0 root netem delay 50ms 10ms distribution normal loss 30%
    sleep 180  # 3min 后移除
    tc qdisc del dev eth0 root netem
) &
TC_PID=$!

echo "[$(date '+%Y-%m-%d %H:%M:%S')] 注入已触发, 等待恢复..."
wait $IPMI_PID $TC_PID

echo "[$(date '+%Y-%m-%d %H:%M:%S')] FD-26-COMBINED: 注入完成"
```

### 10.2 技术优化方向

#### 10.2.1 故障检测加速

**当前**: 心跳超时 5s, 检测到故障约 1s  
**优化方向**:
- 引入主动健康检查 (push-based health check)
- 减少心跳间隔 (5s → 2s)
- 引入基于指标的故障预测 (延迟趋势 + CPU 趋势)
- 预期效果: 检测延迟 1s → 300-500ms

#### 10.2.2 流量转移加速

**当前**: 44s 完成流量转移  
**优化方向**:
- 预配置节点权重, 故障后快速调整
- 实现渐进式转移 (先转移 50%, 确认稳定后转移剩余)
- 引入预测性转移 (在检测到趋势时提前启动)
- 预期效果: 转移时间 44s → 15-20s

#### 10.2.3 降级粒度细化

**当前**: 3 项非核心任务降级  
**优化方向**:
- 支持按请求类型 (P0/P1/P2/P3) 分级降级
- 支持按业务线降级 (不影响非受影响业务)
- 支持动态降级阈值 (根据当前负载调整)
- 预期效果: 更灵活的降级策略, 更精细的业务保护
