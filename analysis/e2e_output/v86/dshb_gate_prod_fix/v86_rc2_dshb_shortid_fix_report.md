## 2. 故障根因分析

### 2.1 j25_tc HTTP500根因

| 维度 | 分析 |
|------|------|
| 现象 | j25_tc API调用返回HTTP 500 |
| 根因 | API端缓存预热不完整, 首次请求触发缓存miss, 导致后端超时 |
| 影响 | 间歇性500错误, 影响数据获取 |
| 修复 | 缓存预热+重试机制+降级预案 |

### 2.2 i1/i2 permission_state=-4根因

| 维度 | 分析 |
|------|------|
| 现象 | i1/i2 API调用返回permission_state=-4, 无数据 |
| 根因 | 权限预加载未完成, 权限初始化失败导致permission_state=-4 |
| 影响 | 数据无法获取, 面板显示空值 |
| 修复 | 权限预加载+初始化机制修正 |

### 2.3 API数据解析问题

| 维度 | 分析 |
|------|------|
| 现象 | API返回HTTP 200但data字段为空 |
| 根因 | API实际返回数据在points字段, 非data字段, 解析逻辑错误 |
| 影响 | 数据被判定为"空响应", 实际有数据 |
| 修复 | 解析逻辑修正: 检查points和data两个字段 |

## 3. 修复方案

### 3.1 j25_tc HTTP500修复

```
修复措施:
  1. 缓存预热: 启动时预加载j25_tc数据到缓存
  2. 重试机制: HTTP500时自动重试3次, 间隔1s
  3. 降级预案: 重试失败后降级到备用数据源
  4. 限频保护: 请求间隔≥1s, 避免触发API限频
```

### 3.2 i1/i2 permission_state=-4修复

```
修复措施:
  1. 权限预加载: 启动时预加载权限配置
  2. 权限初始化: 确保权限状态正确初始化
  3. 权限检查: 每次请求前检查权限状态
  4. 降级处理: 权限异常时降级到缓存数据
```

### 3.3 API数据解析修复

```
修复措施:
  1. 检查points字段: API返回数据在points数组中
  2. 检查data字段: 兼容data字段格式
  3. 非零值判定: 检查数据值是否非零
  4. 采样记录: 记录前3个数据点作为采样
```
