## 1. 概述

### 1.1 背景

DSHB_V86_RC2_G1 项目 Phase19 阶段聚焦于 StageE 50% 灰度流量切换前的资源扩容与性能优化工作。在完成 Phase18 StageD 30% 灰度流量 72 小时观测验证后，系统整体运行平稳，核心指标全部达标，具备向 50% 流量级别推进的基础条件。

然而，根据 Phase18 观测数据评估，当前系统资源分配在 30% 流量下已接近瓶颈阈值，若直接进行 50% 流量切换，存在以下风险：

- **CPU 利用率预计突破 88% 阈值**，逼近系统安全红线
- **渲染线程池存在拥塞隐患**，P99 延迟在 30% 流量下已达 192-202ms，接近 200ms 阈值
- **缓存命中率在流量增长场景下可能回落**，影响整体查询性能

### 1.2 目标

本次 Phase19 资源扩容与优化工作旨在：

1. ✅ 确保 50% 灰度流量下 CPU 利用率 ≤88%
2. ✅ 确保查询线程池利用率 ≤75%，消除瓶颈
3. ✅ 确保渲染 P99 延迟 ≤200ms
4. ✅ 确保缓存命中率 ≥97%
5. ✅ 确保存储增长速率控制在 1,600MB/天以内

### 1.3 范围

| 维度 | 范围 |
|------|------|
| 集群 | `pre-prod-shadow-cluster` |
| 流量 | 50% 灰度（从 30% 扩至 50%） |
| 优化项 | S4 查询池线程扩容、S5 缓存预热策略优化、S6 渲染批处理优化 |
| 持续时间 | 2026-10-10 14:00 至 2026-10-11 18:00 UTC（约 28 小时） |
| 涉及组件 | dshb-query-worker、dshb-render-worker、dshb-cache-manager、dshb-storage-engine |

## 3. 资源扩容与优化实施方案

### 3.1 查询池线程扩容 (S4)

#### 3.1.1 变更概述

| 属性 | 变更前 | 变更后 | 变化幅度 |
|------|--------|--------|----------|
| 查询线程池大小 | 24 threads | 30 threads | +6 threads (+25%) |
| 线程池队列容量 | 1024 | 1280 | +256 (+25%) |
| 核心线程数 | 16 | 20 | +4 (+25%) |
| 最大等待时间 | 5000ms | 6000ms | +1000ms |
| 拒绝策略 | CallerRunsPolicy | CallerRunsPolicy | 不变 |

#### 3.1.2 技术实现

- **变更文件**: `dshb-query-worker/src/main/resources/query-pool-config.yaml`
- **配置变更**:
  ```yaml
  query-pool:
    core-pool-size: 20        # 原值: 16
    max-pool-size: 30         # 原值: 24
    queue-capacity: 1280      # 原值: 1024
    max-wait-ms: 6000         # 原值: 5000
    keep-alive-seconds: 60    # 不变
    rejection-policy: CALLER_RUNS  # 不变
  ```
- **生效方式**: 滚动重启 query-worker 实例（无状态，支持零停机重启）
- **回滚方案**: 回退 YAML 配置至 Phase18 版本，触发滚动重启

#### 3.1.3 预期效果

| 场景 | 30%流量 (24 threads) | 50%流量 (30 threads, 预测) |
|------|---------------------|---------------------------|
| 查询线程池利用率 | 72-80% | 65-72% |
| CPU 利用率 | 80-87% | 82-86% |
| 查询 P99 延迟 | 275-290ms | 270-285ms |
| 查询 P95 延迟 | 240-260ms | 235-255ms |

### 3.2 缓存预热策略优化 (S5)

#### 3.2.1 变更概述

| 属性 | 变更前 | 变更后 |
|------|--------|--------|
| 预热方式 | 被动缓存（请求触发） | 主动预热 + 被动缓存双模式 |
| 预热范围 | 无主动预热 | Top 50 查询模板 + Top 100 高频查询 |
| 预热触发 | 应用启动时 | 应用启动时 + 定时刷新（每 30 分钟） |
| 预热并发度 | - | 8 threads |
| 缓存 TTL | 动态（基于访问频率） | 预热缓存固定 TTL 15min + 动态 TTL |

#### 3.2.2 技术实现

- **新增组件**: `dshb-cache-manager/src/main/java/com/dshb/cache/warmup/CacheWarmupScheduler.java`
- **新增配置**: `dshb-cache-manager/src/main/resources/cache-warmup-config.yaml`
  ```yaml
  cache-warmup:
    enabled: true
    schedule-interval-minutes: 30
    threads: 8
    top-templates: 50
    top-queries: 100
    warmup-ttl-seconds: 900
    skip-if-hit-rate-above: 0.975
    metrics-endpoint: /actuator/metrics/cache.warmup
  ```
- **缓存预热逻辑**:
  1. 从查询日志中提取 Top 50 高频模板 ID
  2. 从访问日志中提取 Top 100 高频查询参数
  3. 并发发起预热请求，填充缓存
  4. 记录预热命中率、耗时、缓存大小变化
- **回滚方案**: 关闭 `enabled: false`，系统回退至被动缓存模式

#### 3.2.3 预期效果

| 场景 | 30%流量 (被动缓存) | 50%流量 (主动预热) |
|------|-------------------|-------------------|
| 缓存命中率 | 96.5-97.5% | 97.0-97.8% |
| 缓存内存使用率 | 72-80% | 74-82% |
| 缓存预热耗时 | - | 3-8 秒 |
| 冷启动缓存覆盖率 | - | ≥60% |

### 3.3 渲染批处理优化 (S6)

#### 3.3.1 变更概述

| 属性 | 变更前 | 变更后 |
|------|--------|--------|
| 渲染处理方式 | 逐条串行处理 | 批处理（50 items/batch） |
| 渲染结果缓存 | 无 | LRU 缓存（容量 5000 条，TTL 5min） |
| 渲染队列深度 | 无限制 | 限制最大 2000 |
| 批处理超时 | - | 30 秒/批 |

#### 3.3.2 技术实现

- **变更文件**:
  - `dshb-render-worker/src/main/java/com/dshb/render/RenderBatchProcessor.java`（新增）
  - `dshb-render-worker/src/main/java/com/dshb/render/RenderResultCache.java`（新增）
  - `dshb-render-worker/src/main/resources/render-batch-config.yaml`（新增）
- **批处理配置**:
  ```yaml
  render-batch:
    enabled: true
    batch-size: 50
    batch-timeout-ms: 30000
    queue-max-size: 2000
    result-cache:
      enabled: true
      max-size: 5000
      ttl-seconds: 300
      eviction-policy: LRU
    metrics-endpoint: /actuator/metrics/render.batch
  ```
- **渲染结果缓存策略**:
  - 缓存键：`render:{templateId}:{parametersHash}:{theme}:{resolution}`
  - 缓存值：预渲染的二进制图表数据
  - 命中场景：相同模板 + 相同参数的重复图表请求
- **回滚方案**: 设置 `batch-enabled: false`，系统回退至逐条串行模式

#### 3.3.3 预期效果

| 场景 | 30%流量 (串行) | 50%流量 (批处理) |
|------|---------------|-----------------|
| 渲染 P99 延迟 | 192-202ms | 185-195ms |
| 渲染 P95 延迟 | 165-172ms | 155-168ms |
| 渲染平均耗时 | 135-145ms | 120-132ms |
| 渲染缓存命中率 | - | 15-25% |
| 渲染队列深度 | 50-120 | 30-80 |

- **应对措施**:
