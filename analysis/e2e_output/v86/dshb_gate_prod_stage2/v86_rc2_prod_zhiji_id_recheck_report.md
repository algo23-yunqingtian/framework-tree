## 4. 短 ID 接口实测验证 (j25_tc / i1 / i2)

### 4.1 测试背景

Stage1 发现短 ID (j25_tc / i1 / i2) 调用时出现以下问题：

| 问题编号 | 问题描述 | 发生次数 | 影响 |
|----------|----------|----------|------|
| P-01 | HTTP 500 错误 | 3 次 | 短 ID 解析失败，数据链路中断 |
| P-02 | 空响应 (permission_state=-4) | 2 次 | 数据为空，无法判断是"无数据"还是"无权限" |
| P-03 | 间歇性失败 | 5 次 | 结果不稳定 |

**根因分析**:
- **HTTP 500**: zhiji API 短 ID 解析服务在特定条件下返回内部错误 (服务侧 bug，已在 Stage1 报修)
- **空响应 (permission_state=-4)**: 权限检查逻辑缺陷，`permission_state=-4` 表示"无权限"但返回 HTTP 200 + 空数据，导致误判为"无数据"
- **间歇性失败**: 短 ID 缓存未命中时回退至实时查询，实时查询服务不稳定

**Stage2 修复措施**:
- 修复短 ID 缓存机制，减少实时查询依赖
- 修复权限检查逻辑，`permission_state=-4` 返回 HTTP 403 而非 HTTP 200
- 添加重试机制 (3 次, 指数退避)
- 添加降级机制 (短 ID 解析失败时回退至指标搜索)
