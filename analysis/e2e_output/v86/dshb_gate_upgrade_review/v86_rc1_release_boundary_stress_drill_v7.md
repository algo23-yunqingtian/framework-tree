## 3. 场景一: 资产同步超时 (BS-01)

### 3.1 场景基本信息

| 属性 | 值 |
|------|-----|
| **场景编号** | BS-01 |
| **场景名称** | 资产同步超时 |
| **风险等级** | 🟡 Tier 2 (中危) |
| **发生窗口** | T+2h ~ T-0 (发布前最终同步阶段) |
| **触发概率** | 低 (5%) |
| **场景描述** | 发布前资产同步过程中, 172 个文件分步同步, 任一步骤 (分支同步/资产打包/MD5 校验/tag 创建) 因网络波动、文件锁竞争、磁盘 IO 瓶颈等原因超时或失败 |

### 3.2 触发条件与概率评估

| 触发因素 | 概率 | 说明 |
|---------|------|------|
| 网络抖动 (push/fetch 超时) | 15% | Git 远端响应延迟 >5min |
| 文件锁竞争 | 8% | 并行任务写入同一文件 |
| 磁盘 IO 瓶颈 | 5% | 大量文件打包时磁盘吞吐不足 |
| Git tag 冲突 | 3% | `v86-rc1` tag 已存在远端 |
| 分支基线漂移 | 5% | rebase 过程中远端有新 commit |
| 其他 | 64% | 正常同步 |

**综合触发概率**: 5%

### 3.3 影响范围

| 影响维度 | 受影响项 | 影响程度 | 说明 |
|---------|---------|---------|------|
| 发布时序 | 发布时间延迟 | 中 | 同步阶段延迟 5-15 分钟 |
| 资产完整性 | 部分文件未同步 | 中 | 已同步部分仍有效 |
| 下游步骤 | 后续步骤阻塞 | 中 | 版本切换等待同步完成 |
| 用户影响 | 发布延迟 | 低 | 用户无感知, 仅发布推迟 |
| 数据影响 | 无 | 无 | 不涉及数据变更 |

### 3.4 自动恢复能力分析

| 恢复机制 | 状态 | 说明 |
|---------|------|------|
| 自动重试 | ✅ 有 | Git 操作内置 `GIT_CURL_OPT=--retry 5 --retry-delay 10`, 最多 5 次重试, 间隔 10 秒 |
| 自动降级 | ❌ 无 | 无降级路径, 同步必须完成 |
| 自动熔断 | ✅ 有 | 单次操作超时阈值 300 秒, 超时后熔断 |
| 自动回滚 | ❌ 无 | 同步阶段不涉及回滚 |

**自动恢复评估**: 部分可恢复 (网络抖动场景), 文件锁和 IO 瓶颈需人工介入

## 5. 场景三: MD5 校验批量失败 (BS-03)

### 5.1 场景基本信息

| 属性 | 值 |
|------|-----|
| **场景编号** | BS-03 |
| **场景名称** | MD5 校验批量失败 |
| **风险等级** | 🔴 Tier 1 (高危) |
| **发生窗口** | T-2h ~ T+2min (同步与验证阶段) |
| **触发概率** | 极低 (1%) |
| **场景描述** | MD5 校验过程中, 模拟 10% 以上 (≥17 个) 文件 MD5 不匹配, 可能导致发布阻塞。可能原因: 文件传输损坏、磁盘损坏、Git pack 损坏、文件被中间人篡改 |

### 5.2 触发条件与概率评估

| 触发因素 | 概率 | 说明 |
|---------|------|------|
| 网络传输损坏 (文件丢失/重复) | 2% | Git 传输层错误 |
| 磁盘损坏 | 0.5% | 文件系统异常 |
| Git pack 损坏 | 0.5% | 仓库 pack 文件损坏 |
