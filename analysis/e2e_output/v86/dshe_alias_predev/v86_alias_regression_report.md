### 4.2 F3 与 F3+F4 在本语料上一致

本语料的 165 条全部是**自配对**（`a = b = alias_norm`），canonical 交集非空且多于 1 个。F4 的自触发抑制针对的是**黑名单 pattern 在同一字符串内的自触发**（如 BL-012 的 `库存天数` ⊃ `库存`），而 165 条冲突样本的裁决走的是 R-07 `alias_ambiguous_multi_canonical` 路径（黑名单无命中），因此 F4 未被触发。

**这符合预期**：F3 和 F4 解决的是不同层面的问题——F3 解决裁决链顺序和全量上报，F4 解决黑名单自触发误伤。本语料不触发 F4 是正确行为，不是 F4 失效。

## 6. A_重复注册类（47 条）的特别说明

A_重复注册类是仅差 `_N` 尾缀的机械重复注册（如 `li_21_openinterest` 和 `li_21_openinterest_2`），上一轮本应通过自动合并处理（`action_mode=auto_merge`）。V86 引擎将它们降级为 REVIEW 是**正确行为**：

1. **引擎不负责数据清洗**：`_N` 尾缀的合并应通过离线脚本处理（`action_mode=auto_merge`），而非在运行时裁决
2. **运行时降级是安全兜底**：如果自动合并脚本未执行，V86 引擎通过 REVIEW 确保这些样本不会静默错指标
3. **上线顺序约束**：F2 不得先于 53 条 P0 歧义人工择优部署（参见 `v86_alias_engine_full_design.md` §5）
