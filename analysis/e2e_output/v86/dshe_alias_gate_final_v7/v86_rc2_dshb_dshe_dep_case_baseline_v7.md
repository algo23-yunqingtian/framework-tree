## 4. 验证步骤标准流程

### 4.1 通用验证流程

每个用例切换后执行以下标准验证流程：

```
验证步骤:
┌──────────────────────────────────────────────────────────────┐
│  Step 1: 格式验证                                              │
│  ├─ 检查Real数据格式与Mock规格一致                               │
│  ├─ 检查字段数量与类型                                            │
│  └─ FAIL → 阻断切换，标记格式异常                                │
│                                                              │
│  Step 2: 数据完整性验证                                         │
│  ├─ 检查所有字段值非空/非NULL                                     │
│  ├─ 检查数据范围在有效区间内                                       │
│  └─ FAIL → 阻断切换，标记数据缺失                                │
│                                                              │
│  Step 3: 业务逻辑验证                                           │
│  ├─ 执行用例的业务逻辑检查                                       │
│  ├─ 验证Real数据满足用例预期                                     │
│  └─ FAIL → 标记业务异常，评估是否回滚                            │
│                                                              │
│  Step 4: 一致性验证                                             │
│  ├─ 检查Real数据与Mock数据的格式一致性                            │
│  ├─ 检查Real数据与Mock数据的语义一致性                            │
│  └─ FAIL → 标记一致性异常，评估是否回滚                          │
│                                                              │
│  Step 5: 回归验证                                               │
│  ├─ 运行用例的回归测试                                            │
│  ├─ 验证用例PASS                                                  │
│  └─ FAIL → 标记回归失败，触发回滚                                │
│                                                              │
│  Step 6: 最终裁定                                              │
│  ├─ 全部PASS → 切换完成，标记REAL                                  │
│  ├─ WARNING → 标记后继续                                         │
│  └─ FAIL → 触发回滚                                             │
└──────────────────────────────────────────────────────────────┘
```
