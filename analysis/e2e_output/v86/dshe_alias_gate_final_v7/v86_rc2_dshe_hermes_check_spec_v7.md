## 2. HERMES 校验框架

### 2.1 校验架构

```
HERMES 校验架构:
┌─────────────────────────────────────────────────────────────────────┐
│  Layer 1: 数据准备层                                                 │
│  ├─ 数据源校验 (API/Cache/Static)                                    │
│  ├─ 数据格式校验 (JSON Schema)                                       │
│  └─ 数据完整性校验 (字段完整性/缺失率)                                │
│                                                                     │
│  Layer 2: 归一化校验层                                               │
│  ├─ 单位归一化 (CNY/USD/ton/%/GWh)                                   │
│  ├─ 时间粒度归一化 (日/周/月/季)                                      │
│  ├─ 统计口径归一化 (均价/加权/移动)                                   │
│  └─ 数据类型归一化 (INT/FLOAT/STRING/JSON)                           │
│                                                                     │
│  Layer 3: 业务校验层                                                 │
│  ├─ 渲染校验 (36图表全量渲染)                                         │
│  ├─ 阈值校验 (C1-C5 Gate条件)                                       │
│  ├─ 数据一致性校验 (图表↔DSHB↔回填字段)                              │
│  ├─ 异常检测校验 (z-score/范围/波动率)                                │
│  └─ 格式校验 (标题/单位/图例/配色)                                   │
│                                                                     │
│  Layer 4: 报告层                                                    │
│  ├─ 校验结果汇总 (PASS/FAIL/WARN)                                    │
│  ├─ 异常详情 (哪些用例/图表/指标失败)                                │
│  └─ 自动修复建议 (可自动修复 vs 需人工介入)                           │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.2 自动化级别定义

| 级别 | 说明 | HERMES占比 | 适用场景 |
|------|------|-----------|---------|
| 全自动 (AUTO) | HERMES完全自动化校验, 无需人工介入 | 88.2% | 格式/数值/渲染校验 |
| 半自动 (SEMI) | HERMES自动检测+人工确认 | 14.1% | 异常检测/业务逻辑校验 |
| 人工 (MANUAL) | 完全依赖人工评审 | 0% | 无 (本轮全部可自动化) |

### 2.3 校验结果定义

| 结果 | 说明 | 处理 |
|------|------|------|
| PASS ✅ | 全部校验通过 | 继续下一项 |
| FAIL ❌ | 校验失败, 阻塞发布 | 标记阻塞, 需修复 |
| WARN ⚠️ | 校验通过但有警告 | 记录警告, 条件发布 |
| SKIP ⏭️ | 跳过校验 | 记录跳过原因 |

│  ├─ 数据源连接检查 (API/Cache/Static)                                │
│  ├─ 数据格式校验 (JSON Schema)                                       │
│  ├─ 数据完整性检查 (字段完整性/缺失率)                                │

│                                                                     │
│  Step 2: 归一化处理 (Normalization)                                   │

│  └─ 数据类型归一化 (INT/FLOAT/STRING/JSON)                           │
│                                                                     │
│  Step 3: 业务校验执行 (Validation)                                    │
│  ├─ 渲染校验 (36图表全量)                                             │
│  ├─ 阈值校验 (C1-C5)                                                │
│  ├─ 数据一致性校验 (图表↔DSHB↔回填字段)                               │
│  ├─ 异常检测校验 (z-score/范围/波动率)                                │
│  └─ 格式校验 (标题/单位/图例/配色)                                   │
│                                                                     │
│  Step 4: 结果汇总 (Aggregation)                                      │
│  ├─ 校验结果统计 (PASS/FAIL/WARN/SKIP)                               │
│  ├─ 异常详情汇总 (哪些用例/图表/指标失败)                             │
│  └─ 自动修复建议 (可自动修复 vs 需人工介入)                           │
│                                                                     │
│  Step 5: 报告输出 (Reporting)                                        │
│  ├─ 校验报告生成 (JSON/Markdown)                                     │
│  ├─ 异常报告生成 (含修复建议)                                         │
│  └─ 发布决策建议 (GO/GO⚠️/NO-GO)                                    │
└─────────────────────────────────────────────────────────────────────┘
