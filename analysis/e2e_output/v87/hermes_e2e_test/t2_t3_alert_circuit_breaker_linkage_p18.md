## 2. ⚠️ 关键发现：CPU 峰值余量告警

**Phase34 30 天长稳（720h）真实观测到 CPU 峰值逼近熔断阈值**：

| 指标 | Phase34 实测 | 阈值 | 余量 | 严重度 |
|---|---|---|---|---|
| CPU 均值 | 1.93% | 2.0% | 0.07pp | ⚠️ 需关注 |
| **CPU 峰值** | **1.98%** | **2.0%** | **0.02pp（余量 1%）** | **⚠️ 临界** |
| 内存峰值 | 78.1% | 80% | 1.9pp | 安全 |
| 内存均值 | 76.7% | 80% | 3.3pp | 安全 |

**这是 Phase18 稳态观测发现的最重要的临界信号**：CPU 峰值 1.98% 距熔断阈值 2.0% 仅 0.02pp。虽 720h 全程 0 熔断触发，但余量已不足 1%。

### 2.1 临界性判定的意义

| 项 | 判定 |
|---|---|
| 当前状态 | ✅ 安全（0 熔断触发，720h 验证） |
| 余量状态 | ⚠️ 临界（CPU 峰值余量 0.02pp = 1%） |
| 是否阻断 Release | ❌ 否（当前安全，且阈值有完整保护链） |
| 是否需建观测项 | ✅ **是（P3 观测项，Release 后持续跟踪）** |
| 是否需改阈值 | ❌ 否（2.0% 为生产既定阈值，工单明确"未变更"） |

## 3. 告警规则 ↔ 熔断保护 冲突矩阵

对每条可能影响 2.0% CPU 熔断阈值的告警规则，逐一校验是否会产生逻辑冲突：

| # | 告警规则 | 触发条件 | 与 2.0% 熔断的关系 | 冲突判定 |
|---|---|---|---|---|
| 1 | CPU WARN 告警 | CPU ≥ 1.5% | **先于熔断触发**（1.5% < 2.0%），告警预警后人工介入，可提前降级避开发热 | ✅ 无冲突（预警前置） |
| 2 | CPU CRITICAL 告警 | CPU ≥ 1.9% | 先于熔断 0.1pp 触发，触发降级 | ✅ 无冲突（预警前置） |
| 3 | CPU 熔断 | CPU ≥ 2.0% | 熔断保护动作本身 | ✅ 基准 |
| 4 | 因子 IC<0.50 告警 | IC 衰减 | 与 CPU 无耦合路径（不同计算链路） | ✅ 无冲突 |
| 5 | DQ<99.0% 告警 | 数据质量 | 与 CPU 无耦合路径 | ✅ 无冲突 |
| 6 | 索引膨胀 ≥8.5% 告警 | 存储膨胀 | 与 CPU 独立（当前实测 0.57%） | ✅ 无冲突 |
| 7 | 爬虫调度告警 | 爬虫失败 | 爬虫为每日低频 1 次，不会叠加 CPU | ✅ 无冲突 |

**冲突结论：7 条相关规则全部无冲突，告警链在熔断阈值之前形成预警缓冲层。**

## 4. 触发时序链路（CPU 路径）

```
CPU 上升
  │
  ├─ 1.65-1.78%（Phase34 常态区间）→ 无告警，正常运行
  │
  ├─ 1.90% → ⚠️ CPU CRITICAL 告警触发 → 推送通知 → 准备降级
  │
  ├─ 1.93%（Phase34 均值）→ 持续告警 → 持续监控
  │
  ├─ 1.98%（Phase34 峰值）→ 告警升级 → 自动降级动作执行
  │
  └─ 2.00% → 🔴 CPU 熔断触发 → 自动回滚（SLA 3.2min，3 次 dry-run PASS）
```

### 4.1 时序关键结论

| 项 | 值 | 判定 |
|---|---|---|
| 告警提前量（相对熔断） | ≥0.1pp（1.9% 告警 vs 2.0% 熔断） | ✅ 有缓冲 |
| 告警→熔断间窗口 | 0.1pp | ⚠️ 窄，需依赖自动降级 |
| 熔断后回滚 SLA | 3.2min（实测 3.0/3.1/3.3min） | ✅ 已验证 |
| 熔断误触发（720h） | 0 次 | ✅ 可靠 |
| 熔断漏触发（720h） | 0 次 | ✅ 可靠 |

## 6. T3 爬虫监控 ↔ 熔断保护 联动

| 项 | 值 | 判定 |

**结论：爬虫活动已被包含在实测 CPU 区间内，且采用低频+限流+退避策略，不会叠加推高 CPU 逼近熔断阈值。**
