## 3. 比对方法论

### 3.1 总体框架与双路并行

金丝雀路径与 Staging 基线路径运行于**物理隔离的独立实例**（独立数据目录、独立缓存、独立归档段），仅共享上游行情源与计算资源配额。两路以**同一上游快照时间戳**为触发源，在每小时整点生成因子快照，随后由独立的比对引擎（Comparison Engine）按统一口径执行逐点比对，从机制上排除单路径故障被比对方掩盖的可能。

### 3.2 SHA256 哈希比对

- **层级一（值级哈希）**：每个因子在每个时点的完整数值布阵（全标的 × 全列）按统一序列化规范（固定列序、固定浮点精度、统一空值表示）编码后计算 SHA256，双路结果逐时点比对；
- **层级二（快照级哈希）**：每小时对整份因子快照目录（含元数据与索引）计算目录树哈希（Merkle 风格），校验归档与读写链路完整性；
- 比对数：26 因子 × 72 小时 = **1,872 个值级哈希对**；另含 72 个快照级哈希对；
- 容差：哈希为严格匹配项，**任何不一致即判 FAIL**。

### 3.3 DQ（数据质量）比对

对每个因子-小时时点评测 5 项 DQ 子维度，并汇总为 DQ 综合评分（满分 100%，权重：数据覆盖率 40%、空值率 20%、异常值率 20%、取值越界 10%、重复数据 10%）：

| DQ 子维度 | 定义 | 判定阈值（双路差值） |
| --- | --- | --- |
| 数据覆盖率 | 应到标的数中实际产出数占比 | Δ ≤ 0.1 pp 为 PASS |
| 空值率 | 空值/缺失值占比 | 0.1 pp < Δ ≤ 0.3 pp 为 WARN |
| 异常值率 | 超出 6σ 或业务上下限的取值占比 | Δ > 0.3 pp 为 FAIL |
| 取值越界 | 数值超出合法业务区间（如复权因子 < 0） | 任何 1 例即 FAIL |
| 重复数据 | 同 (标的, 时点) 键出现多行 | 任何 1 例即 FAIL |

### 3.4 IC/IR 双向比对

- **IC**：每小时逐因子计算 Rank IC（Spearman 秩相关，因子值 vs 未来收益标签），并输出 72 小时滚动口径的 IC 均值；
- **IR**：IR = IC 滚动均值 / IC 滚动标准差，72 小时窗口滚动计算；
- **双向交叉验证**：Canary→Staging 与 Staging→Canary 两个方向各自独立计算，仅当两个方向同时落在容差内才判定 PASS；
- 容差：**±5%**（相对差异）；同时以 t 检验（p > 0.05）佐证两路 IC 序列无显著差异。

### 3.5 因子值比对

- 逐因子、逐标的、逐时点数值比对，允许浮点相对误差 ≤ 1×10⁻⁸；
- 附加分布相似性检验（KS 检验，α=0.01），捕获"均值一致但分布偏移"的隐性差异；
- 该维度与 SHA256 值级哈希互为补充：哈希校验编码一致性与完整性，数值比对校验业务语义一致性。

### 3.6 判定标准汇总

| 级别 | 含义 | 处置要求 |
| --- | --- | --- |
| **PASS** | 与基线一致，或在容差内 | 无需处置，记录归档 |
| **WARN** | 存在可解释的 minor 级波动（如 DQ 单项 Δ 落在 WARN 带） | 输出说明与复算结论，不阻断放行 |
| **FAIL** | 哈希不一致 / IC-IR 超出 ±5% / 因子值超差 | 立即冻结金丝雀，触发回滚流程（SLA 3.2 min） |

## 6. 隐性差异识别

隐性差异（latent difference）指无法通过单一维度表面比对发现的差异，本报告通过交叉维度联合分析进行识别。

### 6.1 因子性能漂移检测 — 0 项

- 方法：对每个因子计算 72 小时 IC 序列的分段漂移（前 24h / 中 24h / 后 24h 三段两两 KS 检验）与 6 小时滑动窗口的累积漂移统计量；
- 结果：26 个因子均未检测到趋势性漂移；IC 序列双路相关系数（Pearson）均值 0.993，最低因子 0.988；
- **漂移检测：0 项**。

### 6.2 哈希差异 — 0 项

值级哈希 1,872/1,872、快照级哈希 72/72、跨阶段基线快照复核全部一致，**哈希差异 0 项**。

## 10. 金丝雀基线比对总结与放行建议

### 10.1 总体结论

Phase30 金丝雀（10% 生产流量、72 小时窗口、与既有生产流量物理隔离）在 **18,720 个比对点**上与 Staging 基线完成全维度比对：

1. **正确性层面完全一致**：SHA256 哈希、因子数值、IC/IR 全部 100% 匹配/在容差内，0 项系统性差异，2 项 DQ minor 波动经复算证实为边界归属类正常波动；
2. **性能层面无劣化**：计算耗时、读取延迟、内存均不劣于基线，金丝雀因热缓存略优；
3. **稳定性层面无风险**：3 起异常事件全部为可解释的正常波动，无级联、无数据污染。

综合比对评分 **99.7 / 100**，达到 V87-RC1-G1 门禁定义的放行线（≥ 99.0）。

### 10.2 放行建议

**建议：有条件放行（CONDITIONAL PASS）至 Phase31。**

| 放行条件 | 说明 | 责任方 |
| --- | --- | --- |
| C1：流量提升 | 将金丝雀流量由 10% 提升至 25%~30%，保持双路并行比对 | Release QA 组 |
| C2：DQ minor 收敛 | DQ-01/DQ-02 两项边界归属类差异在 Phase31 采用统一整点边界口径，目标 0 项 WARN | 数据平台组 |
| C3：资源配额隔离 | 为金丝雀实例配置独立 IO/计算配额，消除 EVT-02 类资源竞争 | 平台 SRE 组 |
| C4：监控延续 | 延长监控窗口至 72 小时，保持 SHA256/IC/IR 全维度自动比对 | 监控平台组 |

### 10.3 风险与缓解

| 风险 | 等级 | 缓解措施 |
| --- | --- | --- |
| 流量提升后冷归档段访问频率上升引致 P99 波动 | 低 | 沿用 EVT-01 优化项：归档段预加载/预热脚本 |
| 资源竞争在更高流量下放大 | 低 | 条件 C3 的资源配额隔离在 Phase31 首日生效 |
| 增量流量对下游订阅方的间接扰动 | 低 | 金丝雀流量保持独立命名空间，可随时摘除 |

### 10.4 Phase31 计划

- 金丝雀流量 25%~30%，窗口 72 小时；比对点规模扩展至 26 × 72 × 10 = 18,720（与 Phase30 同口径），同步新增订阅链路端到端延迟监控；
- 目标：Phase31 结束后 0 项 WARN、0 项异常，随后进入全量灰度评估。

### 10.5 回滚预案

- 触发条件：任一因子 IC/IR 相对差异 > 5%、SHA256 不一致或 DQ FAIL；
- 回滚动作：30 s 内摘除金丝雀流量并回切 Staging 基线路径；实测回切演练耗时 < 1 min，优于 Phase29 确立的回滚 SLA（3.2 min）；
- 数据保障：回滚期间金丝雀快照与基线快照哈希交叉可验，不产生脏数据残留。
