## 1. 迁移概述

### 1.1 背景

V86 版本经过 27 个 Phase（Phase1-Phase27）的开发与验证，已发布并稳定运行。V86 操作手册（OPS Manual）v4.0.21 版本完整记录了从 Phase15 到 Phase27 期间的各项标准操作流程（SOP）。Phase27 新增 §42 章节「90天运维 SOP」，包含 11 个子章节，覆盖了从指标归档到 V87 需求集成的完整运维生命周期。

V87 RC1 Gate1 需要将所有 V86 的 SOP 迁移到新的 feature/v87-rc1-g1 分支上，并根据 V87 的功能变更进行适配和扩展。本 Phase01 工作流负责执行完整的 SOP 迁移检查与验证。

### 1.2 迁移范围

| 项目 | 数量/值 | 说明 |
|------|---------|------|
| **V86 版本总数** | 27 Phases | Phase1 至 Phase27 |
| **SOP 总数** | 25 | 含 §42 的 11 项 + 历史 SOP 14 项 |
| **直接复制** | 4 | 无需修改，原样复制到 V87 分支 |
| **直接复制 + V87 更新** | 6 | 复制后需增加 V87 相关参数/指标 |
| **适配改造** | 12 | 需要较大范围修改以适配 V87 架构 |
| **新建** | 3 | V87 全新引入的功能所需 SOP |
| **配置迁移** | 18 项配置文件 | 含环境参数、密钥、阈值等 |
| **文档更新** | 10 项文档 | 版本号、日期、引用更新 |

### 3.4 新建 SOP（New SOPs）— 3 SOPs

#### 3.4.1 事件处理 SOP（SOP-O-003）

**V87 新特性**: V87 引入了全新的事件驱动处理机制，支持实时事件流处理和异步事件协调。

| 维度 | 描述 |
|------|------|
| **核心功能** | 事件采集、路由、处理、分发全链路管理 |
| **事件源** | 应用日志事件、指标告警事件、业务触发事件、系统状态事件 |
| **处理引擎** | V87 事件总线（基于消息队列的发布/订阅模型） |
| **事件类型** | 5大类：系统事件、指标事件、业务事件、告警事件、运维事件 |
| **事件格式** | V87 统一事件信封（Event Envelope v1.0） |
| **延迟要求** | P99 < 500ms（事件发布到处理完成） |
| **吞吐要求** | 峰值 10,000 events/sec |
| **幂等保证** | 所有事件处理器必须实现幂等性 |
| **重试策略** | 指数退避，最多重试5次 |
| **死信队列** | 5次重试后进入死信队列，需人工介入 |
| **监控指标** | 事件吞吐量、处理延迟、失败率、死信数量 |
| **与现有SOP关联** | 与告警系统SOP（SOP-M-009）深度集成 |

#### 3.4.2 规则引擎 SOP（SOP-O-005）

**V87 新特性**: V87 新增可配置规则引擎，支持动态规则定义、评估与执行。

| 维度 | 描述 |
|------|------|
| **核心功能** | 规则定义、存储、评估、执行、版本管理 |
| **规则类型** | 告警规则、路由规则、抑制规则、聚合规则、转换规则 |
| **规则语言** | YAML DSL（V87 Rule DSL v1.0） |
| **规则数量上限** | 单实例 10,000 条 |
| **评估延迟** | 单条规则评估 < 10ms |
| **热加载** | 支持规则热加载（无需重启） |
| **规则测试** | 内置规则模拟器（dry-run模式） |
| **规则审计** | 所有规则变更留痕，支持版本回溯 |
| **权限控制** | 基于角色的规则管理权限（RBAC） |
| **与现有SOP关联** | 与告警系统SOP（SOP-M-009）、事件处理SOP（SOP-O-003）集成 |

#### 3.4.3 跨团队对齐 SOP（SOP-O-007）

**V87 新特性**: V87 RC1 涉及 DSHB/DSHE/HERMES 三方协同，需要建立标准化的跨团队对齐机制。

| 维度 | 描述 |
|------|------|
| **核心功能** | 三方对齐流程标准化、文档同步、冲突解决、决策追踪 |
| **对齐频率** | 每周2次（周一/周四 15:00） |
| **参与方** | DSHB（开发）、DSHE（架构）、HERMES（运维） |
| **对齐主题** | 架构决策、接口契约、SOP变更、问题升级 |
| **决策记录** | ADR（Architecture Decision Record）格式 |
| **冲突解决** | 三级升级机制（团队内→跨团队→管理层） |
| **同步工具** | 共享看板 + 文档仓库 + 即时通讯 |
| **验收标准** | 所有决策有书面记录，所有变更有签核 |
| **SLA要求** | 对齐文档 24h 内更新，决策记录 4h 内归档 |
| **与现有SOP关联** | 与所有SOP的跨团队依赖项关联 |
