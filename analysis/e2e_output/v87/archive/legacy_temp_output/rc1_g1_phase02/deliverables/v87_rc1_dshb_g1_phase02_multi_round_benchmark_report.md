### 1.1 测试目的

1. **验证 V87 功能加载后的性能**：Phase01 完成后 F01（新事件管道）、F02（新索引逻辑）、F03（规则引擎迭代）、F05（内存优化）等特性已加载，需重新评估。
2. **多轮次稳定性验证**：单轮数据容易掩盖退化趋势，通过 3 轮负载递增（50% → 100% → 120%）观察性能退化曲线。
3. **V87 目标达成度量化**：以 V87 目标（吞吐 ≥15000、WAL<3ms、索引<7ms、丢包<0.005%、内存<40%、P99<250ms、缓存>90%）为锚点，逐项打分。
4. **纵向对比锚点**：为 Gate2 决策提供 V86 → Phase01 → Phase02 三段式基线。
5. **Phase03 就绪度评估**：识别 Phase03 必须解决的性能缺口。

基于 V86 Phase27 中位生产负载，按 V87 目标调整：

### 2.6 指标定义

| 指标 | 单位 | 定义 |
|------|:---:|------|
| 吞吐量 | ev/s | 每秒处理事件数（含读/写/查询/管理） |
| Per-Worker 吞吐 | ev/s | 总吞吐 / 16 workers |
| P50 / P95 / P99 | ms | 延迟分位数（T-Digest 算法，δ=0.01） |
| WAL 延迟 | ms | WAL 刷盘延迟均值（含 P50/P95/P99） |
| 索引延迟 | ms | 索引操作延迟均值（含插入 + 查询） |
| 丢包率 | % | 端到端丢包率（请求发出 → 响应返回） |
| 内存使用率 | % | 进程 RSS / 总物理内存 × 100% |
| 缓存命中率 | % | 缓存命中次数 / 总查询次数 × 100% |
| CoV | % | 变异系数 = 标准差 / 均值 × 100% |
| Jitter | ms | P99 - P50（尾部扩散宽度） |

## 附录 B: 指标定义与计算公式

| 指标 | 公式 | 采样方法 |
|------|------|------|
| 吞吐量 | Σ(采样事件数) / Σ(采样时长) | Metrics-Collector, 60s |
| Per-Worker 吞吐 | 总吞吐 / 16 | 计算 |
| P50 / P95 / P99 | T-Digest 算法, δ=0.01 | Latency-Probe, 60s |
| WAL 延迟均值 | Σ(每次刷盘耗时) / 刷盘次数 | WAL-Monitor, 30s |
| WAL P99 | T-Digest 算法, δ=0.01 | WAL-Monitor, 30s |
| 索引延迟均值 | Σ(索引操作耗时) / 操作次数 | Index-Analyzer, 60s |
| 索引膨胀率 | (当前索引大小 - 初始索引大小) / 初始索引大小 × 100% | Index-Analyzer, 600s |
| 内存使用率 | 进程 RSS / 总物理内存 × 100% | Mem-Watcher, 30s |
| 缓存命中率 | 命中次数 / 总查询次数 × 100% | Cache-Probe, 30s |
| 冷缓存命中率 | 冷数据命中次数 / 冷数据查询次数 × 100% | Cache-Probe, 30s |
| 丢包率 | (请求发出数 - 响应返回数) / 请求发出数 × 100% | Packet-Loss-Probe, 10s |
| CoV | 标准差 / 均值 × 100% | 计算（基于 60s 样本） |
| Jitter | P99 - P50 | 计算 |
| 性能余量 | (容量上限 - 实际负载) / 容量上限 × 100% | 计算 |
| 边际收益 | Δ吞吐 / Δ负载 × 100% | 计算（跨轮次） |
