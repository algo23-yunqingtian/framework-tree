## 5. 索引优化方案

### 5.1 优化目标

| 维度 | 值 |
|------|----|
| **优化维度** | 维度1: 索引优化 |
| **目标改善** | -3.5ms (P99) |
| **当前P99** | 259.4ms |
| **优化后P99** | 255.9ms |
| **风险等级** | 🟢 低 (离线操作，无服务影响) |
| **实施阶段** | Phase A (设计) + Phase B (实现) |

### 5.2 优化方法

| # | 方法 | 描述 | 预计改善 | 优先级 | 复杂度 |
|:-:|------|------|:--------:|:------:|:------:|
| 1 | 索引剪枝 (Index Pruning) | 移除超过30天的过期索引段 | -1.2ms | P0 | 低 |
| 2 | 段合并 (Segment Merging) | 合并碎片化段，减少段数量40% | -1.0ms | P0 | 中 |
| 3 | 索引压缩调度 (Compaction Schedule) | 每周自动压缩低热度索引段 | -0.8ms | P1 | 低 |
| 4 | 冷索引归档 (Cold Index Archive) | 将归档数据移至独立索引存储 | -0.5ms | P1 | 中 |

### 5.3 索引剪枝详细设计

| 设计项 | 说明 |
|--------|------|
| **原理** | 索引按时间分段存储，超过30天的段不再需要高频查询 |
| **触发条件** | 段年龄 > 30天 |
| **操作模式** | 离线 (维护窗口执行) |
| **影响** | 减少索引查找范围30%+ |
| **数据一致性** | 不删除原始数据，仅删除过期索引引用 |
| **回滚机制** | 保留索引备份，可快速恢复 |
| **预计节省** | 索引大小减少15%，查找范围减少30%+ |

### 5.4 段合并详细设计

| 设计项 | 说明 |
|--------|------|
| **原理** | 小段合并为大段，减少段数量和段间切换开销 |
| **合并阈值** | 段大小 < 50MB 且相邻段时间间隔 < 24h |
| **目标** | 段数量减少40% |
| **操作模式** | 离线 (维护窗口) + 在线 (增量合并) |
| **预计改善** | 段切换延迟减少40%，查询延迟降低1.0ms |
| **风险** | 离线合并无风险；在线合并需控制合并频率 |

## 6. 查询优化方案

### 6.1 优化目标

| 维度 | 值 |
|------|----|
| **优化维度** | 维度2: 查询优化 |
| **目标改善** | -2.8ms (P99) |
| **当前P99** | 255.9ms (索引优化后) |
| **优化后P99** | 253.1ms |
| **风险等级** | 🟡 低-中 (查询缓存可能影响一致性，TTL缓解) |
| **实施阶段** | Phase A (设计) + Phase B (实现) |

### 6.2 优化方法

| # | 方法 | 描述 | 预计改善 | 优先级 | 复杂度 |
|:-:|------|------|:--------:|:------:|:------:|
| 1 | 查询计划缓存 (Query Plan Caching) | 缓存常见查询计划，目标命中率85% | -1.2ms | P0 | 中 |
| 2 | 索引选择优化 (Index Selection) | 智能索引选择算法，减少全表扫描 | -0.6ms | P0 | 中 |
| 3 | 查询并行化 (Query Parallelization) | 复杂查询并行执行 | -0.5ms | P1 | 高 |
| 4 | 结果集缓存 (Result Set Caching) | 缓存高频查询结果集 | -0.5ms | P1 | 低 |

### 6.3 查询计划缓存详细设计

| 设计项 | 说明 |
|--------|------|
| **原理** | 对常见查询模式缓存优化后的执行计划，避免重复编译 |
| **缓存策略** | LRU缓存，容量10,000条查询计划 |
| **命中率目标** | ≥85% (当前基线: 查询编译占比约15%) |
| **TTL** | 30分钟 (动态调整) |
| **失效策略** | TTL过期 + 查询模式变化触发 |
| **一致性保证** | 基于查询模式哈希匹配，非语义分析 |
| **预计改善** | 查询编译时间减少1.2ms，查询延迟降低-1.2ms |

### 6.4 索引选择优化详细设计

| 设计项 | 说明 |
|--------|------|
| **原理** | 基于查询条件选择最优索引，减少不必要的全表扫描 |
| **算法** | 成本估算 + 选择性评估 + 索引统计信息 |
| **统计更新** | 每小时更新索引统计信息 |
| **预计改善** | 减少全表扫描30%，延迟降低-0.6ms |
| **风险** | 统计信息延迟可能导致次优选择 (风险低) |

## 7. 缓存优化方案

### 7.1 优化目标

| 维度 | 值 |
|------|----|
| **优化维度** | 维度3: 缓存优化 |
| **目标改善** | -1.8ms (P99) |
| **当前P99** | 253.1ms (查询优化后) |
| **优化后P99** | 251.3ms |
| **风险等级** | 🟢 低 (仅配置变更) |
| **实施阶段** | Phase B (实现) + Phase C (基准测试) |

### 7.2 优化方法

| # | 方法 | 描述 | 预计改善 | 优先级 | 复杂度 |
|:-:|------|------|:--------:|:------:|:------:|
| 1 | 缓存预热 (Cache Warming) | 启动时预加载热数据 | -0.5ms | P0 | 低 |
| 2 | TTL动态调整 (TTL Tuning) | 基于访问频率动态调整TTL | -0.4ms | P1 | 中 |
| 3 | 驱逐策略优化 (Eviction Policy) | LRU→LFU混合策略 | -0.5ms | P0 | 中 |
| 4 | 缓存分区 (Cache Partitioning) | 分离热/温/冷分区 | -0.4ms | P1 | 中 |

### 7.3 缓存预热详细设计

| 设计项 | 说明 |
|--------|------|
| **原理** | 服务启动时预加载最近7天的热数据到缓存 |
| **预热数据量** | 预估500-800个热数据条目 |
| **预热时间** | 启动后2-3分钟 (异步执行) |
| **预热策略** | 按访问频率排序，优先加载Top 1000条目 |
| **内存影响** | 预热后内存使用率从38%→41.5% (+3.5%) |
| **延迟影响** | 预热后首次查询延迟降低约0.5ms |
| **风险** | 低 (异步预热，不影响启动流程) |

### 7.4 驱逐策略优化详细设计

| 设计项 | 说明 |
|--------|------|
| **当前策略** | LRU (最近最少使用) |
| **新策略** | LFU-LRU混合 (最不经常使用 + 最近最少使用) |

### 8.3 G1GC暂停时间优化详细设计

| 设计项 | 说明 |
|--------|------|
| **当前GC** | G1GC, 暂停时间P99 28.2ms |
| **目标GC** | G1GC调优, 暂停时间P99 <20ms |
| **关键参数** | `-XX:MaxGCPauseMillis=20` |
| **Region Size** | 调整 `-XX:G1HeapRegionSize` 适配负载 |
| **Mixed GC阈值** | `-XX:G1MixedGCLiveThresholdPercent=85` |
| **并发标记** | 启用 `-XX:ConcGCThreads=8` |
| **原理** | 降低GC暂停目标，增大并发标记线程数，优化Region大小 |
| **预计改善** | GC P99从28.2ms→<20ms (-29%) |
| **风险** | 降低暂停目标可能增加GC频率，需监控吞吐量 |
