## 5. hash缓存优化机制验证

### 5.1 缓存架构

| 维度 | 配置 |
|------|------|
| 缓存类型 | LRU + TTL + Hash |
| Hash缓存容量 | 256MB |
| LRU容量 | 10,000条 |
| 缓存键 | trace_id + batch_id → SHA256 |
| TTL | 7天 |
| 淘汰策略 | LRU热度淘汰 |

### 5.2 缓存命中率提升分析

| 缓存层 | Phase06(72h) | Phase07(30天) | 变化 | 理由 |
|--------|:-----------:|:-------------:|:----:|------|
| 总缓存命中率 | 85% | 92.3% | +8.3pp | 30天数据更多→缓存预热更充分 |
| hash缓存命中率 | — | 94.5% | — | trace_id+batch_id重复率高 |
| SHA256计算减少 | -12.9% | -15.2% | -2.3pp | 命中率提升→计算量减少 |
| trace_id缓存 | -87.5% | -88.0% | -0.5pp | 稳定 |
| batch_id缓存 | -87.5% | -88.0% | -0.5pp | 稳定 |

命中率从85%提升至92.3%的原因：30天运行期间LRU缓存预热更充分，相同trace_id/batch_id的重复事件更多被缓存命中，减少SHA256重复计算。
