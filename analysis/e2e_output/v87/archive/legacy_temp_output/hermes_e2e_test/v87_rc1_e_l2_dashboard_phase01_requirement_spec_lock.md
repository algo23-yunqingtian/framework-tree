## 2. V86 Phase27复盘发现的监控需求

### 2.1 复盘背景

V86 Phase27 是 V86 版本的最后一个迭代阶段，主要交付内容包括：容量预测功能上线、内存趋势长视图、Vacuum 事件标记层、故障演练时间线四项面板新增。Phase27 验收过程中暴露出 V87 阶段需要补齐的监控能力缺口。

### 2.2 复盘报告关键发现

Phase27 复盘报告编号 `V86-PT27-RETRO-001`，共识别出以下五类能力缺口：

1. **异常检测手段单一**：当前所有告警规则均基于静态阈值，无法捕捉趋势型异常、季节性波动与突发脉冲
2. **跨服务调用不可视**：L1/L2/L3 之间的调用链、依赖关系、数据流向均缺乏可视化能力
3. **容量规划依赖人工**：当前容量规划完全依赖 SRE 人工评估，无自动化趋势预测支撑
4. **告警关联缺失**：高负载场景下告警频繁触发，但告警之间缺乏关联分析，根因定位困难
5. **故障演练手工化**：混沌工程演练场景的编排、执行、评估均依赖人工操作，效率低下且不可重复

### 2.3 V87 监控需求清单 (Phase27 来源)

#### V87-MON-REQ-001: AI驱动异常检测

| 属性 | 值 |
|------|-----|
| 需求ID | V87-MON-REQ-001 |
| 名称 | AI驱动异常检测 |
| 优先级 | P1 |
| 来源 | V86 Phase27 复盘 |
| 关联面板 | V87-P-001 |
| 预计工作量 | 8-12 周 |
| 责任方 | DSHE L2 (主) + HERMES L3 (协) |
| 依赖 | HERMES L3 模型推理服务 |

**需求描述**:

在现有静态阈值告警体系之上，叠加 AI 驱动的异常检测层。该能力由 HERMES L3 提供异常检测模型推理服务，DSHE L2 负责面板可视化与告警联动。异常检测模型基于历史时序数据，支持以下检测模式：

- **趋势异常检测**: 识别指标偏离历史趋势的行为，适应季节性、周期性与非平稳时序
- **突变检测**: 识别指标的突发性异常变化，对脉冲、跳变、阶跃等突变模式敏感
- **关联异常检测**: 基于多指标相关性建模，识别违反指标间正常关联关系的异常组合
- **自适应阈值**: 根据历史数据动态计算告警阈值，替代静态配置阈值

**技术规格**:

| 参数 | 规格 |
|------|------|
| 检测模型 | LSTM-Transformer 混合架构 |
| 训练窗口 | 30天历史数据 |
| 推理频率 | 每 30 秒一次 |
| 检测延迟 | ≤ 100ms (P99) |
| 模型置信度阈值 | ≥ 0.85 |
| 支持指标类型 | 时序数值型 / 分类型 / 布尔型 |
| 最小训练数据量 | 7 天连续采集 |
| 冷启动策略 | 前 7 天降级为静态阈值，数据充足后自动切换 |

**验收标准**:

1. 面板展示模型置信度、异常评分与异常窗口时间范围
2. 支持按时间窗口回溯查看历史异常事件
3. AI 异常检测告警自动关联 IE-AL-001 三级预警 (E/W/C)
4. 冷启动期降级行为可观测，日志完整
5. 模型推理性能不影响 L2 主流程，P99 延迟 ≤ 100ms

| 属性 | 值 |

构建跨服务依赖拓扑可视化能力，覆盖 DSHB (L1) → DSHE (L2) → HERMES (L3) 的完整服务调用链。支持以下可视化模式：

- **依赖拓扑图**: 以图拓扑形式展示服务间调用关系，节点为服务实例，边为调用路径
- **调用链追踪**: 支持 traceId 关联的分布式追踪，展示单次请求的完整调用路径与耗时分解

- **故障传播路径**: 标注故障服务节点，自动计算并高亮故障影响传播路径

**技术规格**:

| 参数 | 规格 |

| 拓扑节点类型 | 服务实例 / 数据库 / 缓存 / 消息队列 / 外部API |
| 拓扑刷新频率 | 每 60 秒增量刷新 |
| 拓扑节点上限 | 500 节点 |
| 调用链采样率 | 10% (可调 1%-100%) |
| 追踪数据保留 | 7 天 |
| 依赖深度统计窗口 | 实时 / 5分钟 / 1小时 / 24小时 |

**验收标准**:

1. 拓扑图渲染时间 ≤ 2秒 (500 节点以内)
2. 支持节点缩放、拖拽、固定、展开、折叠操作
3. 调用链支持按服务名、耗时、状态码过滤
4. 依赖深度异常 (>3 层) 自动告警
5. 拓扑数据支持导出为 Mermaid / PlantUML 格式

#### V87-MON-REQ-003: 自动化容量规划

| 属性 | 值 |
|------|-----|
| 需求ID | V87-MON-REQ-003 |
| 名称 | 自动化容量规划 |
| 优先级 | P1 |
| 来源 | V86 Phase27 复盘 |
| 关联面板 | V87-P-003 |
| 预计工作量 | 4-8 周 |
| 责任方 | DSHE L2 (主) + HERMES L3 (协) |
| 依赖 | HERMES L3 趋势预测模型 |

**需求描述**:

基于 HERMES L3 提供的趋势预测模型，实现自动化容量规划能力。系统基于历史负载数据，预测未来负载趋势，输出容量建议与扩容/缩容窗口，并在容量不足时触发提前告警。

**功能范围**:

1. **负载趋势预测**: 基于 7/14/30 天历史数据，预测未来 1/7/30 天负载趋势
2. **容量建议引擎**: 根据预测趋势，计算推荐容量配置 (CPU/内存/磁盘/网络带宽)
3. **扩容/缩容窗口推荐**: 识别最佳扩容/缩容时间窗口，避开业务高峰期
4. **容量预测准确度追踪**: 记录预测值与实际值的偏差，持续优化预测模型
5. **容量预测告警**: 当预测容量不足时，提前 N 天 (可配置，默认 3 天) 触发告警

**技术规格**:

| 参数 | 规格 |
|------|------|
| 预测算法 | Prophet + LSTM 混合 |
| 预测时间粒度 | 15分钟 |
| 预测时间范围 | 1天/7天/30天 |
| 容量评估维度 | CPU / 内存 / 磁盘 / 网络带宽 / 连接数 |
| 告警提前量 | 可配置 (1-7天)，默认 3 天 |
| 预测准确度 | MAPE ≤ 15% |

**验收标准**:

1. 面板展示趋势预测曲线、预测区间 (置信区间 95%)、容量建议
2. 容量预测准确度 MAPE ≤ 15% (连续 7 天滚动评估)
3. 容量预测告警与 CP-AL-005 告警规则联动
4. 容量建议支持一键导出为运维工单格式
5. 支持按服务/实例粒度查看容量预测

#### V87-MON-REQ-004: 告警关联AI

| 属性 | 值 |
|------|-----|
| 需求ID | V87-MON-REQ-004 |
| 名称 | 告警关联AI |
| 优先级 | P1 |
| 来源 | V86 Phase27 复盘 |
| 关联面板 | V87-P-004 |
| 预计工作量 | 4-6 周 |
| 责任方 | DSHE L2 (主) + HERMES L3 (协) |
| 依赖 | HERMES L3 告警关联模型 |

**需求描述**:

在高负载场景下，多个告警规则同时触发的概率显著增加。当前告警之间缺乏关联分析，导致告警疲劳与根因定位困难。本需求引入 AI 驱动的告警关联分析与根因推荐能力。

**功能范围**:

1. **告警关联聚类**: 基于时间相关性、指标相关性与拓扑依赖关系，将关联告警自动聚类
2. **告警抑制**: 当根因告警触发时，自动抑制其引发的下游告警，减少告警噪音
3. **根因推荐**: 基于关联分析结果，推荐最可能的根因告警
4. **告警时间线**: 展示关联告警的完整时间线，包含触发顺序、持续时间、恢复状态
5. **关联度评分**: 对关联告警对计算关联度评分 (0-1)，评分 ≥ 0.8 自动归入同一事件

**技术规格**:

| 参数 | 规格 |
|------|------|
| 关联聚类窗口 | 5分钟 (可配置 1-30分钟) |
| 关联度阈值 | ≥ 0.8 |
| 告警抑制延迟 | ≤ 5 秒 |
| 根因推荐准确度 | ≥ 80% (基线) |
| 最大关联告警数/事件 | 20 |
| 关联模型更新频率 | 每小时增量更新 |

**验收标准**:

1. 面板展示告警关联事件时间线，包含触发顺序、根因推荐、抑制状态
2. 告警抑制延迟 ≤ 5 秒 (P99)
3. 关联度评分计算延迟 ≤ 2 秒 (P99)
4. 根因推荐准确率达到 ≥ 80% (基于标注集)
5. 关联告警事件支持导出与分享

## 3. DSHB V87新增业务特性需求

### 3.1 DSHB V87 业务特性总览

DSHB (L1 业务层) 在 V87 阶段新增以下业务特性，直接影响 L2 监控面板与指标的扩展需求：

| 特性ID | 特性名称 | 优先级 | 对L2监控的影响 |
|--------|---------|--------|--------------|
| DSHB-V87-F01 | 高吞吐事件处理引擎 | P0 | 吞吐指标阈值从800提升至900 ev/s |
| DSHB-V87-F02 | WAL增强型存储 | P0 | WAL延迟阈值从4ms收紧至3ms |
| DSHB-V87-F03 | 索引优化引擎 | P0 | 索引延迟阈值从8ms收紧至7ms |
| DSHB-V87-F04 | 数据包完整性校验 | P1 | 丢包率阈值从0.01%收紧至0.005% |
| DSHB-V87-F05 | 全链路追踪SDK | P1 | 新增全链路追踪面板需求 |

### 3.2 DSHB-V87-F01: 高吞吐事件处理引擎

**业务描述**: DSHB V87 引入基于无锁并发架构的事件处理引擎，目标吞吐量从 800 ev/s 提升至 900 ev/s，提升幅度 +12.5%。

**对 L2 监控的影响**:

| 影响项 | 说明 |
|--------|------|
| 吞吐指标阈值 | 从 ≥800 ev/s 提升至 ≥900 ev/s |
| 面板展示 | 新增吞吐实时速率图，支持 1s/5s/1min/1h/24h 时间窗口 |
| 告警规则 | G-AL-001 相关吞吐告警阈值需同步调整 |
| 容量规划 | 吞吐容量预测需纳入新引擎基准 |

**监控需求**:

1. 新增吞吐实时速率面板区域，展示当前 ev/s、峰值 ev/s、均值 ev/s
2. 新增吞吐分布直方图，展示不同时间窗口下的吞吐分布
3. 新增吞吐趋势预测区域 (与 V87-MON-REQ-003 联动)

#### 7.2.3 IE-AL-001 三级预警升级: 新增AI检测层

V87 阶段 IE-AL-001 (索引膨胀三级预警) 升级为三级预警 + AI 检测层双轨并行：

| 层级 | 名称 | V86 阈值 | V87 阈值 | V87 AI检测层 |
|------|------|---------|---------|-------------|
| E级 | Emergency | > 15% | > 12% | 模型置信度 ≥ 0.9 |
| W级 | Warning | > 10% | > 10% | 模型置信度 ≥ 0.85 |
| C级 | Critical | > 8% | > 8% | 模型置信度 ≥ 0.8 |

**AI 检测层行为**:

1. 当 AI 异常检测模型识别到索引膨胀异常趋势时，即使当前阈值未触发，也提前生成预警
2. AI 检测层输出结果与静态阈值取并集，任一触发即告警
3. AI 检测层支持异常趋势预测，可提前 N 小时 (可配置) 预警
4. AI 检测层与 V87-P-001 (AI异常检测面板) 联动

**告警升级规则**:

### 7.5 告警抑制与关联规则

1. **告警抑制**: 当根因告警触发时，自动抑制其下游衍生告警
