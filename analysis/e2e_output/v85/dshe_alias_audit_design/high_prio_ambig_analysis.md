## 1. 「高优先级歧义」的三个总体

本分析覆盖别名库歧义的三个不同总体，它们**不可混用**：

| 总体 | 规模 | 来源 | 风险性质 |
|---|---|---|---|
| **A. 歧义别名全集** | 448 行 | `alias_lib_full_audit/ambiguous_indicator_list.csv` | 别名映射可能错误（品种混淆 / 语义不匹配） |
| **B. 多 canonical 冲突** | 165 条 | `multi_canonical_conflicts_165.csv` | 别名指向多个 canonical key，**选择哪一个**会改变裁决 |
| **C. 高危混淆对** | 409 对（402 跨品种） | `alias_lib_full_audit/high_risk_confusion_pairs.csv` | 两个不同指标在匹配期可能互换 |

本文档的分析对象是 **总体 B**。总体 A 与 C 的结论已分别由 T2.1（`alias_sampling_audit_report.md`）与上游审计承担，本文档仅在 §4 做交叉校验。

**关键区别**：总体 A 的错误是**别名指向了错的指标**（静态缺陷，修别名库即可）；总体 B 的错误是**别名同时指向多个对指标**（动态缺陷，取决于引擎在运行时如何裁决）——后者只有在引擎侧才能暴露，因此总体 B 的处置必须与 V86 引擎设计联动。

## 3. 高优先级重排（P0 / P1 / P2）

### 3.1 分级规则

| 级别 | 判定条件 | 条数 | 风险性质 |
|---|---|---|---|
| **P0-跨品种** | B 类 且 `variety_family` 含 `\|` | **6** | 别名同时指向两个品种族；引擎任意选择 → 匹配在品种间静默翻转 |
| **P0-窄口径双候选** | B 类 且 `n_unique_base ≤ 2` 且度量词已识别 | **47** | 恰好两个候选且语义可辨，引擎必须确定性择优 |
| **P1-宽口径或多候选** | B 类 且（`n_unique_base ≥ 3` 或度量词未识别） | **65** | 候选多或语义模糊，人工裁决成本高 |
| **P2-机械合并** | A 类（唯一 base + 仅尾缀差异） | **47** | 无歧义，可脚本合并 |
| **合计** | | **165** | |

### 3.2 P0-跨品种：6 条全量明细（唯一「静默错指标」高危点）

| # | 别名 | 品种族 | `n_unique_base` | 度量词 | 冲突子类 |
|---|---|---|---|---|---|
| 1 | `氧化铝:净进口数量:中国(月)` | `AL\|AO` | 2 | 未识别 | 不同序号不同度量词 |
| 2 | `氧化铝:库存:中国(周)` | `AL\|AO` | 2 | 库存 | 不同序号不同度量词 |
| 3 | `氧化铝:港口库存:中国(周)` | `AL\|AO` | 2 | 库存 | 不同序号不同度量词 |
| 4 | `铝土矿:进口:港口库存:中国(周)` | `AL\|AO` | 2 | 库存 | 不同序号不同度量词 |
| 5 | `精炼镍:生产利润:中国:外采:硫酸镍加工工艺(日)` | `ENTITY\|NI` | 2 | 利润 | 不同序号不同度量词 |
| 6 | `镀锌板卷:库存:中国(周)` | `ENTITY\|ZN` | 4 | 库存 | 不同序号不同度量词 |

**根因**：`variety_family` 由 `variety_of_any` 双形态识别（中文品种词 + `AL/NI/...` 代码），对**产业链关联实体**（氧化铝 ↔ 铝、硫酸镍 ↔ 镍、镀锌板 ↔ 锌）产生双标签。这不是别名错误，而是**族标签口径过宽**——族标签被下游当作「品种锚点」使用，双标签会污染 R-01 品种锚点门禁。

**处置建议**：不删任何 canonical，改为在族标签层引入「主族 / 关联族」两级区分；R-01 品种锚点只使用主族。

### 3.3 P0-窄口径双候选：47 条的度量词分布

| 度量词 | 条数 | 说明 |
|---|---|---|
| 产量 | 12 | 不同序号的产量指标（`_2`/`_i` 尾缀） |
| 持仓量 \| 持仓 | 6 | 期货持仓，跨交易所或跨合约月份 |
| 成本 | 5 | 成本口径（完全成本 / 现金成本 / 加工成本） |
| 库存 | 3 | 库存口径（社库 / 厂库 / 仓单） |
| 利润 | 3 | 利润口径 |
| 价格 | 3 | 价格口径 |
| 其他 | 15 | 开工率、盈亏、升贴水等 |

**品种分布**：LI 12 / NI 10 / SN 8 / SI 6 / AL 3 / ZN 3。

**共同形态**：47 条全部是「同一度量词在不同序号下的两个实例」，如 `si_21_openinterest` vs `si_21_openinterest_2`。别名层看不出差异，**只有指标注册表的口径说明才能区分**——因此这 47 条**无法在别名库内解决**，必须读 `indicators_v1.json` 的指标定义（只读）后人工择优。

### 3.4 P1：65 条的两类成因

| 成因 | 条数 | 处置 |
|---|---|---|
| 度量词未识别 | 28 | 先跑 `metric_nouns` 的口径扩展（同义词表补全），可自动收敛一批 |
| `n_unique_base ≥ 3` 但度量词已识别 | 37 | 按度量词分桶后人工择优 |

28 条「度量词未识别」是本分析新发现的**口径缺陷 C-03**（新增，详见 §5）：`metric_nouns` 的正则表缺少 28 条别名使用的度量词表述，导致这批本可自动分诊的冲突被推入 P1。

## 5. 口径缺陷（本分析新增）

### C-03 `metric_nouns` 正则表覆盖不足

28 / 165 = **17.0 %** 的多 canonical 冲突因度量词未识别而无法自动分诊。已知缺失表述包括产业链实体词（`氧化铝`、`硫酸镍`、`镀锌板`）与口径修饰词（`完全成本`、`现金成本`、`开工率`的多种写法）。

**影响**：这批冲突只能进入 P1 人工队列，抬升人工成本。
**建议**：在 V86 引擎中把 `metric_nouns` 从正则表升级为**可热更新的分词字典**，并把缺失词表作为独立交付物（便于增量维护）。

### C-04 `variety_family` 双标签无主从之分

6 条跨品种族冲突（§3.2）的根因是族标签把**产业链关联实体**与品种本体并列。下游 R-01 品种锚点门禁直接消费族标签，双标签会导致锚点误判。

**影响**：6 条 P0 冲突无法通过「择优合并」解决——两个 canonical 都是对的，错的是族标签口径。
**建议**：引入「主族 / 关联族」两级标签；R-01 只用主族，R-07 别名门禁可同时参考两者。

## 7. 与 V86 引擎设计的联动

165 条冲突的运行时表现取决于三个引擎修复（详见 `v86_alias_engine_full_design.md`）：

| 修复 | 作用 | 覆盖 |
|---|---|---|
| **F1** `guard_resolve_canonical` | 未命中返回 `[]` 而非 `KeyError` | 消除 2977 / 9714 次崩溃 |
| **F2** `resolve_canonical_safe` | 多 canonical 取交集并排序，消除顺序敏感 | **直接决定 165 条冲突的裁决稳定性** |
| **F3** 门禁重排 + 全量上报 | R-05 前移于 R-07，`all_rules` 全量上报 | 使冲突裁决**可归因** |

**关键结论**：F2 只能保证「同一个输入永远返回同一个结果」，**不能保证「返回的那个 canonical 是对的」**。因此 53 条 P0 的人工择优是 F2 的**必要前置**——F2 会把人工裁决结果固化下来，若裁决本身是错的，F2 会把错误固化得更彻底。

**上线顺序约束**：
```
人工择优 53 条 P0  →  F2 部署  →  F1 部署  →  F3+F4 同批  →  冻结回归门禁
```
F2 不能先于 P0 裁决上线。
