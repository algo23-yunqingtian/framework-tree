## 1. 架构总览

### 1.1 端到端流水线

```
原始字符串 a_raw / b_raw
        │
        ▼
┌─────────────────────────┐
│ P0 归一化 norm_full     │  小写化 / 标点统一 / 全半角 / 空白收敛
└─────────────────────────┘
        │  a, b  (norm_full 后的可比形态)
        ▼
┌─────────────────────────┐
│ P1 特征提取             │  primary_metric / metal_families / metric_conflict
└─────────────────────────┘
        │
        ▼
┌─────────────────────────┐
│ P2 规范解析             │  resolve_canonical_safe(a) / (b)   ← F1 + F2
│   别名库 4821 归一名    │  未命中 → []  (不再 KeyError)
│   → canonical 集合      │  多命中 → 排序取交集 (确定性与顺序无关)
└─────────────────────────┘
        │  ca, cb
        ▼
┌─────────────────────────┐
│ P3 门禁裁决链（L0→L3） │  见 §3
└─────────────────────────┘
        │
        ▼
┌─────────────────────────┐
│ P4 裁决契约             │  {verdict, reason, all_rules, incomplete, dice}
└─────────────────────────┘
```

### 1.2 数据依赖（全部只读）

| 依赖 | 规模 | 用途 | 阶段 |
|---|---|---|---|
| 别名库 | 4643 行 / 4821 归一名 | 别名 → canonical 映射 | P2 |
| `indicators_v1.json` | 指标注册表 | 指标口径说明（歧义择优依据） | 离线 |
| 黑名单 | 31 条规则（P0 13 / P1 13 / P2 5） | L1 安全门禁 | P3 |
| `metric_nouns` 词典 | 度量词识别 | P1 特征提取 | P1 |
| `metal_families` 词典 | 品种族识别 | P1 特征提取 | P1 |

### 1.3 设计目标与非目标

**目标**：
1. 裁决链**可归因** —— 每次 BLOCK 都必须能指认到具体规则与具体命中片段
2. 裁决链**可复现** —— 同一输入永远得到同一结果（F2）
3. 裁决链**可回归** —— 14 道门禁全部机器可判定
4. 安全门禁**不可被遮蔽** —— INV-1 / INV-3

**非目标**（明确排除）：
- 不提高召回率 —— 现有引擎 Recall 已 100.00 %，提升 Precision 是精度问题而非召回问题
- 不重写黑名单规则语义 —— 规则集仅静态评估，规则改写归 V86 后续工单
- 不解决别名库数据缺陷 —— 165 条歧义择优归离线人工队列，引擎只做确定性裁决
- 不调用任何外部 API —— 全程静态文本分析

## 2. 四层门禁模型

### 2.1 分层定义

| 层 | 名称 | 成员 | 唯一权限 | 短路语义 |
|---|---|---|---|---|
| **L0** | 输入校验 | `empty_input`、编码异常、超长 | 拒绝 | 短路（前置无效） |
| **L1** | **安全门禁** | R-01 品种锚点、R-03-HARD 度量词硬冲突、**R-05 黑名单** | **只阻断，不裁决** | 短路，但必须**收集全部命中** |
| **L2** | **裁决门禁** | **R-07 别名** | **唯一的「放行」权限** | 仅当 L1 全部通过才可执行 |
| **L3** | 兜底裁决 | R-01b 品种中性、R-03-SOFT 软冲突、R-06 dice 阈值 | 放行 / 降级复核 / 拦截 | 顺序执行，取最不宽容结果 |

### 2.2 三条不变式

| ID | 不变式 | 违反后果 | 回归门禁 |
|---|---|---|---|
| **INV-1** | 任一 L1 门禁命中 ⇒ 裁决必为 `BLOCK` 或 `REVIEW`，**永远不能是 `PASS`** | `BOUNDARY-013` 类漏拦截 | G7（本语料不可判定） |
| **INV-2** | R-07 是唯一拥有 `PASS` 主动放行权的门禁；L3 的 `PASS` 必须带 `dice` 依据 | 静默放行，无法审计 | G8 |
| **INV-3** | 任一 L1 门禁被短路未执行 ⇒ 裁决必须标记 `incomplete=true` 且不允许 `PASS` | 不可观测的漏检 | G6 + G7 |

### 2.3 目标顺序（V86）

```
1. empty_input                     -> 拒绝                (L0)
2. variety_anchor_violation (R-01) -> 阻断                (L1)
3. metric_exclusion_hard (R-03)    -> 阻断                (L1)
4. blacklist_precheck (R-05)       -> 阻断 + 全量上报      (L1)  ← F3 前移
5. alias_exact (R-07)              -> 放行                (L2)  ← F3 后移
6. variety_neutral_target_review   -> 降级复核             (L3)
7. metric_exclusion_soft           -> 降级复核             (L3)
8. R-06 dice 阈值                  -> 放行/复核/阻断       (L3)
```

相对 V85 的**唯一顺序变化**是第 2–4 与第 5 交换。规则语义、阈值、判定条件全部不变。

## 3. 门禁契约

### 3.1 输入契约（每个门禁统一）

```python
{
    "a_raw": str, "b_raw": str,          # 原始输入
    "a": str, "b": str,                   # norm_full 后
    "ca": list[str], "cb": list[str],     # resolve_canonical_safe 结果
    "metrics": (Metric, Metric),          # primary_metric
    "families": (list, list),             # metal_families
    "conflict_level": "HARD"|"SOFT"|None, # metric_conflict
    "dice": float,                        # Dice 相似度
}
```

### 3.2 裁决输出契约

```python
{
    "verdict": "PASS" | "REVIEW" | "BLOCK",
    "reason": str,                        # 裁决门禁 ID，如 "blacklist_precheck"
    "all_rules": list[str],               # L1 全部命中规则 ID        ← F3 新增
    "hit_fragments": list[str],           # 命中片段（可归因依据）      ← F3 新增
    "incomplete": bool,                   # 是否有 L1 门禁被短路       ← INV-3
    "dice": float,
}
```

**关键变更**：`all_rules` 在 V85 只上报首命中规则，导致 `BL-003 / BL-025 / BL-015 / BL-026 / BL-016a` 在 4857 pair 语料上**从未被上报过**（base 上报数 = 0）。T2.6 实测：base 上报 0/6 条组合规则，f3 修复后 6/6。

### 3.3 三态语义

| 裁决 | 含义 | 生产动作 |
|---|---|---|
| `PASS` | 自动通过 | 直接入库 |
| `REVIEW` | 降级人工复核 | 进入人工队列，**不等于拒绝** |
| `BLOCK` | 硬拦截 | 丢弃候选 |

`REVIEW` 与 `BLOCK` 的区分是 T2.1 发现的口径缺陷：V85 测试集只有布尔 `expected_blocked`，无法区分两者，掩盖了 7 条降级复核路径的回归风险。本设计强制每条用例标注三态期望。

## 4. 四个修复档

### F1 · 异常兜底（0.25 人时）

`resolve_canonical` 对未命中的归一名抛 `KeyError`。修复为返回空列表。

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 9714 次调用中 KeyError | **2977（30.65 %）** | 0 |
| 单元测试 | — | 19/19 PASS |

**零行为变化**：F1 只改变异常路径，不改变任何命中路径的返回值。

### F2 · 确定性解析（2 人时）

多 canonical 冲突时，原实现返回的顺序取决于字典遍历顺序，**同一输入在不同进程下可能得到不同结果**。修复为：交集计算后**排序取稳定序**，并返回结构化结果（候选集合 + 裁决理由）。

**约束**：F2 只能保证「同一输入永远得到同一结果」，**不能保证「结果是对的」**。165 条歧义中 53 条 P0 的人工择优是 F2 的必要前置（详见 `high_prio_ambig_analysis.md` §7）。

### F3 · 门禁重排 + 全量上报（4 人时）

1. `blacklist_precheck` 前移到 `alias_exact` 之前
2. R-05 改为**收集全部命中规则**而非首命中即返回
3. 输出 `all_rules` 与 `hit_fragments`

### F4 · 自触发抑制（3 人时）

黑名单规则的 L 侧与 R 侧 pattern 在**同一字符串内**可能构成子串关系（如 BL-012 的 `库存天数` ⊃ `库存`），导致规则自我触发。修复为：
- **F4a 子串抑制**：L 侧命中片段与 R 侧命中片段若存在包含关系，抑制该规则
- **F4b 不相交共现抑制**：复合短语内的不相交共现不视为跨侧冲突

### 修复档关系

| 档位 | 人时 | 依赖 | 可独立上线 |
|---|---|---|---|
| F1 | 0.25 | 无 | **是** |
| F2 | 2 | 53 条 P0 人工择优 | **否** |
| F3 | 4 | F4 | **否** |
| F4 | 3 | 无 | **是** |

## 5. 上线顺序（硬约束）

```
阶段 1  F1 部署                          （0.25 人时，零行为变化，立即）
阶段 2  53 条 P0 歧义人工择优           （≈ 2 人天，离线）
阶段 3  F2 部署                          （前置：阶段 2 完成）
阶段 4  F3 + F4 同批部署                 （前置：F1；禁止单独上 F3）
阶段 5  冻结 14 道回归门禁为 V86 基线
```

### 为什么 F3 不能单独上线

T2.6 在 102 条用例上实测：F3 把 R-05 前移后，更多原本被 `alias_exact` 直接放行的 pair 进入 R-05 检查，其中大量是 pattern 自触发 —— 恰好是 F4 要抑制的形态。

| 指标 | base | **f3 单独** | f3+f4 |
|---|---|---|---|
| 整体一致率 | 89.2 % | **75.5 %**（低于 base） | 100 % |
| G4 边界零误拦 | FAIL 11/18 | **FAIL 17/18** | PASS 0/18 |
| D6 自配对 | PASS × 8 | **BLOCK × 8** | PASS × 8 |

F3 单独上线会净增 **17 个边界误拦 + 8 个自配对误拦**。

### 6.2 G7 为什么判 N/A 而非 PASS

4821 归一名语料中，`alias_exact` 分支条件（双侧 canonical 有交集）与黑名单命中**同时成立的 pair 共 14 条，全部是自配对**（`a == b`），且这些配对的黑名单命中本身就是 pattern 自触发误报（正确答案是放行）。语料中**不存在**「别名精确命中 + 真实黑名单冲突」的跨配对。

把样本为 0 的门禁记为 PASS 是**过度声明**。必须引入外部构造的跨配对样例后，G7 才可判定。

### 6.3 G1 为什么不可证伪

三个引擎变体均由 `audit_kit.load_engine()` 装载，该装载器已安装 F1 守卫，故 G1 恒 PASS。G1 必须在**未打补丁**的引擎上验证。

### 6.4 门禁判定口径的两处易错点

1. **G3 衡量拦截率而非 R-05 归因** —— P0 用例被 R-01 / R-03 / R-05 任一门禁阻断即算拦截。若只看 R-05 归因，会得出「G3 失败 62.5 %」的错误结论。
2. **G6 只在 R-05 裁决的用例上评估** —— 被 R-01 上游短路的用例此时不产生 `all_rules`，空列表是**正确行为**而非上报缺失。若把分母设为全部组合用例，base 会被误判为 0/8。

## 7. 实测收益与回归面

### 7.1 102 用例 / 7 维度

| 维度 | 条数 | 目的 | base | f3 | **f3+f4** |
|---|---|---|---|---|---|
| D1_POSITIVE | 26 | 每条活规则 ≥ 1 条应拦截对 | 100 % | 100 % | 100 % |
| D2_NEGATIVE | 26 | a 含 L token、b 无黑名单 token | 100 % | 100 % | 100 % |
| D3_BOUNDARY | 12 | 同串 L/R 子串关系（F4a） | 50 % | 8.3 % | **100 %** |
| D4_COMPOUND | 6 | 同串 L/R 不相交共现（F4b） | 16.7 % | 0 % | **100 %** |
| D5_COMBINATION | 8 | 命中 ≥ 2 条规则，全量上报 | 100 % | 100 % | **100 %** |
| D6_GATE_CONFLICT | 8 | alias_exact ∩ 黑名单同时成立 | 100 % | 0 % | **100 %** |
| D7_ROBUSTNESS | 16 | 空值 / 超长 / 短词 / 编码异常 | 100 % | 100 % | 100 % |
| **整体** | **102** | | **89.2 %** | **75.5 %** | **100 %** |

### 7.2 D1 拦截机制分布

| 裁决门禁 | 独占裁决 | 含义 |
|---|---|---|
| R-01 品种锚点 | 16 / 26 | 跨品种 pair 由品种锚点拦截 |
| R-05 黑名单 | **10 / 26** | 黑名单的边际贡献 |

三变体拦截率均为 100 %。**黑名单门禁的价值不是提升拦截率，而是提升可归因性** —— 从「被某个模糊规则拦住」变成「被 BL-005 第 3 条 pattern 拦住，因为 a 侧命中『锌锭』、b 侧命中『表观消费』」。

### 7.3 4857 pair 语料差分（F1 后）

| 裁决 | 修复前 | 修复后 | Δ |
|---|---|---|---|
| accept=True | 1844 | 1679 | **−165（−8.95 %）** |
| accept=False | 3013 | 3178 | +165 |

通过率下降 8.95 % 全部由**多 canonical 冲突的确定性裁决**贡献（F1 修复前这些 pair 直接崩溃，无从计入）。阈值 −9.1 % ⇒ G10 PASS。
