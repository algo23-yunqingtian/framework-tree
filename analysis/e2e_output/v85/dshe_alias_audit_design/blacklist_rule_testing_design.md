## 1. 现状盘点：三类结构性问题

### 1.1 覆盖缺口

| 状态 | 规则数 | 说明 |
|---|---|---|
| `COVERED`（被引用且可达） | **7** | BL-009、BL-012、BL-015、BL-018、BL-018a、BL-022、BL-026 |
| `UNCOVERED_REACHABLE` | **24** | 可达但测试集未引用 |
| `UNCOVERED_SHADOWED` | 0 | 无规则级遮蔽（见 §1.3） |

**按严重级**（未覆盖）：

| 严重级 | 未覆盖 / 总数 | 规则 |
|---|---|---|
| **P0** | **14 / 20** | BL-001/002/003/005/006/008/010/018b/019/019a/020/021/025/025a |
| P1 | 7 / 8 | BL-004/007/011/013/016/016a/024 |
| P2 | 3 / 3 | BL-014/017/023 |

> **P0 规则的测试覆盖率只有 15 %**——这是当前测试集最严重的结构性缺陷。P0 是唯一会阻断导入的门禁，却几乎没有回归保护。

### 1.2 规则活性：3 条死规则 + 27.4 % 死 token

以别名库 4643 行的 4821 个归一名池为语料核算：

| 项 | 值 |
|---|---|
| R 侧 token 全部 0 命中（规则永不触发） | **3 条**：`BL-019a`（铜TC/铜加工费/铜管加工费/铜精矿TC 全为 0）、`BL-020`（苯乙烯 0）、`BL-021`（黄金 0） |
| R 侧含 ≥1 个 0 命中 token | 17 / 31 条规则，共 **26 / 95 = 27.4 %** 死 token |
| L 侧含 ≥1 个 0 命中 token | 5 / 31 条规则 |
| L 侧全部 0 命中 | 0 条 |

**成因**：黑名单是**按品种语义**设计的，但别名库覆盖的是**基本金属 7 种**（CU/AL/ZN/NI/SN/SI/LI）+ 部分铝系子品类。`苯乙烯`（化工）、`黄金`（贵金属）、`铜TC`（英文缩写口径）根本不在语料内。这 3 条规则在 V86 上线**永远不会被触发**——它们是"范围外冗余"，不是"待测试规则"。

### 1.3 遮蔽分析：遮蔽发生在**门禁层**而非**规则层**

| 检查项 | 结果 |
|---|---|
| 规则级遮蔽（同 severity 且 `L_j ⊇ L_i` 且 `R_j ⊇ R_i`） | **0 条** |
| 同 severity 且 L 交集非空 | 9 对（BL-001/002、BL-005/006、BL-010/026、BL-018/018a、BL-018/018b、BL-018a/018b、BL-019/020、BL-019/021、BL-020/021） |
| 同 severity 的 L 真子集 | 1 对：`BL-018 ⊂ BL-018a` |
| 近乎逆对（冗余） | 3 对：`(BL-001,BL-025)`、`(BL-002,BL-003)`、`(BL-008,BL-015)` |

**关键澄清**：T2.2 观测到"`BL-003/BL-025/BL-015/BL-026/BL-016a` 在 base 中从未上报"，其成因**不是规则间遮蔽**（结构检查为 0），而是**门禁层遮蔽**——`alias_exact`（R-07）在 R-05 之前返回，导致 R-05 对别名命中的 pair **完全没机会执行**。因此：

- 规则遮蔽是**语料依赖**的：任何规则都可能因语料中被 `alias_exact` 抢占而无法上报；
- 修复手段只能是 T2.2 的 **F3（门禁重排）**，无法通过改写规则本身解决；
- 测试集必须**显式包含"黑名单命中 + 别名也命中"的组合用例**，否则门禁层遮蔽永远无法被回归发现（BOUNDARY-013 即为此类，base 因 `alias_exact` 直接放行）。

**冗余规则**：`R-05` 的检查逻辑是双向的（`(L in a and R in b) or (L in b and R in a)`），因此逆对规则完全冗余——3 对逆对可压缩为 3 条（**冗余率 9.7 %**）。

## 2. 现有测试集缺陷诊断（24 条，缺陷率 41.7 %）

| 类别 | 条数 | expected_blocked |
|---|---|---|
| 正向危险样例 | 10 | True |
| 安全负向样例 | 7 | False |
| 数据缺失样例 | 7 | False |

### 2.1 缺陷一：引用不存在的规则（3 条）

| 用例 | 期望规则 | 实际命中 |
|---|---|---|
| BOUNDARY-001/002/003 | **`BL-009a`** | `BL-009` |

`BL-009a` **不存在于终版黑名单**。实际黑名单中"子品类变体"后缀 `-a/-b` 只出现在 `BL-018a/BL-018b/BL-019a/BL-025a`，`BL-009` 没有 `a` 变体。这 3 条用例的 `expected_rule` 应从 `BL-009a` 改为 `BL-009`。

### 2.2 缺陷二：机制张冠李戴（5 条，最严重）

| 用例 | 期望规则 | 实际拦截机制 | 根因 |
|---|---|---|---|
| BOUNDARY-014 | `BL-012; BL-026` | **R-01 品种锚点** | `锡厂库存天数（天）` ↔ `锡厂库存量（吨）`：BL-012 的 `L=库存天数` 与 `R=库存/库存量` 在同侧构成子串关系，被 F4a 抑制；真正拦下的是 R-01 |
| BOUNDARY-016 | `BL-026` | **R-01 品种锚点** | 同上 |
| BOUNDARY-020 | `BL-022` | **R-01 品种锚点** | `COMEX镍持仓量（手）` ↔ `COMEX：铜：主力合约：持仓量（日）`：名字中**没有** `电解镍`/`电解铜`，BL-022 的 token 根本不出现 |
| BOUNDARY-022 | `BL-018; BL-018a` | **R-01 品种锚点** | `LME锡库存（吨）` ↔ `LME：镍：注册仓单（日）`：名字中**没有** `锡矿`/`锡锭`，BL-018/BL-018a 的 token 不出现 |
| BOUNDARY-024 | `BL-015` | `BL-008`（+ BL-015） | 两者都命中，期望只写了 BL-015，且 F3 的 `all_rules` 才上报 `BL-008\|BL-015` |

**系统性结论**：测试集把 **"R-01 品种锚点拦截"** 与 **"R-05 黑名单 token 拦截"** 两个机制混为一谈。凡"仅品种前缀不同、指标词相同"的跨品种对（`COMEX镍` ↔ `COMEX铜`、`LME锡` ↔ `LME镍`），**正确机制是 R-01**，与黑名单无关。测试集必须按机制而非按"应该被拦住"来标注期望。

### 2.3 缺陷三：期望方向错误（2 条）

| 用例 | 期望 | 实际（base 与 F3+F4 一致） | 说明 |
|---|---|---|---|
| BOUNDARY-019 | 不拦截 | **拦截**（`below_threshold`） | `COMEX镍持仓量（手）` ↔ `COMEX：镍：主力合约：持仓量（日）`：dice 低于 R-06 阈值 |
| BOUNDARY-021 | 不拦截 | **拦截**（`below_threshold`） | `LME锡库存（吨）` ↔ `LME：锡：库存：中国（日）`：同上 |

这两条不是黑名单问题，而是 **R-06 阈值行为**。期望应改为 `BLOCK`，或把用例重新归类为"阈值类"而非"黑名单安全负向"。

### 2.4 缺陷四：门禁层遮蔽用例缺失

`BOUNDARY-013`（`碳酸锂工厂库存天数` 同名对）在 base 下走 `alias_exact` **直接放行**，黑名单从未执行——base 与期望"恰好一致"（期望就是不拦截），但**路径完全错误**。这类"黑名单命中 + 别名命中"的组合用例只有 1 条，无法回归门禁层遮蔽。

### 2.5 修复后一致率

| 门禁 | 与期望一致 | 变化 |
|---|---|---|
| base | 20 / 24 | — |
| F3-only | 20 / 24 | 未改善（F3 引入的黑名单优先反而多拦了 BOUNDARY-013） |
| **F3 + F4** | **22 / 24** | **+2**：`BOUNDARY-017`（`锡厂库存天数` 同名对，F4a 抑制 BL-012）、`BOUNDARY-018`（`碳酸锂利润与需求分析`，F4b 抑制复合短语） |

| | | **合计** | **104** |

### 3.2 三态期望标注

每条用例必须标注**期望裁决态**而非只标 `expected_blocked`：

| 期望态 | 含义 | 对应字段 |
|---|---|---|
| `BLOCK` | `accept=False, review=False` | 黑名单 P0/P1 命中、R-01 品种锚点 |
| `REVIEW` | `accept=False, review=True` | 多 canonical、品种中性、软冲突 |
| `PASS` | `accept=True` | 别名命中、高 dice 同品种 |

现有测试集只有布尔 `expected_blocked`，无法区分 `BLOCK` 与 `REVIEW`——这导致 BOUNDARY-007~012/023 这类 `REVIEW` 用例被"算作一致"，**掩盖了 7 条降级复核路径的回归风险**。

### 3.3 期望机制标注（修正机制张冠李戴）

`expected_rule` 必须扩展为 `expected_mechanism`：

| 机制 | 取值 |
|---|---|
| `R-01` | `variety_anchor_violation` |
| `R-03` | `metric_exclusion_hard` |
| `R-05` | 具体 `BL-xxx` 列表 |
| `R-07` | `alias_exact` / `alias_ambiguous_multi_canonical` |
| `R-06` | `high_dice` / `mid_dice_same_variety` / `low_dice_no_variety` / `below_threshold` |

## 6. 回归门禁定义

V86 每次修改黑名单或门禁顺序后必须全部通过：

| Gate | 名称 | 判据 | 阻断级别 |
|---|---|---|---|
| **G1** | 无崩溃 | 104 条用例全部无异常返回（T2.2 的 2977 KeyError 已归零） | **P0 硬阻断** |
| **G2** | 活规则覆盖 | 25 条独立活规则 × 4 类用例 = 100 % 有裁决 | P0 硬阻断 |
| **G3** | P0 拦截率 | D1 中 P0 用例拦截率 = 100 % | P0 硬阻断 |
| **G4** | 边界零误拦 | D3 + D4 误拦数 = 0 | **P0 硬阻断** |
| **G5** | 安全负向误拦 | D2 误拦率 ≤ 1 % | P1 |
| **G6** | 组合全量上报 | D5 用例 `all_rules` 与期望集合相等 | P1 |
| **G7** | 门禁冲突可观测 | D6 用例中 R-05 被实际执行（非 `alias_exact` 短路） | P1 |
| **G8** | 一致率不回退 | 整体与期望一致率 ≥ 98 %，且不低于上一版 | P0 硬阻断 |
| **G9** | 单元断言 | T2.2 的 19 条 UT 全部 PASS | P0 硬阻断 |
| **G10** | 语料差分 | 4857 pair 语料上 `accept=True` 数量下降 ≤ 9.1 %（167/1824），且 `A→B` 仅允许来自门禁重排 | P1 |

### 6.1 门禁与修复档位的对应

| 修复档位 | 直接通过的 Gate |
|---|---|
| F1 最小修补 | G1、G9 |
| F2 结构化返回 | G6、G7 |

## 9. 修订记录（v1.1 · T2.6 实测回填）

执行 `blacklist_rule_effectiveness_test.py`（102 用例 / 7 维度）后，对本文档以下设计假设做修订：

### 9.1 D6 门禁冲突的构造必须用 `resolve_canonical` 交集，不能用「别名是否注册」

原设计用「a 侧在别名库注册 + 黑名单命中」近似 alias_exact ∩ blacklist。实测该近似**漏判**：
注册不等于能解析出 canonical（`alias_exact` 的真条件是
`ca and cb and set(ca) & set(cb)`）。修订为直接用 `resolve_canonical` 交集判定，
共 14 条真实样例。

### 9.2 INV-1 在本语料上不可判定

14 条 alias_exact ∩ 黑名单命中样例**全部是自配对**（`a == b`），且其黑名单命中本身即
pattern 自触发误报（BL-012 的 L 侧 `库存天数` 与 R 侧 `库存` 同串子串关系），
正确答案是**放行**。因此：

- G7 改名为 `G7_INV1_BLACKLIST_BEATS_ALIAS`，且**只在跨配对上评估**；
- 跨配对样例数 = 0 时判 **N/A**（不可判定），**不得**记为 PASS；
- 补齐方向：引入外部构造的跨配对（同 canonical 多品种别名 ↔ 异 canonical 黑名单别名）。

### 9.3 D6 的期望按配对类型分叉

| 配对类型 | 正确答案 | 依据 |
|---|---|---|
| 自配对 | `PASS` | 黑名单命中系 pattern 自触发，F4 必须抑制 |
| 跨配对 | `BLOCK` | INV-1：黑名单必须优先于别名放行 |

### 9.4 G6 只在 R-05 裁决的用例上评估

base 变体的 2 条 D5 用例被 R-01 上游短路，此时 R-05 不执行、不产生上报，
`all_rules` 为空是**正确行为**而非上报缺失。G6 分母改为「R-05 成为裁决门禁的 D5 用例」。

### 9.5 G3 衡量拦截率而非 R-05 归因

P0 目标用例被 R-01/R-03/R-05 任一门禁阻断即算拦截。R-05 归因率另立为
信息性指标 `G3b`（实测 37.5 %），不设门槛。
