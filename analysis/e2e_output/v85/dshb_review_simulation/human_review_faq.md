## 一、常见冲突场景

### Q1: 白名单条目被黑名单规则拦截怎么办？

**场景**: 人工将某模板标记为白名单放行，但该模板的指标名称匹配了黑名单规则的 left_patterns。

**示例**: RISK-005（TPL-LC-087 磷酸铁锂 电池 国内销量）被推荐白名单放行，但 series_name 包含'国内销量'，匹配 BL-008（出口↔国内销量互斥）的 right_patterns。

**判定标准**:

| 条件 | 判定 | 处置 |
|------|------|------|
| 口径正确，确认无误 | 白名单放行合理 | 在评审备注中说明确认依据 |
| 口径存疑 | 拒绝白名单，重新评审 | 标记为'需进一步确认' |
| 口径明确错误 | 拒绝白名单 | 标记为'BLOCKED' |

**处置建议**: 在 `recommended_action` 字段中明确记录判定依据，如: `白名单放行（条件：人工确认TPL-LC-087国内销量口径正确）`

### Q2: 数据缺失P0如何处置？

**场景**: PDF模板的 matched_name 为空（N/A），导致黑名单规则无法触发。RISK-010/011/013 是典型案例。

**处置方案优先级**:

| 优先级 | 方案 | 说明 | 推荐度 |
|--------|------|------|--------|
| 1 | 上游数据修复 | 联系数据源方补全 matched_name | ⭐⭐⭐ 根本解决 |
| 2 | 人工白名单放行 | 人工确认指标语义正确后放行 | ⭐⭐ 临时方案 |
| 3 | 不处置，标记观察 | 等待上游修复后自动处理 | ⭐ 最低 |

**注意**: 白名单放行后，若上游数据后续修复，该模板将可能被黑名单规则拦截。建议在白名单备注中标记 `WHITELIST-TEMP` 并设定过期时间。

### Q3: 漏拦截P0（方向性缺失）如何判定？

**场景**: RISK-002（碳酸锂 三元523需求→碳酸锂现金生产利润），BL-009 仅检查正向（利润→需求），反向（需求→利润）漏拦截。

**判定标准**:

1. **确认方向性**: 检查 indicator_name 和 matched_name 的语义方向
2. **确认BL-009覆盖**: BL-009 的 left_patterns 包含'利润'，right_patterns 包含'需求' — 仅覆盖正向
3. **确认BL-009a覆盖**: BL-009a 的 left_patterns 包含'需求'，right_patterns 包含'利润' — 覆盖反向
4. **确认无遗漏**: 两条规则互补，双向覆盖完整

**处置建议**: 标记为 `confirmed_new`，推荐上线 BL-009a。在评审备注中记录: `BL-009a确认，需求→利润反向匹配，1TP/0FP`

### Q4: P0已阻塞但需确认别名映射怎么办？

**场景**: 21条P0-C案例已被黑名单规则覆盖（如BL-005、BL-003、BL-002等），但仍需确认别名映射的正确性。

**处置标准**:

| 检查项 | 通过条件 | 不通过条件 |
|--------|---------|-----------|
| 别名映射 | 映射后指标名与原始语义一致 | 映射后语义偏差 |
| 黑名单规则 | 规则匹配逻辑正确 | 规则误匹配或漏匹配 |
| 品种一致性 | 模板品种与匹配数据品种一致 | 跨品种误匹配 |

**处置建议**: 在评审备注中记录别名映射结果，如: `别名映射确认：碳酸锂→碳酸锂（同品种），BL-009a拦截，P0已处置`

### Q5: BL-026 为什么需要人工确认？

**场景**: BL-026（库存天数跨品种禁止）标记为 `needs_manual_review`，需人工确认后才能启用。

**原因分析**:

1. **规则特殊性**: BL-026 是 BL-012 的扩展规则，专门处理库存天数跨品种匹配
2. **前置过滤依赖**: BL-012 方案B（品种感知前置过滤）需要先启用，BL-026 才能正确工作
3. **潜在FP风险**: 若品种识别不准确，BL-026 可能产生误拦截

**确认标准**:

| 条件 | 确认结果 |
|------|---------|
| BL-012方案B已验证通过 | ✅ 确认BL-026 |
| 9条P1库存天数跨品种案例全部正确拦截 | ✅ 确认BL-026 |
| 无新增FP | ✅ 确认BL-026 |
| 任何条件不满足 | ❌ 暂不确认 |

## 二、判定标准速查

### 2.1 白名单放行判定标准

```
✅ 可放行条件（全部满足）:
  1. 人工已确认指标口径正确
  2. 无数据缺失（matched_name非空，或有明确替代数据源）
  3. 放行后不影响其他模板的黑名单规则执行
  4. 已记录放行理由和确认人

❌ 不可放行条件（任一满足）:
  1. 指标口径存疑或已确认错误
  2. 数据缺失且无法修复
  3. 放行后会导致P0漏拦截风险
  4. 无明确的放行依据
```

### 2.2 P0处置标记判定标准

| 标记 | 含义 | 前置条件 |
|------|------|---------|
| `BLOCKED` | 已被黑名单规则正确拦截 | 规则匹配确认 |
| `WHITELISTED` | 人工白名单放行 | 口径确认+理由记录 |
| `PASS` | 评审通过，可直接渲染 | 无风险标记 |
| `REJECTED` | 评审拒绝，需替换指标 | 风险确认+替换方案 |
| `CONDITIONAL_PASS` | 条件通过（需后续跟踪）| 条件说明+跟踪计划 |

### 2.3 风险等级判定标准

| 等级 | 触发条件 | 处置要求 |
|------|---------|---------|
| P0 | 跨品种误匹配/口径冲突/漏拦截 | 必须处置（拦截/白名单/修复）|
| P1 | 警告级/术语歧义/非跨品种 | 建议处置（可人工观察）|
| CLEAN | 无风险标记 | 可直接渲染 |

## 三、填写错误案例

### 错误1: 数据缺失模板标记为 BLOCKED

**错误填写**:
```
RISK-010 | 中国电解镍净进口量 | BLOCKED | BL-022已覆盖
```

**正确填写**:
```
RISK-010 | 中国电解镍净进口量 | NOT_BLOCKED（漏拦截）| 上游数据修复或人工白名单放行
```

**原因**: BL-022规则存在但 matched_name 为空，规则无法触发。标记为 BLOCKED 是错误的。

### 错误2: 白名单条目未记录放行理由

**错误填写**:
```
RISK-005 | 磷酸铁锂 电池 国内销量 | WHITELISTED | 白名单放行
```

**正确填写**:
```
RISK-005 | 磷酸铁锂 电池 国内销量 | WHITELISTED | 白名单放行（条件：人工确认TPL-LC-087国内销量口径正确，不匹配出口数据）
```

**原因**: 白名单放行必须有明确的理由和条件，否则后续无法追溯判定依据。

### 错误3: Gate跟踪表与工作表状态不一致

**错误填写**:
```
Gate: H2 = DONE (P0全部处置)
工作表: 4条P0标记为NOT_BLOCKED（未处置）
```

**正确填写**:
```
Gate: H2 = BLOCKED (2%处置率)
工作表: 4条P0标记为NOT_BLOCKED
```

**原因**: Gate跟踪表状态必须与工作表实际处置进度一致。使用 `review_consistency_check.py` 可自动检测此类不一致。

### 错误4: 漏拦截标记为已拦截

**错误填写**:
```
RISK-002 | 碳酸锂 三元523需求 | BLOCKED | BL-009已覆盖
```

**正确填写**:
```
RISK-002 | 碳酸锂 三元523需求 | NOT_BLOCKED（漏拦截）| 规则修复：新增BL-009a（confirmed_new）
```

**原因**: BL-009 仅检查正向（利润→需求），BL-009a 才能覆盖反向（需求→利润）。标记为 BLOCKED 会遗漏这个漏拦截风险。

### 错误5: 跨品种P0未标记gate_block_flag

**错误填写**:
```
RISK-014 | COMEX镍持仓量（手）| BLOCKED | YES (gate_block_flag) | —
```
（gate_block_flag 字段留空）

**正确填写**:
```
RISK-014 | COMEX镍持仓量（手）| BLOCKED | YES | BLOCKED |
```

**原因**: 所有P0条目（无论是否已拦截）都必须设置 gate_block_flag=YES，以便Gate跟踪表统计。P1条目设置 gate_block_flag=NO。

## 四、处置建议速查

### 4.1 P0风险处置决策树

```
P0风险 → 检查数据是否完整
  ├─ 数据缺失 → 上游修复 / 白名单放行 / 观察
  └─ 数据完整 → 检查黑名单规则覆盖
       ├─ 规则已覆盖 → 确认拦截 → BLOCKED
       ├─ 规则未覆盖 → 新增规则 → 回放验证 → BLOCKED
       └─ 口径正确 → 白名单放行 → WHITELISTED
```

### 4.2 数据修复检查清单

```
上游数据修复完成后:
  [ ] matched_name 字段非空
  [ ] matched_name 与 indicator_name 品种一致
  [ ] 黑名单规则可正常触发
  [ ] 回放验证通过
  [ ] 更新P0工作表状态
  [ ] 运行 review_consistency_check.py 校验
  [ ] 更新Gate跟踪表
```

### 4.3 白名单管理

| 检查项 | 要求 |
|--------|------|
| 放行理由 | 必须有明确的口径确认说明 |
| 确认人 | 必须记录评审人姓名和日期 |
| 过期时间 | 建议6天有效期（WL-EXPIRY）|
| 数据变更跟踪 | 上游数据变更后需重新评估 |
| 评审审计 | 所有白名单条目纳入Batch-C评审 |
