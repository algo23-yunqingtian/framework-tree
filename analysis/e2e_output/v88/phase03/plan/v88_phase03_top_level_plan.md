### 1.2 CRLF MD5 校验优化方案（Phase03 落地规范）

**问题本质**：MD5 对行尾符敏感，跨平台检出（Linux LF / Windows CRLF）导致同一内容产生不同哈希，造成「假阳性差异」。

**Phase03 规范（写入长期运维 SOP）**：

| 环节 | 规范 | 责任方 |
|---|---|---|
| 提交前 | `core.autocrlf=input`（Windows 检出 LF，提交 CRLF→LF） | 全 Agent |
| MD5 登记 | 统一登记 **LF 规范化后** 的哈希（`dos2unix` 后计算） | DSHB/DSHE |
| 审计时 | HERMEShf 先规范化行尾再算 MD5，与登记值比对 | HERMEShf |
| 差异判定 | 差异字节数 = CRLF 数量 → 判「行尾差异，非内容损坏」，自动归档不阻断 | HERMEShf |
| 校验脚本 | 新增 `md5_normalize.py --check-crlf <file>`，输出 (raw_md5, lf_md5, crlf_count, delta_bytes) | HERMEShf |

**验证公式**：`delta_bytes == crlf_count` → CRLF 归因成立（Phase02 实测 640/640、430/430 精确吻合）。
