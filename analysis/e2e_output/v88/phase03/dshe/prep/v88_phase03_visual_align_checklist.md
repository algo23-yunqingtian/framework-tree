## 3. 答辩素材汇总 (T1)

### 3.1 核心组件设计说明

#### 3.1.1 RenderScheduler (请求调度层)

| 维度 | 设计 |
|------|------|
| 功能 | 异步渲染调度器, 500并发优化 |
| 并发控制 | asyncio.Semaphore(DEFAULT_CONCURRENT=200), 渐进扩容至500 |
| 优先级队列 | asyncio.PriorityQueue(maxsize=1000), 三级优先级(critical/normal/background) |
| 队列深度告警 | >500 WARN, >800 CRIT |
| 超时控制 | 单图表渲染超时2.0s, 超时自动切换下一级降级 |
| 背压保护 | 队列满时拒绝请求, 返回503 |
| 监控指标 | queue_depth/avg_wait_ms/rejected_count/priority_distribution |

#### 3.1.2 RenderCache (渲染缓存层)

| 维度 | 设计 |
|------|------|
| 功能 | 渲染结果LRU+TTL缓存 |
| 缓存容量 | MAX_SIZE=256条 |
| 过期策略 | TTL_SECONDS=300s (5分钟) |
| 淘汰策略 | LRU (最久未访问优先淘汰) |
| 线程安全 | asyncio.Lock |
| 命中率目标 | 60-70% |

## 5. 灾备切换时序细节对齐 (T1补充)

### 5.1 HERMEShf灾备时序协议 (DSHE采纳)

```
T-30min: DSHB→DSHE预热通知:
         DSHE读取当前快照, 预热缓存(101图表×最新值)
         DSHE启用placeholder→simulated降级链路(Phase02已验证960次0崩溃)
         → dr_warm_cache_status=ready, dr_status=normal

T-0:     DSHB主链路:
         (1) 标记停止写入(soft-stop, 不丢失最后写入批次)
         (2) 双写开启: 主库→灾备库(全量同步)
         (3) 灾备链路追平数据(WAL日志回放)
         → DSHE检测到数据流中断, 自动启用降级
         → dr_fallback_depth=1或2, dr_status=switchover

T+0~5min: RPO核验:
         (1) 对比主库最后写入时间戳 vs 灾备库最新时间戳
         (2) 差距=0 → RPO=0验证通过 (采纳HERMEShf标准)
         (3) 差距>0 → 触发重试(最多3次, 间隔30s)
         → DSHE dr_rpo_seconds实时更新, dr_reconciliation_pct=0%

T+5min:  切回主链路:
         (1) DSHB通知DSHE切回主链路
         (2) DSHE缓存刷新(读取主库最新数据)
         (3) 主链路恢复写入
         → DSHE dr_status=switchback, dr_fallback_depth=0

T+5~10min: 一致性对账:
         (1) 逐指标对比主库vs灾备库最后146行
         (2) 一致率=100% → 演练完成
         (3) 一致率<100% → 标记差异, 触发HERMEShf审计
         → DSHE dr_reconciliation_pct更新(30s间隔), dr_reconciliation_mismatch=0

T+10min:  演练完成:
         (1) 标记DRILL_COMPLETE
         (2) 进入7天观察窗(S-1门禁: 0 P0/P1)
         (3) HERMEShf独立复核演练日志
         → DSHE dr_status=normal, dr_total_switches+1
```
