### 2.2 关键风险详解

#### R-03: 降级连锁反应 (Critical)

**风险描述**: 三级降级(real→simulated→placeholder)在高并发+灾备切换场景下, 若simulated数据源(16项SEEDS)也出现异常, 可能导致placeholder渲染也不可用, 造成渲染全面断供。

**根因分析**:
1. Phase02已验证960次降级操作0崩溃, 但均为单图表级别测试
2. 500并发全降级场景下, SEEDS数据源可能成为瓶颈
3. 灾备切换期间, 所有数据源可能同时不可用

**缓解措施**:
1. **Phase02继承**: 三级降级链路已验证960次0崩溃
2. **新增缓存预热**: 灾备切换前T-30min预热缓存, 覆盖最近渲染结果
3. **placeholder保底**: placeholder不依赖外部数据源, 渲染结果本地生成
4. **熔断机制**: 单图表2s超时自动切换下一级降级
5. **P0原型验证**: P3-DR-04(全降级场景)验证三级降级全部失效时placeholder渲染

**影响评估**: 若全部三级降级失效, 影响范围=全局(101图表全部无法渲染), 但placeholder为本地渲染, 不会依赖任何外部数据源, 因此三级全部失效概率极低。

#### R-01: 500并发内存溢出 (High)

**风险描述**: 500并发场景下, 每个渲染请求占用~5-15MB内存(YAML解析+指标数据+序列化缓冲), 预估峰值内存2.5-7.5GB, 可能超过容器/进程内存限制。

**缓解措施**:
1. **LRU缓存**: 缓存256条渲染结果, 避免重复解析
2. **流式序列化**: 大图表JSON流式输出, 减少缓冲占用
3. **YAML解析缓存**: 解析结果持久化缓存, 避免重复解析1758行
4. **线程池限流**: 最大128线程, 避免并发膨胀
5. **队列限流**: 队列上限1000, 超出拒绝(背压保护)

**监控指标**: worker_memory_mb(新增到并发扩容面板)

#### R-04: CPU FUSE逼近 (Medium)

**风险描述**: Phase02 CPU峰值1.94%, 500并发线性外推约4.85%, 加调度开销约5-8%。虽然<10%目标, 但距CPU FUSE 2.0%(注意: 这是V87 Phase36的1.94%观测数据, V88 Phase03 CPU阈值目标<10%)仍有余量。但Phase02已有1.9%预警阈值, 扩容后需确认不会误触发预警。

**缓解措施**:
1. 缓存命中率优化(60-70%目标) → 减少重复渲染CPU
2. 异步序列化 → 减少同步阻塞CPU
3. 线程池自适应 → 避免线程膨胀CPU
4. 监控: worker_utilization_pct >80% WARN / >95% CRIT

**注意**: CPU FUSE 2.0%是Phase02 DSHB后端阈值, DSHE渲染侧目标<10%。两者不冲突, 但需在扩容前确认CPU监控口径统一。

#### R-05: 灾备切换渲染断供 (Medium)

**风险描述**: 灾备切换T-0时刻, DSHB停止写入, DSHE数据源中断。若降级链路未在T-0前就绪, 可能导致请求失败。

**缓解措施**:
1. 灾备切换前T-30min预热缓存(DSHB通知DSHE)
2. 三级降级自动切换(real→simulated→placeholder)
3. Phase02已验证50并发降级P99=29.44ms, 渲染连续性有保障
4. 新增: 灾备状态监控面板实时显示降级深度

#### R-15: 仿真与真实流量差异 (Medium)

**风险描述**: Phase03 P1仿真阶段使用locust/wrk模拟500并发, 但真实金丝雀流量分布可能不同(如burst模式、长尾请求、品种分布不均), 导致仿真结果与生产表现偏差。

**缓解措施**:
1. 继承R-V88-011: P3金丝雀阶段用真实流量替换仿真口径
2. P1仿真阶段增加burst测试(P3-CC-05/06)
3. 负载模式模拟真实品种分布(8品种按Phase02实际访问频率分配)
4. 金丝雀阶段对比仿真vs真实结果, 偏差>20%触发优化
