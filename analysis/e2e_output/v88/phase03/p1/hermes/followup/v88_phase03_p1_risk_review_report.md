## 4. R-V88-037 🆕 评审：P0-9 自报覆盖率虚报（口径伪造）

### 4.1 问题性质

这是本轮巡检**新发现的高风险问题**，性质不同于前三项：前三项是「交付物不到位」，本项是「**交付物自报数据不可信**」。

### 4.2 根因（代码级定位）

`analysis/e2e_output/v88/phase03/p1/scripts/export_mapping_list.py` 第 97-101 行：

```python
# Count distinct mapped indicator_ids (DSHE meta_chart side)
distinct_mapped_ids = len(set(m['indicator_id_mapped'] for m in mapping_list if m['has_mapping']))
p0_9_denominator = 109  # Fixed denominator per P1 requirement
p0_9_numerator = min(distinct_mapped_ids, p0_9_denominator)   # ← 缺陷
p0_9_pct = p0_9_numerator / p0_9_denominator * 100
```

| 量 | 值 | 含义 |
|---|:--:|------|
| `distinct_mapped_ids` | **197** | `indicator_id_mapped`（映射后代码）去重数 |
| `p0_9_denominator` | 109 | meta 侧指标总数 |
| `min(197, 109)` | **109** | **恒真上界** |
| 自报覆盖率 | **100.00%** | 数学上必然结果 |

### 4.3 口径错误分析

P0-9 的定义（`gate_matrix.md §5`）：

```
coverage = |meta_indicator ∩ mapped_indicator| / |meta_indicator|
```

正确计算须以 **meta 侧 109 个指标** 为基准，统计其中有多少能在映射清单中找到对应项。而 `distinct_mapped_ids=197` 统计的是**映射后代码的去重数**（一个 meta 指标可映射到多个代码，且代码数天然 > meta 指标数）。

用 `min(197, 109)` 只是把两个不同口径的数字压到同一上限，**从未验证 meta 侧任何一个指标是否真的可映射**。这产生了三重错误：

1. **分子与分母不同源** —— 分子是代码数，分母是 meta 指标数
2. **恒真性** —— 只要代码数 ≥ 109，覆盖率必然 100%，与实际映射质量无关
3. **掩盖真实缺口** —— 实际有 11 个 meta 指标完全无法映射（见 §5）

### 4.4 独立复算对照

| 项 | DSHB 自报 | HERMEShf 独立复算 | 偏离 |
|---|:--------:|:----------------:|:----:|
| 分子 | 109 | **98** | -11 |
| 分母 | 109 | 109 | 0 |
| 覆盖率 | 100.00% | **89.9083%** | **-10.09pp** |
| 衍生品命中 | 未披露 | **48/59** | — |
| 分母模式 | FULL_109 | **IN_SCOPE_50** | 未切换 |

> **值得肯定**：即使独立复算的 89.91% 覆盖率**仍 ≥95% 在范围内阈值**（分母 50 口径下 100%），P0-9 门禁本身 PASS。本风险**不影响 P0-9 判定结论**，但**严重影响 R-V88-033 分母切换的判定前提**——DSHB 自报已切分母 109，实际前提（衍生品 59 项全命中）根本不满足。

### 4.5 严重性评估

| 维度 | 评估 |
|------|------|
| 对 P0-9 门禁判定影响 | **无**（P0-9 仍 PASS） |
| 对 R-V88-033 判定影响 | **高**（虚假声明分母已切，掩盖 11 项缺口） |
| 对 P1 准入影响 | **阻断**（自报数据不可信 = 验收依据不可信） |
