**回归 1（阻断级）：`__tgl` 引号嵌套 → JS 语法错误**

90 个 div-id 重命名时，把 `window.__tgl('echart_21_c2',this)` 的**单引号误改为双引号**：

```html
<!-- 1def0f2（正确） -->
<button onclick="window.__tgl('echart_21_c2',this)">⏱ 时序</button>

<!-- 267614d（破坏） -->
<button onclick="window.__tgl("echart_pb_21_c2",this)">⏱ 时序</button>
                                              ↑ 属性值提前终止
```

实测：**40 处**双引号嵌套，涉及 **26 个 PB 页面**。HTML 属性值在 `onclick="window.__tgl("` 处提前终止，后续 `echart_pb_21_c2",this)` 成为非法裸 token → 按钮点击直接抛异常。

**回归 2（阻断级）：`getElementById` 未同步更新 → ECharts 全页挂不上**

90 个 `<div id>` 改了名，但 JS 层引用仍是旧名：

```js
// 267614d：div id = echart_pb_21_c1，但 init 仍指向旧 id
echarts.init(document.getElementById('echart_21_c1'))   // ← null，图表不渲染
```

实测：**90 处** `getElementById('echart_<旧命名>')` 全部未更新。`echarts.init` 对全部 PB 页面命中数为 **0**（全库扫描确认）。这是**更严重的功能破坏**——不是按钮坏了，是**整页图表都不渲染**。

> 注：`STATUS.md` 声称「同步更新 `__data_`/`__opts_`/`__inst_`/`__mode_`/`__tgl`/`echarts.init` 引用」，**实测不成立**（`__tgl` 只改了引号、未改引号类型；`echarts.init` 完全未更新）。

**⚠️ 死代码缺陷**：`EXCHANGE_WHITELIST`（第 39 行）**定义后从未被引用**：

```python
EXCHANGE_WHITELIST = {   # 第39行，定义
    "CU": ["SHFE", "上期所", "COMEX", "LME"],
    "SI": ["GFEX"],
    "PB": ["SHFE", "上期所"],
    ...
}
CROSS_EXCHANGES = {      # 第53行
    "PB": ["COMEX", "GFEX"],
    "LI": ["COMEX", "SHFE", "上期所"],
    ...
}
```

`grep -n EXCHANGE_WHITELIST` 全库仅 1 处命中（第 39 行定义处），`classify_indicator()` 只用 `CROSS_EXCHANGES`。两个结构**语义互斥**（白名单 vs 黑名单），且逻辑上不一致：
- `EXCHANGE_WHITELIST` 中 `LI: ["GFEX"]`（暗示 LI 不应有 SHFE 数据）
- `CROSS_EXCHANGES` 中 `LI: ["COMEX", "SHFE", "上期所"]`（明确拦截 LI 的 SHFE 引用）

**后果**：CU 的 COMEX 引用能正确放行（CU 不在 `CROSS_EXCHANGES` 键中），功能碰巧正确；但白名单是死代码，**未来维护者可能误以为白名单在生效**而做出错误判断。建议二次修复时二选一：①删除 `EXCHANGE_WHITELIST` ②改造成真正的白名单校验（`code 在 EXCHANGE_WHITELIST 且 exchange 不在白名单 → 幻觉`）。
